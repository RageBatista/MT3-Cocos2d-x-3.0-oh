# 资源真实名称与路径恢复质量标准

## 1. 证据等级

### A 级：可直接并入主资源树

至少满足一条：

- 路径 CRC 精确命中
- 唯一同内容命中且目标路径可信
- 文件内容强信号与目标扩展、目标目录完全一致
- 客户端代码、`auto`、表结构三方共同指向同一落点

### B 级：可提升为候选，但不直接并入

典型情形：

- `sound.inf`
- `ridemodel` 上下文映射
- 半闭环 ANI
- 结构正确但路径多候选的地图配置

### C 级：仅保留在 review

典型情形：

- 只有内容碎片
- 只有猜测，没有代码或结构支持
- 会覆盖现有主树内容的冲突项

## 2. 分类标准

### accepted

- 已经能稳定并入 `unpacked_res`
- 必要时同步到 `dev_res`
- 有明确报告或 manifest 记录

### candidate

- 内容和结构足够强
- 但原始路径仍有一处以上不确定

### alias

- 内容已知，但原始路径不唯一
- 包括：
  - `resolved_exact_content_alias`
  - `resolved_ambiguous_content_alias`

### unresolved

- 当前证据不足以升级为前三类

## 3. 主树回流标准

写入 `unpacked_res` 前至少检查：

1. 目标路径是否已经存在
2. 若存在，内容是否完全一致
3. 若存在但不同，是否必须保留为 `exists_conflict`
4. 是否需要同时写入 `dev_res`
5. 是否已经记录到正式报告

## 4. 报告标准

每轮恢复至少新增或更新一项：

- 数量统计
- 证据说明
- 输入目录与输出目录
- 成功项 / 候选项 / 跳过项 / 冲突项
- 下一轮剩余重点

## 5. 脚本标准

若使用脚本完成恢复或分类：

- 输出必须可复跑
- 输出目录必须固定、可追溯
- 至少产出 CSV 或 JSON 供后续机器消费
- 不允许“只在终端打印，不落盘”

## 6. 不可接受做法

- 没有证据直接批量改名
- 用覆盖主树的方式压 `unresolved`
- 把多命中内容当成唯一恢复
- 把语义候选伪装成正式恢复结果
- 只改 `dev_res` 不改正式报告或工作树说明

## 7. 交付标准

一个合格的恢复轮次应满足：

- `formal_results_*` 有完整记录
- `unpacked_res` 反映当前最优工作树
- `dev_res` 保持开发可用
- `review/` 中的候选、别名、未解决分层清楚
- 最终答复能说明：
  - 做了什么
  - 为什么这样做
  - 哪些还没解决
