# MT3 双引擎升级收敛总结报告

> 日期：2026-08-05  
> 任务基线：Win32 `cocos2d-x-3.0-oh + CEGUI-0.7.9-r5`；Android/iOS `cocos2d-x-2.2.6`  
> 固定工具链：VS2013/v120/Windows SDK 8.1；NDK r16 clang/Ant/JDK8；服务端 JDK7/8/Ant

## 1. 结论

本轮没有重复修改已经完成的 Cocos/CEGUI 业务 API 适配源码，而是把升级后的工程事实收敛到构建清单、门禁脚本、技能、Codex sidecar 和现行文档中。

主要结果：

1. Win32 `Upgrade30` 的 27 个依赖工程和最终 `MT3` 工程由 `tools/scripts/build-config.psm1` 统一提供，构建、v120 门禁、分析器和技能预检不再各自复制旧清单。
2. `Legacy226` 仍保留 13 工程兼容清单，不与 Win32 canonical 的 3.0-oh/0.7.9-r5 产物混用。
3. Release `Upgrade30` SafeChain 完成 31 个计时步骤，严格 runtime audit、D3D9 三层检查和 25 秒启动烟测通过。
4. Android arm64/JDK8 静态门禁与 iOS 47 项静态工程门禁通过，确认两端仍使用 2.2.6 兼容链。
5. Codex sidecar、skills 和 guardrails 审计通过；workflow health 平均分 92，runtime dependency 提示为 0。

## 6. 遗留问题与风险

1. 完整 SafeChain 日志仍包含 C4996 旧 Cocos API、C4819 代码页/编码和 C4005 宏重复等兼容告警；最终增量恢复日志的 BuildConfig 汇总为 0 warnings。兼容告警未阻断本轮构建，但 C4819 应按原文件编码逐个取证处理，禁止批量转码。
2. `Build-MT3-FullValidation.ps1 -Configuration Release` 会默认再执行 SafeChain；本轮外层命令的 600 秒宿主上限低于实际 14 分钟构建耗时，因此未生成最终 FullValidation JSON。直接 canonical SafeChain 和中断后的 canonical 恢复均已完成。
3. Android 本轮只执行静态门禁，未重打 APK、安装或实机验证；iOS 只执行 Windows 可完成的静态门禁，未在 macOS/Xcode 编译。
4. 当前工作区 D3D9 脚本仍受 `/tools/` 忽略规则影响。若要纳入 CI，应先专项治理 `/tools/` 白名单，避免同时暴露大量 runtime-local CEGUI 文件。
5. Debug 全链未在本轮重建；发布前里程碑仍建议在足够长的执行窗口中运行 `Build-MT3-FullValidation.ps1 -Configuration Both`。
6. 文档全量审计仍报告 5 个既存断链，分布在 1 份历史记录和 4 份既有计划；Claude legacy 层另报告 2 个指向已不存在 `.roo` 规则的旧链接。
7. `.gitignore` 按既有“正式 Release 运行归档”策略放行 `client/resource/bin/Release/MT3.exe`，且历史提交中存在该产物；本轮生成的文件当前未跟踪，执行 `git add -A` 会把它纳入暂存。源码提交必须显式排除该文件，是否恢复二进制归档应作为独立发布决策处理。

## 7. 后续行动

1. 建立独立告警治理任务，优先处理 C4819 文件编码，再处理可安全替换的 C4996 API 和 C4005 宏保护。
2. 在 Android 交付机运行 free 渠道 canonical APK 构建、ABI 内容检查、安装和启动验证。
3. 在 macOS/Xcode 执行器运行 iOS Release 编译、链接和签名/无签名验证。
4. 为 FullValidation 配置不少于 20 分钟的外层超时，并在发布里程碑执行 Debug+Release 双配置验证。
5. 若 D3D9 门禁需要进入 CI，先设计精确的 `tools/` 跟踪边界，再把脚本及调用入口一并落库。
