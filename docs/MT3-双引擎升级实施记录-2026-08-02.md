# MT3 双引擎升级实施记录

> **日期**：2026-08-02
> **状态**：Win32 canonical `Upgrade30` 已完成构建闭环；Android/iOS 仍保持各自平台基线。

## 1. 升级范围

本次收敛的交付链为：

```text
Win32 平台
  cocos2d-x-3.0-oh -> CEGUI-0.7.9-r5 -> engine -> FireClient -> MT3.exe
```

- `engine/engine.win32.vcxproj` 使用 `cocos2d-x-3.0-oh` 头文件与静态库。
- `client/MT3Win32App/FireClient.win32.vcxproj` 与 `mt3.win32.vcxproj` 使用 `tools/CEGUI-0.7.9-r5`。
- CEGUI Cocos2D renderer 接入 Cocos 3.0-oh 的 kazmath 矩阵模式与 GL 状态缓存。
- Android/iOS 的物理 Cocos 依赖仍是 `cocos2d-x-2.2.6`，不在本次 Win32 交付范围内。

## 2. 代码与配置变更

- Cocos 3.0-oh 的 Win32 生成工程统一补齐 `GLEW_STATIC`，保证静态 GLEW 链接宏一致。
- kazmath 增加当前矩阵模式查询，并在矩阵栈空弹出时记录诊断信息、跳过非法弹出。
- Cocos GL 状态缓存增加保留矩阵栈的失效入口，避免 CEGUI 结束渲染时释放外层 Cocos 矩阵栈。
- CEGUI Cocos2D renderer 保存并恢复进入渲染前的矩阵模式；renderer 头文件显式包含 kazmath matrix 类型定义。
- CEGUI Lua 绑定与 `.pkg` 同步 `MessageTips` 类型转换。

## 3. 依赖与影响面

| 层级 | 入口 | 影响 |
| --- | --- | --- |
| 基础库 | `cocos2d-x-3.0-oh/build/**` | 重新生成 v120 静态库；GLEW 宏和 GL 状态缓存影响所有 Win32 Cocos 模块 |
| UI | `tools/CEGUI-0.7.9-r5/` | CEGUI、Cocos2D renderer、Lua binding 和纹理上传路径重编 |
| 引擎 | `engine/` | 依赖 Cocos 3.0-oh API 与静态库，需先于 FireClient 重编 |
| 业务 | `client/FireClient/` | 依赖 engine 与 CEGUI 头/库，需在 MT3 链接前重编 |
| 壳层 | `client/MT3Win32App/` | 最终链接和运行目录同步，产出 `MT3.exe` |

## 4. 验证结果

执行命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\scripts\Validate-BuildConfig.ps1 -EngineProfile Upgrade30 -Configuration Release
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\scripts\Build-MT3-Exe-Canonical.ps1 -Configuration Release -Platform Win32 -EngineProfile Upgrade30 -BuildMode Incremental -MaxParallelJobs 4
```

结果：

- v120 工具链门禁通过，13 个主线工程均为 `PlatformToolset=v120`。
- `Validate-BuildConfig`：20 项检查，0 errors，当前构建日志报告 9 个非阻断 warning。
- canonical Release 构建：Cocos 3.0-oh、CEGUI 0.7.9-r5、engine、FireClient、MT3 全部完成。
- 产物：`client/resource/bin/Release/MT3.exe`，11,613,184 bytes。
- 28 个 Release MSBuild 日志中未发现 `error Cxxxx`、`fatal error Cxxxx` 或 `error LNKxxxx`；现有 warning 主要为静态库链接器 `LNK4221`，不阻断产物生成。
- runtime audit：`DriftHighCount=0`、`MissingDepHighCount=0`、`RuntimeImportHighCount=0`、`FamilyHighCount=0`。
- CEGUI renderer/纹理路径仍保留压缩纹理与 `saveToMemory` 等后续专项 TODO；这些不影响 Win32 当前静态链接闭环，但不应标记为全平台功能验收完成。

### FullValidation 烟测补充

执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\scripts\Build-MT3-FullValidation.ps1 -Configuration Release -EngineProfile Upgrade30 -RunSmoke -SmokeSeconds 30 -MaxParallelJobs 4
```

- 完整 Release 链再次通过，报告位于 `build_logs/mt3-full-validation-report.json`。
- smoke 进程保持运行 30 秒；自动关闭阶段返回 `Access is denied`，记录为 `cleanup_failed`，因此仍需在交互桌面手工确认关窗退出。该状态不等同于启动崩溃。
- `runtime-audit-release-full-validation.json` 因扫描根未枚举到 exe（`ExeCount=0`）而计数为 0；实际构建后的运行目录审计仍以 `build_logs/runtime-audit-after-client-build.json` 为准，四项 High 计数均为 0。
- 使用显式可执行文件参数复核：`Audit-RuntimeDependencies.ps1 -ScanRoots client/resource/bin/Release -ExecutableNames MT3.exe`，结果 `ExeCount=1`、`MissingDepHighCount=0`、`RuntimeImportHighCount=0`、`DriftHighCount=0`，报告为 `build_logs/runtime-audit-release-explicit.json`。
