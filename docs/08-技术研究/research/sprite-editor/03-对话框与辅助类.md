# SpriteEditor 对话框与辅助类

> **证据边界**：当前工作树不包含旧报告中列出的完整对话框/Command/辅助类源码。
> **当前可直接核对**：`SpriteEditorOperationUi.*`、`SpriteEditorViewInteractionUtils.*`、`SpriteEditorViewRenderUtils.*`、`SpritePackCoreService.*`。
> **文档索引**：[docs/07-参考文档/02-文档索引.md](../../../07-参考文档/02-文档索引.md)

## 1. 当前 helper/service

| 文件 | 边界 |
| --- | --- |
| `SpriteEditorOperationUi.*` | 将业务操作结果与 UI 呈现/提示责任抽离。 |
| `SpriteEditorViewInteractionUtils.*` | 将视图交互、命中和坐标辅助抽离。 |
| `SpriteEditorViewRenderUtils.*` | 将视图渲染辅助抽离。 |
| `SpritePackCoreService.*` | 将打包算法与图集/ANI 写出从 UI/Doc 调度抽离。 |

这些抽取表明当前治理方向是在保持旧工具交互的前提下逐步分离职责，而不是一次性推翻重写。

## 2. 对话框的阶段性分类

工具内文档/历史研究将对话框大致分为：

- 动作/动画管理。
- 装备层和资源选择。
- 打包配置与结果。
- 重命名、属性和兼容格式。
- 帮助、错误与其他工具性面板。

具体类名、DDX、资源 ID 和消息映射必须在完整源码回流后重新核对，不从旧报告直接复制为当前 API。

## 3. 对话框设计规则

1. Dialog 只采集/校验用户输入，复杂打包/资源逻辑交给 service。
2. 应用前验证路径、名称、数值范围、冲突和覆盖风险。
3. 可撤销数据变更通过现有 command/history 边界，不在 Dialog 里直接多点写模型。
4. 长任务显示进度、取消和部分失败清单，不阻塞 UI 线程。
5. Dialog 关闭后不留下指向 View/Doc/任务的悬空回调。

## 4. 与 `SpritePackCoreService` 的分工

```text
Pack dialog / caller
  -> validate real pack.ini and paths
  -> construct pack inputs/options
  -> SpritePackCoreService::BuildAtlas
  -> result/log summary
  -> UI presentation and next action
```

UI 层不复制 `RectPacking`、`GetBigPicSize`、`PicArrange`、`WriteConvertedAni` 算法。

## 5. 历史辅助类的使用口径

Command/Undo、EquipmentLayer、PNG 导出、旧 ANI 兼容、Chunk 信息、CrashDump 等只能作为工具内文档/历史研究的模块线索。当前任务需修改它们时，先确认完整源码是否已回流。

## 6. 验证

- Dialog 取消不修改 Document。
- 无效输入在调用 service 前被拦截。
- 成功操作产生一致的 UI、Document、预览和 dirty 状态。
- 撤销/重做可恢复数据和预览。
- 长任务可取消，不留部分产物或悬空回调。
