# SpriteEditor 完整工作流

> **口径**：打包核心来自当前 `SpritePackCoreService`；菜单、Doc/View、对话框和装备层全流程来自工具内文档/历史研究。
> **配置**：仓库没有默认 `pack.ini`，必须使用调用方提供的真实路径。
> **文档索引**：[docs/07-参考文档/02-文档索引.md](../../../07-参考文档/02-文档索引.md)

## 1. 工作流总览

```text
准备模型/动画/图片资源
  -> 在 SpriteEditor 打开或创建文档
  -> 编辑动作、方向、帧、偏移和装备层
  -> 预览播放与单帧检查
  -> 保存可继续编辑文档
  -> 使用调用方 pack.ini 执行打包
  -> BuildAtlas 生成图集和 picture -> texture/rect 映射
  -> 上层按需显式调用独立动画转换/写出流程
  -> 工具预览与客户端运行验收
```

## 2. 打包前预检

```powershell
powershell -ExecutionPolicy Bypass -File .\.agents\skills\sprite-pack-algorithm\scripts\verify-pack-output.ps1 -ConfigPath <调用方真实pack.ini路径>
```

预检记录：

- 配置文件路径和 SHA256。
- 源 ANI/模型/图片资源根。
- 输出目录和覆盖策略。
- 最大纹理尺寸、图像格式、纹理格式和命名规则。
- 可回滚的旧产物。

## 3. 当前打包核心

### 3.1 `BuildAtlas()`

输入是图片矩形、ANI 路径、输出格式和结果容器等参数；它只按顺序调度 `RectPacking()`、`GetBigPicSize()` 和 `PicArrange()`，成功后直接返回图集数量。

### 3.2 `RectPacking()`

- 拒绝超过最大纹理尺寸的单图。
- 用 MaxRects 风格策略将矩形分配到多个 bin。
- 输出每个图片的 bin 和矩形位置。

### 3.3 `GetBigPicSize()`

- 计算每个 bin 的最终纹理宽高。
- 记录 used area 和利用率，作为优化与回归证据。

### 3.4 `PicArrange()`

- 创建 render target。
- 将源图片绘制到目标位置。
- 保存目标纹理并建立 picture -> texture/rect 映射。
- 失败时记录 render target/保存错误并清理状态。

### 3.5 `WriteConvertedAni()`

这是独立方法：接收 `picPosInfos`、ANI 路径和 `COldAniPack`，将新图集位置写入转换后动画数据，保持帧、方向、偏移和图片引用语义。当前抽取源码未发现其调用者，也没有证据表明 `BuildAtlas()` 会自动触发该方法；完整工具链需要由上层显式编排。

## 4. 产物验证

| 产物 | 检查 |
| --- | --- |
| 图集 | 尺寸、数量、透明、边界渗色、重叠/越界、空间利用率。 |
| ANI/XAP | 仅在上层另行生成时检查：文件存在、可重新打开、纹理索引/矩形与图集一致。 |
| 日志 | 输入数、bin 数、利用率、保存路径、失败原因。 |
| 预览 | 所有动作/方向/帧/装备层，不只看第一帧。 |
| 客户端 | 同一产物在实际运行时加载、渲染、切动作与纹理恢复。 |

## 5. 回滚

- 保留原始动画/模型和旧图集。
- 新产物输出到独立目录，验收后再回流。
- 记录配置、输入/输出哈希和工具源码提交。
