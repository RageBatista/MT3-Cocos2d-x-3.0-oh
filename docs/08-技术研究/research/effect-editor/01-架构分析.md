## 1. 证据边界

本页对 EffectEditor 的整体结构描述来自工具内文档，不声称当前已对全量 `.cpp/.h/.vcxproj` 重新回读。旧文档中的文件数、行数、函数行号和“已完成”比例只作为历史分析信息。

## 2. 阶段性架构模型

```text
MFC application/frame
  -> Document / View
  -> effect editing tools and property panels
  -> timeline / keyframe editing
  -> engine preview and resource managers
  -> file load/save/export
  -> undo/redo and dialogs
```

工具内 [01-架构设计](../../../../tools/engine/EffectEditor/docs/01-架构设计.md) 将其定位为 VS2013/v120 下的 MFC Doc/View 工具，具有特效编辑/预览的双模式边界。

## 3. 主要职责

| 区域 | 阶段性职责 |
| --- | --- |
| Application/Frame | MFC 启动、菜单/工具栏、面板和工具生命周期。 |
| Document | 特效数据、文件状态、加载/保存和 dirty 标记。 |
| View/Preview | Nuclear/图形预览、摄像机、选择和交互。 |
| Timeline/Keyframe | 时间、关键帧、插值、播放与帧定位。 |
| Property/Dialog | 参数编辑、颜色/曲线/文件选择和验证。 |
| Undo/Redo | 将可编辑操作封装为可撤销变更。 |

## 4. 数据流

```text
open effect/resource
  -> Document model
  -> property panels + timeline
  -> preview renderer
  -> edit command
  -> model mutation + dirty state
  -> save/export
```

工具内 [04-数据流向与关键算法](../../../../tools/engine/EffectEditor/docs/04-数据流向与关键算法.md) 是当前最详细的阶段性说明。

## 5. 高风险边界

- 文件格式和引擎特效数据版本。
- 关键帧插值、时间单位和预览/运行时一致性。
- 资源引用路径、PFS/松散资源和缺失资源处理。
- 撤销命令中的指针/所有权。
- 工具预览和客户端实际效果的渲染状态差异。

## 6. 维护方法

1. 若完整源码回流，先读取就近 `AGENTS.md`、工程文件和编码。
2. 从一个真实特效样本建立“打开 -> 编辑 -> 撤销/重做 -> 保存 -> 重打开 -> 客户端预览”回归。
3. 对文件格式变更保留旧样本和回滚产物。
4. 构建结果以当次工程、日志和产物为准，不复用历史文档中的“已验证”结论。
