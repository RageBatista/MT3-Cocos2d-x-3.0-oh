# 2D 地图制作流程

> **定位**：说明地图可编辑文件、运行时地图、阻挡/NPC/跳转等伴随数据的真实来源、回流边界和验收点。
> **当前运行技术栈**：Cocos2d-x 2.2.6 + Nuclear + FireClient。
> **工作树边界**：`tools/engine/MapEditor/` 与 `tools/engine/npceditor/` 当前保留文档、OBJ/PDB 等阶段性产物，完整源码、工程和可直接执行的编辑器未在当前工作树出现。
> **文档索引**：[docs/07-参考文档/02-文档索引.md](../07-参考文档/02-文档索引.md)

## 2. `5001_dayanta1` 当前样本盘点

当前目录共有 11 个文件。`MapEditor1.mrmp` 与 `map.rmp` 的地图尺寸均为 `2048 x 1280`；阻挡和区域类文件记录的逻辑网格均为 `86 x 80`，对应客户端按 `24 x 16` 像素格计算的覆盖范围。

| 文件 | 当前样本事实 | 来源/编辑阶段 | 回流与消费方 | 最低验收点 |
| --- | --- | --- | --- | --- |
| `MapEditor1.mrmp` | 5360 字节；`MRMP`、工具版本 1，内嵌 `RMAP` | MapEditor 可继续编辑文件；普通保存保留工具图层扩展 | 作为编辑真源和回滚点保存在地图源目录；客户端运行时不以它代替 `map.rmp` | 打开、无修改保存、重新打开；地图尺寸、图层、对象、背景、触发器保持一致 |
| `map.rmp` | 4695 字节；`RMAP`、地图版本 45、`2048 x 1280` | MapEditor 通过资源预检后导出的纯 `PMap` | `client/resource/res/map/<resdir>/map.rmp`；Nuclear 固定读取 `/map/<resdir>/map.rmp` | 客户端首次进入/重进成功；地表、对象、特效、摄像机边界正确；无缺失资源日志 |
| `maze.dat` | 6892 字节；头部记录 `86 x 80`，后接阻挡数据 | Maze/NPC 编辑阶段的 `WriteMazeBuffer()` | 客户端同目录；服务端还按地图 ID 读取 `gamedata/map/<mapID>/maze.dat` | 编辑器回读尺寸一致；玩家/NPC 不穿墙、不被错误阻挡；服务端阻挡判定与客户端一致 |
| `goto.dat` | UTF-16 LE XML，根节点 `<data>`，记录跳转区域和目标地图坐标 | 跳转点编辑的 `SaveJumpPointInf()` | 客户端同目录，`GameScene::LoadJumpMapPointInf()` 读取 | XML 可解析；入口覆盖区域正确；目标地图和落点有效；重复进入不会叠加异常效果 |
| `npc.dat` | UTF-16 LE XML，根节点 `<data>`，记录 NPC ID、位置和方向 | NPC 编辑的 `OnSaveNpcInf()`；工具文档称 XML，现行样本使用 `.dat` 扩展名 | 客户端同目录；服务端按 `gamedata/map/<mapID>/npc.dat` 读取 | 客户端 NPC 显示、坐标、朝向正确；服务端同一 NPC 配置可解析，交互位置一致 |
| `regiontypeinfo.dat` | `QUYU`，`86 x 80`，序列化区域数据 | `WriteRegionBufferToFile()` | 客户端同目录；服务端也按地图 ID 读取 | PK/摆摊等区域边界正确；客户端、服务端对关键格子的区域类型一致 |
| `JumpBlock.dat` | `QUYU`，`86 x 80`；当前样本数据区为空 | `SaveJumpBlockInf()` | 客户端同目录；服务端也按地图 ID 读取 | 文件可回读且尺寸匹配；需要跳跃限制的地图必须验证关键格子，不能仅以文件存在判定完成 |
| `Island.dat` | `QUYU`，`86 x 80`，一层孤岛结果 | `SaveIslandInf(layer=1)`，由阻挡数据执行孤岛检测 | 客户端同目录，`GameScene` 加载一层孤岛缓冲 | 关键可达区不被标为孤岛；自动寻路、传送和重载后结果一致 |
| `Island2.dat` | `QUYU`，`86 x 80`；当前样本数据区为空 | `SaveIslandInf(layer=2)` | 客户端同目录，`GameScene` 加载二层孤岛缓冲 | 文件可回读且尺寸匹配；若地图使用二层阻挡，必须补充对应连通性验收 |
| `monster.dat` | 二进制，头部记录 `86 x 80` | `SaveMonsterKind()` 怪物分布编辑 | 服务端按 `gamedata/map/<mapID>/monster.dat` 读取；当前客户端主链未发现直接读取点 | 服务端启动/重载时无解析错误；怪物类型、区域和刷新行为符合配置 |
| `Untitled.mps` | UTF-16 LE 空 XML：`<data/>` | 当前工作树未找到可靠生成入口 | 不作为运行时声音文件验收；Nuclear 固定查找的是 `/map/<resdir>/sound.mps` | 不因它存在就宣告地图声音完成；需要声音时必须生成并验证实际的 `sound.mps` |

当前 `server/game/server1|server2/game_server/gamedata/map/5001/` 也保存同名地图文件，但 `Island.dat`、`regiontypeinfo.dat`、`monster.dat` 与客户端样本的字节数不同。回流时应按消费方和地图 ID 生成/核对，不能把客户端目录整体覆盖到服务端目录。

## 3. 产物链总览

```text
美术源图/分层资产
  -> MapEditor 编辑地表、对象、背景、水面、触发器和场景参数
  -> 保存 MapEditor1.mrmp（可编辑真源）
  -> ValidateExportResources / CleanMap 副本预检
  -> 导出 map.rmp（客户端运行时 PMap）

map.rmp + 地图尺寸
  -> Maze/NPC 编辑阶段
  -> maze / region / JumpBlock / Island / Island2 / monster
  -> npc.dat / goto.dat

客户端消费文件
  -> client/resource/res/map/<resdir>/
  -> LJFilePack/PFS/版本索引
  -> 三端客户端加载

服务端消费文件
  -> game_server/gamedata/map/<mapID>/
  -> 服务端阻挡、区域、NPC、怪物配置加载
```

## 4. 源素材准备

1. 从同类型现有地图复制目录骨架，先确认地图 ID、客户端 `resdir` 和服务端地图 ID 的映射。
2. 保留未裁切源图、分层文件、中间切片和资源对应表，不用运行时文件反推唯一美术真源。
3. 固定色彩空间、位深、alpha、瓦片网格、边界补齐和命名规则。
4. 透明图做 alpha bleed，避免线性采样出现黑/白边。

旧文档中的 `Build-MapTile-AlphaBleed.ps1` 未在当前仓库找到。当前没有可引用的仓库内脚本；实际处理必须记录所用工具、版本、参数和输出哈希。

## 5. MapEditor 编辑、保存与导出

1. 在可回滚副本中打开 `MapEditor1.mrmp`，先确认其 `MRMP` 文件头、工具版本和地图尺寸。
2. 编辑地表图层、场景对象、背景、水面/特效、透明对象、触发器、区域和场景参数。
3. 每个阶段先普通保存工具格式；该动作保留编辑器图层扩展，并可能同步被修改的 PImg/PLinkedObject 资源。
4. 保存后关闭并重新打开，核对图层顺序、对象位置、画布尺寸和资源引用。
5. 导出时先在副本上执行资源预检；缺失或非法资源应写入 `experr.log` 并阻止导出。
6. 预检通过后才生成 `map.rmp`；它只包含运行时 `PMap`，不包含 `MRMP` 文件头和工具扩展图层。
7. 导出到独立临时目录，对比上一版文件大小、哈希、地图尺寸和实际加载结果，通过后再回流。

## 6. 阻挡、区域、NPC 与跳转数据

Maze/NPC 编辑阶段必须加载同一版 `map.rmp`，并保持地图尺寸不变。阶段性工具文档记录的保存链为：

```text
OnSavemaze
  -> WriteMazeBuffer(maze.dat)
  -> WriteRegionBufferToFile(regiontypeinfo.dat)
  -> SaveJumpBlockInf(JumpBlock.dat)
  -> SaveIslandInf(Island.dat, layer=1)
  -> SaveIslandInf(Island2.dat, layer=2)
  -> SaveMonsterKind(monster.dat)

NPC 保存
  -> OnSaveNpcInf()
  -> npc.dat（XML 内容）

跳转点保存
  -> SaveJumpPointInf()
  -> goto.dat（XML 内容）
```

保存后至少执行一次工具侧回读：阻挡/区域文件尺寸必须与当前地图一致，XML 文件必须完整解析，孤岛检测不能把合法出生点、NPC 点、传送点或主要路径标成不可达。

## 7. 回流边界

### 7.1 客户端

- 回流 `map.rmp` 以及客户端实际读取的 `maze.dat`、`goto.dat`、`npc.dat`、`regiontypeinfo.dat`、`JumpBlock.dat`、`Island.dat`、`Island2.dat`。
- `MapEditor1.mrmp` 作为可编辑真源和回滚点保留，但运行时验收只针对 `map.rmp`。
- 不直接修改 `client/android/LocojoyProject/assets/res/**`；先更新 `client/resource/res/**`，再走现有 LJFilePack/PFS/版本索引链。

### 7.2 服务端

- 只同步服务端代码实际读取的 `maze.dat`、`JumpBlock.dat`、`regiontypeinfo.dat`、`npc.dat`、`monster.dat`。
- 目标目录按服务部署树和数值地图 ID 确认，例如 `game_server/gamedata/map/<mapID>/`；不要用客户端 `resdir` 名称替代地图 ID。
- 同步前比较地图尺寸、关键格子、NPC 坐标和怪物区域；同名文件不同字节时先确认消费语义，不做整目录覆盖。

### 7.3 声音文件

- 引擎读取 `sound.mps`，不是当前样本的 `Untitled.mps`。
- 需要地图声音时，应从实际声音编辑流程生成 `sound.mps`，验证环境音区域、背景音乐切换和缺失文件日志。

## 8. 联合验收

| 层次 | 检查 |
| --- | --- |
| 工具真源 | `MapEditor1.mrmp` 可打开、保存、重开；变更差异只包含预期图层/对象/资源。 |
| 运行时地图 | `map.rmp` 文件头、版本、尺寸正确；客户端加载、滚动、切图和资源重载正常。 |
| 阻挡/孤岛 | 出生点、NPC、传送点、主路径、边界、二层阻挡；客户端移动与服务端判定一致。 |
| 区域/跳跃 | PK/摆摊/特殊区域、JumpBlock、goto 入口和目标落点。 |
| NPC/怪物 | 客户端显示与交互、服务端 XML/二进制解析、怪物区域和刷新行为。 |
| 视觉 | 地表拼缝、对象层级、透明边缘、水面/特效和摄像机边界。 |
| 性能/稳定性 | 首次加载、峰值内存、帧时、前后台、重连、重复切图和长时间驻留。 |
| 发布 | 客户端资源包、版本索引和服务端部署目录来自同一批次，均保留哈希与回滚副本。 |

## 9. 常见问题

| 现象 | 优先排查 |
| --- | --- |
| 工具可见、客户端缺图 | 是否只保存了 `.mrmp` 而未重新导出 `map.rmp`；资源预检、PFS/索引和路径大小写。 |
| 客户端可走、服务端判阻挡 | client/server 的 `maze.dat`、`JumpBlock.dat`、地图 ID 或版本批次不一致。 |
| NPC 显示但无法交互 | `npc.dat` 客户端与服务端副本、坐标语义、NPC ID 和场景配置不一致。 |
| 跳转点不生效 | `goto.dat` XML、入口覆盖格、目标地图 ID/落点和客户端加载开关。 |
| 区域规则异常 | `regiontypeinfo.dat` 的网格尺寸、客户端/服务端副本和关键格子值。 |
| 有 `Untitled.mps` 仍无声音 | 引擎读取的是 `sound.mps`；检查实际声音产物和资源索引。 |
| 新版难以回滚 | 是否同时保留 `.mrmp`、`map.rmp`、全部伴随文件、客户端索引、服务端部署副本和批次哈希。 |
