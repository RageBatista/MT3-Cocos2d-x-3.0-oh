# 客户端界面清晰度与高分屏适配

> **状态**：当前问题模型 + 分阶段研究方案。
> **当前实现**：Cocos2d-x 2.2.6、Nuclear、CEGUI 0.7.1、`ResolutionAdapter`/`RuntimeViewportCalculator`。
> **文档索引**：[docs/07-参考文档/02-文档索引.md](../07-参考文档/02-文档索引.md)

## 1. 当前事实

- Android/iOS 的 scene/UI 基线当前为 1080x720，Android `maxUiScale=2.0`。
- Win32 UI 默认基线为 1280x720，可通过 `frameResolutionSize.txt` 覆盖，`maxUiScale=1.3`。
- CEGUI 使用 Cocos2D Renderer，UI 纹理、Font glyph、GeometryBuffer 和 GL 状态共同决定最终画质。
- Win32 可导出 runtime profile 与编辑器 WYSIWYG 对照。
- 当前仓库不存在已覆盖三端的统一“倍率资源系统”完成证据。

## 2. 问题分类

| 类别 | 典型现象 | 首要证据 |
| --- | --- | --- |
| OS/DPI 缩放 | Win32 窗口物理像素和报告尺寸不一致 | manifest/DPI awareness、frame size、OS 缩放。 |
| 视口计算 | 黑边、拉伸、点击偏移 | screen/target/logic/display/safe inset/uiScale。 |
| 资源密度 | 放大后图标和边框模糊 | 原图尺寸、Imageset region、缩放率。 |
| 纹理采样 | 小图标发虚或像素风被平滑 | min/mag filter、半像素对齐。 |
| 字体 | 小字错位、缺字、边缘模糊 | glyph source/cache、font size、UI scale。 |
| 布局 | 不同比例下挤压/空洞 | UDim、安全区、根窗口逻辑尺寸。 |

## 3. 治理原则

1. 先修正物理尺寸、视口和输入映射，再谈资源清晰度。
2. 场景和 UI 允许使用不同的逻辑/渲染目标，但必须有统一 runtime profile。
3. 不用全量改 Lua/layout 硬编码弥补 adapter 错误。
4. 不使用单一实机截图作为全平台比例常量。
5. 所有画质优化同时记录 CPU/GPU/内存，避免只看截图。

## 4. 分阶段方案（研究）

### Phase 1：可观测性

- 三端统一输出 runtime profile。
- 建立代表设备/窗口的截图、输入命中和帧时基线。
- 区分 OS DPI、逻辑尺寸、渲染目标和 UI scale。

### Phase 2：像素契约

- 定义 UI 逻辑像素、物理像素、资源像素和输入坐标的转换。
- 对 1px 线条、九宫格、小图标和文字设立像素对齐规则。

### Phase 3：资源与字体

- 根据实测决定是否引入倍率 Imageset/字体资源。
- 建立资源选择、回退、显存预算和打包策略。

### Phase 4：渲染与性能

- 对 UI 采样、GeometryBuffer 合并、裁剪和 glyph cache 做对照实验。
- 只合入能在三端稳定性和性能基线上证明收益的改动。

## 5. 验收矩阵

- 分辨率/比例：主流手机长宽比、Win32 100%/125%/150%/200% DPI、窗口/全屏。
- UI：登录、主界面、大型面板、聊天/输入、战斗、提示、动态子布局。
- 画质：文字、小图标、边框、半透明、动画和缩放。
- 交互：四角/安全区边缘点击、拖拽、滚动、文本输入。
- 稳定性：前后台、窗口尺寸变化、切场景、切账号、纹理恢复。
