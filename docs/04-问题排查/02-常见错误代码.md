## 0. 排障信息采集（先做这一步）

> AI 与人类排障都依赖“可复现信息”。建议在提问/记录前先收集以下内容。

1. **复现命令**：你执行的是 `Build-MT3-v120.ps1` 还是某个 `msbuild` 命令？把命令原样贴出。
2. **完整错误日志**：优先提供 `build_logs\\*.log` 中对应失败步骤的日志文件路径与关键片段。
3. **工具链信息**（可复制）：

```bat
cmd /c "\"C:\Program Files (x86)\MSBuild\12.0\Bin\MSBuild.exe\" /version"
```

```bat
cmd /c "call \"D:\Program Files (x86)\Microsoft Visual Studio 12.0\VC\vcvarsall.bat\" x86 && cl"
```

## 1. LNK2038：链接时检测到不匹配

### 1.1 典型症状

常见报错形式：

- `LNK2038: mismatch detected for 'RuntimeLibrary'`
- `LNK2038: mismatch detected for 'PlatformToolset'`
- `LNK2038: mismatch detected for 'MDd_DynamicDebug'` / `MT_StaticRelease` 等

### 1.2 根因（高频）

- **运行时库混用**：主工程用 `/MD`（或 `/MDd`），某些第三方库/静态库是 `/MT`（或 `/MTd`）。
- **工具集不一致**：主工程必须是 `v120`，某些 `.lib` 来自其它 VS 版本或不同 toolset。
- **Debug/Release 产物混用**：把 Debug 的 `.lib` 链到 Release 里，或反过来。

### 1.3 修复策略（按优先级）

1. **确认主线约束**：MT3 主工程仅支持 `VS2013 + v120`（见 `AGENTS.md`）。
2. **运行当前可用的配置与依赖审计**（快速定位不一致）：
   ```powershell
   # 当前仓库未保留 tools/scripts/Audit-VcxprojRuntime.ps1；
   # 先用工程文件直接审计 PlatformToolset / RuntimeLibrary。
   rg -n "<PlatformToolset>|<RuntimeLibrary>" `
     client common engine cocos2d-x-2.2.6 tools `
     -g "*.vcxproj" -g "*.props"

   # 构建入口会接入 Win32 依赖修复与运行时审计。
   powershell -ExecutionPolicy Bypass -File .\tools\scripts\Build-MT3-Exe-Canonical.ps1 `
     -Configuration Release -Platform Win32 -BuildMode SafeChain

   # 仅审计当前运行目录二进制依赖。
   powershell -ExecutionPolicy Bypass -File .\tools\scripts\Audit-RuntimeDependencies.ps1 `
     -ScanRoots client\resource\bin\Release
   ```
3. **定位"哪一个库不一致"**：
   - 从 LNK2038 报错行找到涉及的 `.obj/.lib`
   - 查看审计报告中的 "Outliers" 部分
   - 反向定位它来自哪个工程/依赖目录
4. **统一重编译依赖**：
   - 统一 `PlatformToolset=v120`
   - 统一 `RuntimeLibrary`：
     * Release → `/MD` (MultiThreadedDLL)
     * Debug → `/MDd` (MultiThreadedDebugDLL)

**当前状况参考**：不要复用历史固定数量。以本节 `rg` 输出、构建入口日志和 `Audit-RuntimeDependencies.ps1` 报告为准。

### 1.4 验证（可复制）

**第一步：运行审计工具**
```powershell
Set-Location <repo-root>
rg -n "<PlatformToolset>|<RuntimeLibrary>" `
  client common engine cocos2d-x-2.2.6 tools `
  -g "*.vcxproj" -g "*.props"

powershell -ExecutionPolicy Bypass -File .\tools\scripts\Audit-RuntimeDependencies.ps1 `
  -ScanRoots client\resource\bin\Release
```

检查输出：
- 主线工程应保持 `PlatformToolset=v120`
- Release 链路优先保持 `/MD`，Debug 链路优先保持 `/MDd`
- `Audit-RuntimeDependencies.ps1` 不应报告运行目录缺少关键 DLL

**第二步：重新编译验证**
```powershell
Set-Location <repo-root>
powershell -ExecutionPolicy Bypass -File .\tools\scripts\Build-MT3-Exe-Canonical.ps1 -Configuration Release -Platform Win32 -BuildMode SafeChain
```

**参考文档**:
- 运行时依赖审计脚本：[`tools/scripts/Audit-RuntimeDependencies.ps1`](../../tools/scripts/Audit-RuntimeDependencies.ps1)
- Win32 标准构建入口：[`tools/scripts/Build-MT3-Exe-Canonical.ps1`](../../tools/scripts/Build-MT3-Exe-Canonical.ps1)
- CRT 约束规则：[`AGENTS.md`](../../AGENTS.md)

## 2. MSB8020：找不到 v120 生成工具

### 2.1 典型症状

- `error MSB8020: The build tools for v120 (Platform Toolset = 'v120') cannot be found.`

### 2.2 根因

- 未安装 VS2013 或安装不完整（缺少 VC++ 工具链）
- 使用了错误的 MSBuild（不是 12.0）或 PATH 指向其它版本

### 2.3 修复

1. 安装/修复 Visual Studio 2013（确保 VC++ 组件）
2. 验证 MSBuild 12.0：

```bat
cmd /c "\"C:\Program Files (x86)\MSBuild\12.0\Bin\MSBuild.exe\" /version"
```

3. 验证 `vcvarsall.bat`：

```bat
cmd /c "call \"D:\Program Files (x86)\Microsoft Visual Studio 12.0\VC\vcvarsall.bat\" x86 && where cl"
```

## 3. Windows SDK 缺失/不匹配

### 3.1 典型症状

- `fatal error RC1015: cannot open include file 'windows.h'`
- `fatal error C1083: Cannot open include file: 'Windows.h': No such file or directory`
- `error MSB8036: The Windows SDK version ... was not found.`

### 3.2 根因

- Windows SDK 未安装（VS2013 常见需要 Windows SDK 8.1）
- 环境变量/注册表定位失败（少见，多为安装缺失导致）

### 3.3 修复

1. 按 [`docs/03-开发指南/01-Windows编译环境准备.md`](../03-开发指南/01-Windows编译环境准备.md) 安装 VS2013 及 Windows SDK
2. 使用 `vcvarsall.bat` 激活环境后再构建（可减少 SDK 定位问题）：

```bat
cmd /c "call \"D:\Program Files (x86)\Microsoft Visual Studio 12.0\VC\vcvarsall.bat\" x86 && msbuild <your.vcxproj> /t:Build /p:Configuration=Release /p:Platform=Win32 /p:PlatformToolset=v120"
```
