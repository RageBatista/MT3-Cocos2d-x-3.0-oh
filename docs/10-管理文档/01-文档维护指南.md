# MT3 文档维护指南

> **版本**：3.0.0
> **更新日期**：2026-07-15
> **维护者**：技术委员会

## 1. 维护目标

1. 现行基线与源码、脚本、配置、日志和构建结果一致。
2. 专题研究与当前实现明确分层。
3. 历史归档保留日期和证据边界，不伪装成当前规范。
4. 机器产物与 Agent 计划不形成第二事实源。
5. 导航、统计和链接始终来自当前实物。

## 2. 目录角色

| 角色 | 位置 | 维护重点 |
| --- | --- | --- |
| 现行基线 | `01-快速入门/` 至 `07-参考文档/`、`10-管理文档/` | 当前准确、可执行、可验证 |
| 专题研究 | `08-技术研究/` | 区分已实现、实验和未来设计 |
| 历史归档 | `09-历史归档/` | 保留日期、原始结论、证据和当前入口 |
| 机器产物 | `generated/` | 记录来源、批次、格式和 Git LFS 状态 |
| 审计证据 | `audit/` | P0 等专项执行过程产生的 CSV 等结构化证据，不作为规范入口 |

主入口固定为：

- `docs/README.md`
- `docs/07-参考文档/02-文档索引.md`
- `docs/10-管理文档/01-文档维护指南.md`
- `docs/10-管理文档/02-文档审查机制.md`

## 3. 何时必须沉淀

满足任一条件时，应评估并更新文档：

1. 解决了可复现且可能重复出现的构建、链接、运行时或发布问题。
2. 发现新的工具链、ABI、编码、生成代码或资源源头约束。
3. 修改构建入口、执行顺序、输出目录、依赖版本或发布流程。
4. 修改核心架构、接口、协议、运行时流程或平台桥接。
5. 服务目录、平台目录、资源目录或 Agent 配置体系发生变化。
6. 发现入口、索引、链接、统计或历史角色与实物不一致。

## 5. 证据驱动条目模板

````markdown
## 条目标题

### 现象
- 可观察结果和首个错误。

### 复现
```powershell
# 最小复现命令
```

### 根因
- 调用链、配置、日志或工程文件证据。

### 修复
1. 最小必要步骤。

### 验证
```powershell
# 能证明结论的命令
```

### 事实源
- 仓库路径、关键符号、日志或构建产物。

### 关联文档
- 相对链接。
````

不要只写“已修复”；必须记录复现、首个阻塞点、根因、修改和验证证据。

## 6. 标准维护流程

1. **定位角色**：判断是现行基线、研究、历史、机器产物还是 Agent 计划。
2. **回读事实源**：使用 `rg`、`Get-Content`、构建脚本、日志、配置和目录实物取证。
3. **确定处理结论**：保留、修订、合并、归档或删除。
4. **修改权威目标**：先更新主题主文档，再更新 README、索引和交叉链接。
5. **记录影响**：在提交说明或 PR 中列出原因、影响范围、验证和回滚。
6. **执行门禁**：统计、链接、围栏、编码、旧路径和 `git diff --check`。

合并时必须先提取独有事实和证据，再删除来源；删除后不创建跳转页。历史文档中的原始命令可以保留旧路径，但必须标明当时语境。

## 7. 更新通知

### 7.1 通知范围

影响全局认知时至少同步检查：

- `docs/README.md`
- `docs/07-参考文档/02-文档索引.md`
- 对应现行基线文档
- `docs/10-管理文档/` 中相关规则

如需保留审计或里程碑证据，将日期化记录放入 `09-历史归档/`。正式通知渠道是提交说明和 PR 描述；不在规范中假设外部邮箱、机器人或文档平台。

### 7.2 通知模板

```markdown
## 文档更新通知

- 触发原因：
- 受影响代码或目录：
- 受影响文档：
- 当前事实来源：
- 验证命令与结果：
- 风险与回滚：
```

## 8. 命名、路径与编码

- 现行文档使用 `两位序号-主题.md`；历史报告使用 `YYYY-MM-DD-主题.md`。
- 只链接真实存在的仓库相对路径，不写本机绝对路径。
- Markdown 使用 UTF-8 无 BOM、LF；修改后严格解码并检查 BOM、乱码标记和换行。
- `generated/` 的结构化文件由来源流程维护；若当前仅签出 Git LFS pointer，应先拉取对象再分析内容。
- `audit/` 的 CSV 等证据由 P0 等专项流程生成，不作为规范入口，不手工改写。

## 9. 最小验证

```powershell
$files = @(Get-ChildItem docs -Recurse -File)
$md = @($files | Where-Object Extension -eq '.md')
$dirs = @(Get-ChildItem docs -Directory)
"files=$($files.Count); markdown=$($md.Count); topdirs=$($dirs.Count)"

rg -n '目标术语或旧路径' docs
git diff --check
git status --short
```

全量门禁、通过条件和记录要求见 [文档审查机制](./02-文档审查机制.md)。

## 10. 提交与回滚

提交说明至少包含：背景、方案、影响范围、验证结果、风险和回滚。目录迁移或大规模合并应保持单一主题提交；回滚优先使用 Git 恢复对应提交，不手工复建已删除的旧目录。
