# MT3 文档审查机制

> **版本**：4.0.0
> **最后更新**：2026-07-15
> **审查周期**：每季度全量审查、每月入口抽查、变更触发加审

## 1. 审查目标

- 现行基线与工程实物一致。
- 研究、历史、机器产物和 Agent 计划不覆盖当前事实。
- 顶层结构、文件统计、导航和本地链接一致。
- 合并、归档和删除保留可追溯决策与回滚依据。

## 2. 审查范围

### 2.1 每月入口抽查

- `docs/README.md`
- `docs/01-快速入门/`
- `docs/02-技术架构/01-技术体系总览.md`
- `docs/02-技术架构/02-项目架构.md`
- `docs/03-开发指南/` 中的当前构建与资源入口
- `docs/05-平台专项/android/00-README.md`
- `docs/07-参考文档/02-文档索引.md`

### 2.2 每季度全量审查

覆盖 `docs/` 全部文件，并按以下角色分别判定：

1. 现行基线：事实、命令和接口可验证。
2. 专题研究：已实现与设计设想有明确标签。
3. 历史归档：日期、批次、原始证据和当前入口清晰。
4. 机器产物：来源脚本、生成批次、格式和 Git LFS 状态清晰。
5. Agent 设计与计划：状态和未实施项清晰。

### 2.3 变更触发加审

- 构建入口、工具链、ABI 重编顺序或产物目录变化。
- Android 渠道、资源源头、打包或发布链变化。
- 服务目录、生成代码入口、核心架构、接口或协议变化。
- `.codex/`、`.claude/`、`.agents/` 治理入口变化。
- 文档新增、删除、合并、归档或顶层目录变化。

## 3. 审查步骤

1. 盘点文件、Markdown、扩展名和顶层目录。
2. 读取根与就近规则，确定事实裁决顺序。
3. 对每篇文档记录保留、修订、合并、归档或删除。
4. 回读源码、脚本、配置、日志和构建输出，修正权威目标。
5. 更新 README、总索引、交叉链接和维护规则。
6. 删除已吸收来源和空目录。
7. 执行统计、链接、围栏、编码、旧路径和 Git 差异门禁。
8. 在 `09-历史归档/` 写入日期化记录，或更新对应既有里程碑记录。

## 4. 检查清单

### 4.1 结构与角色

- [ ] 顶层目录与 README、索引一致。
- [ ] 现行、研究、历史、机器产物和 Agent 计划角色清晰。
- [ ] 历史报告未被当作当前规范入口。
- [ ] 机器产物未被手工说明替代来源流程。

### 4.2 工程事实

- [ ] Windows 固定入口、v120、SDK 8.1 和 ABI 顺序有工程证据。
- [ ] Android 主线工具链、渠道和资源生成边界有工程证据。
- [ ] 客户端四层运行时、CEGUI 当前版本和依赖关系有源码证据。
- [ ] 服务目录、Ant 目标和生成代码边界有实物证据。

### 4.3 内容质量

- [ ] 每个本地 Markdown 链接目标存在。
- [ ] 围栏成对，代码块语言和 shell 语法一致。
- [ ] Markdown 严格 UTF-8、无 BOM、LF，且无乱码标记。
- [ ] 当前入口不引用已迁移的顶层路径。
- [ ] 数字统计由命令生成，不复制历史报告。

## 5. 通过标准

同时满足以下条件才通过：

1. README、索引和操作记录的当前统计一致。
2. 十二个顶层目录为十个编号目录加 `generated/`、`audit/`。
3. 本地链接不可达项为 0，Markdown 围栏不平衡项为 0。
4. Markdown 编码、BOM、换行和乱码门禁通过。
5. 现行入口中的旧顶层引用为 0。
6. `git diff --check` 退出码为 0。

## 6. 审查输出

全量审查至少产出：

- 逐篇审查清单或等价结构化决策记录；
- 日期化操作记录，包含初始/最终统计、删除、合并、移动、事实修正、验证和回滚；
- 对 README、总索引和管理规则的必要更新。

专题审查可更新既有历史记录，不要求为每次小改动新建报告。

## 7. 风险与回滚

- 历史证据删除前必须确认独有内容已合入目标或由原始数据保留。
- `generated/` 和 Git LFS 对象不得用 pointer 文本推断业务结论。
- 大规模迁移以独立提交落库；发现错误时优先回滚提交，再重新执行审查。
- 尚未执行的后续计划不得写成已验证结果。
