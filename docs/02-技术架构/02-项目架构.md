# 02-项目架构

> **职责**：说明客户端运行时层次、模块边界、启动主链、平台桥接、服务端装配和 ABI 影响。技术栈短表见 [技术体系总览](./01-技术体系总览.md)。

## 1. 客户端四层运行时

```text
Layer 4  FireClient 业务层
         C++ 业务、Lua、UI、协议、Manager、Battle、SceneObj
                         ↓
Layer 3  Nuclear 引擎层
         IEngine/IWorld/IEnv/IQuery、场景、精灵、动画、特效
                         ↓
Layer 2  Cocos 基础层
         Win32/Android/iOS canonical: cocos2d-x-3.0-oh + CEGUI-0.7.9-r5
                         ↓
Layer 1  平台层
         Win32、Android、iOS 生命周期和系统能力桥接
```

三端 canonical 使用 `cocos2d-x-3.0-oh/` 与 `tools/CEGUI-0.7.9-r5/` 的 `Upgrade30` 配置；Android 通过 NDK r16/Ant 工程接入，iOS 通过独立 Upgrade30 Xcode 工程接入。`cocos2d-x-2.2.6/ + dependencies/cegui/` 仅保留给 `Legacy226` 回滚链，历史 `cocos2d-2.0-rc2-x-2.0.1/` 在当前工作树中不存在。

## 2. 模块边界

### 2.1 平台层

- `client/MT3Win32App/`：Win32 进程入口、窗口、CrashDump 和最终链接工程；
- `client/android/`：`common`、`LocojoyProject`、`JoysdkProject`、`YijieProject` 等 Android 公共/渠道工程；
- `client/FireClient/FireClient/`：iOS AppDelegate、ViewController、SDK 与共享 C++ 桥接。

平台层负责生命周期、输入、窗口、通知、录屏、WebView 和渠道 SDK，不承载另一套独立游戏业务核心。

### 2.2 Cocos 基础层

`Upgrade30` 三端共享同一 Cocos/CEGUI 源基线，但平台工程和产物保持独立。Win32 由 `cocos2d-x-3.0-oh/build/` 中以下 v120 工程构建；Android 使用 `Android.mk`，iOS 使用 `cocos2d_libs.xcodeproj`：

- `cocos2d-x-3.0-oh/build/cocos/2d/cocos2d.vcxproj`
- `cocos2d-x-3.0-oh/build/cocos/base/cocosbase.vcxproj`
- `cocos2d-x-3.0-oh/build/external/Box2D/box2d.vcxproj`
- `cocos2d-x-3.0-oh/build/extensions/extensions.vcxproj`
- `cocos2d-x-3.0-oh/build/cocos/scripting/lua-bindings/luabinding.vcxproj`

### 2.3 Nuclear 引擎层

`engine/` 封装场景、精灵、动画、特效、渲染器和运行时环境。真实接口基线包括：

```cpp
Nuclear::IEngine* Nuclear::GetEngine();
```

`IApp` 生命周期为 `InitIni`、`OnInit`、`OnExit`、`OnTick`、`OnBeforeRender`、`OnRenderUI`；`IWorld` 的精灵接口使用 `NewSprite`、`AttachSprite`、`DetachSprite`、`DeleteSprite`、`DeleteAllSprite`。

### 2.4 FireClient 业务层

`client/FireClient/Application/` 的主要职责：

| 模块 | 职责 |
| --- | --- |
| `Framework` | `GameApplication`、共享主循环、Lua 绑定与场景框架 |
| `Manager` | 登录、UI、消息、配置和业务管理器 |
| `Battle` | 战斗流程与结果驱动 |
| `SceneObj` | 角色、NPC、掉落物和跟随对象 |
| `GameUI` / `Utils` | UI 包装与通用桥接 |
| `ProtoDef` | 协议生成结果，不作为手写源维护 |

`Framework` 与 `Manager` 存在双向编排。跨模块公共头变更需要按 ABI 敏感改动处理。

## 3. Win32 启动主链

`client/MT3Win32App/main.cpp` 的主流程：

1. 处理 `Launcher.exe.new` 替换；
2. 使用命名 semaphore 限制并发实例；
3. 解析 `shortcutLaunch=` 参数；
4. 读取 `frameSize.txt`；
5. 读取 `clientsetting_win.ini` 的版本配置；
6. 以日期和时间生成 `.dmp` 文件名并初始化 CrashDump；
7. 调用 `gRunGameApplication()`；
8. 共享主链退出后清理 CrashDump。

`client/FireClient/Application/Framework/GameApplication.cpp` 中：

```text
gRunGameApplication
  -> UpdateEngine::Run
  -> GameApplication::InitIni
  -> LJFM::LJFMOpen::InitFileList
  -> Nuclear::IEngine::Run
```

`GameApplication::OnInit(int step)` 当前分阶段完成：

1. MT3 日志；
2. 网络与协议注册、Lua 脚本模块；
3. bintable 数据加载；
4. 获取 Nuclear 引擎实例；
5. 创建并初始化 `GameUImanager`；
6. 字体与 Lua Hero 管理器；
7. 录音、空间与语音子系统；
8. `GameConfigManager`；
9. `LoginManager`；
10. `MessageManager`；
11. default 尾阶段完成内存等级判断与收尾。

登录阶段按角色数量进入直接进世界、选角或创角分支；是否进入世界还依赖 XmlBean 数据就绪状态。

## 4. 平台桥接

### Android

Android 当前主线工具链为 NDK r16 clang + Ant + JDK 8 + Python 2.7。`LocojoyProject` 是当前 free 主渠道工程；保留的其他渠道目录不等于已经完成同一轮主线复验。

Java 层负责 Application/Activity 生命周期、Breakpad、资源更新、SDK 与系统能力，再通过 JNI 进入共享 C++ 主链。

### iOS

iOS 由 `FireClientAppDelegate`、`FireClientViewController`、`GameSdk` 等 Objective-C/Objective-C++ 组件负责生命周期、通知、分享、录屏和 SDK，再调用共享 `gRunGameApplication()`。

## 5. 服务端装配

`server/server/game_server/build.xml` 先通过 `genrpc`、`genxdb`、`gengbeans` 等目标生成协议、XDB/XBean 和配置代码，再执行编译与 `dist` 打包。

`ModuleManager` 读取 `ModuleInfo`，按依赖 DAG 排序并反射实例化模块，启动时顺序执行 `init()`，退出时逆序执行 `exit()`。场景模块再装配地图、进世界、协议发送、市场和战斗相机等线程。

## 6. Windows 构建依赖与 ABI

外部构建入口固定为 `tools/scripts/Build-MT3-Exe-Canonical.ps1`，内部链为 `client/Build-MT3-v120.ps1`。内部脚本当前依次构建：

```text
platform -> ljfm -> cauthc -> Box2D -> chipmunk -> liblua
-> cocos2d -> CocosDenshion -> libExtensions -> CEGUI
-> engine -> FireClient -> lua51-output-sync -> link-input-sync -> MT3
```

ABI 敏感变更包括类成员、继承、虚函数表、模板实例、内联实现、对象大小/偏移和影响布局的宏变化。

- 修改 `engine/**.h` 或引擎公共布局：`Rebuild engine -> Rebuild FireClient -> Build MT3`；
- 修改 `client/FireClient/Application/**.h` 的业务公共布局：`Rebuild FireClient -> Build MT3`；
- 修改 Cocos2d-x 公共接口：重编对应 Cocos 库，并继续重编 `engine -> FireClient -> MT3`；
- 怀疑混编时停止局部增量，从最上游受影响层开始按下游顺序重建。

`FireClient.win32.vcxproj` 与 `mt3.win32.vcxproj` 共享输出目录（`OutDir`），但中间目录（`IntDir`）各自带项目名前缀（`$(ProjectName).$(Configuration).win32\`）相互独立；单项目显示“最新”不等于 ABI 已一致。启动初始化期若在 STL 容器或 `this + offset` 成员访问处崩溃，应优先核对对象布局、工具集和 `engine.lib` / `FireClient.lib` / `MT3.exe` 时间戳。

## 7. 架构修改的验证原则

1. 先确认改动属于平台壳层、Cocos、Nuclear 还是 FireClient；
2. 生成代码变更先回源定义与生成入口；
3. ABI 敏感头文件按整链重编，不使用 `/FORCE` 掩盖链接问题；
4. 构建通过后仍需验证运行目录、runtime audit 和实际启动；
5. 架构文档与工程冲突时，以源码、脚本、项目文件和构建输出为准。
