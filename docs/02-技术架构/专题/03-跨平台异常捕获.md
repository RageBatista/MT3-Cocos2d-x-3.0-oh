# 跨平台异常捕获

> **定位**：记录 Win32、Android、iOS 崩溃捕获的当前实现差异和证据要求。
> **文档索引**：[docs/07-参考文档/02-文档索引.md](../../07-参考文档/02-文档索引.md)

## 1. 三端实现对照

| 平台 | 当前实现 | 关键入口 | 产物/上报边界 |
| --- | --- | --- | --- |
| Win32 | `SetUnhandledExceptionFilter` + `MiniDumpWriteDump` | `client/MT3Win32App/CrashDump.cpp`，`main.cpp` 初始化/清理 | 本地 DMP；需匹配当次 EXE/PDB。 |
| Android / LocojoyProject | Java 仍调用 `setUpBreakpad()`，但当前 JNI 是日志空桩，没有创建 `ExceptionHandler` | `client/android/LocojoyProject/jni/main.cpp` | 当前 free 主渠道不能按 common 副本推断已有 native dump。 |
| Android / common | 创建 Google Breakpad `MinidumpDescriptor` 与 `ExceptionHandler` | `client/android/common/jni/main.cpp` | 公共/参考副本自身有实现，但不代表任一具体渠道自动使用它。 |
| Android / JoysdkProject | 创建 Google Breakpad `MinidumpDescriptor` 与 `ExceptionHandler` | `client/android/JoysdkProject/jni/main.cpp` | Java 传入缓存目录；工程链接 `breakpad_client`。 |
| Android / YijieProject | 创建 Google Breakpad `MinidumpDescriptor` 与 `ExceptionHandler` | `client/android/YijieProject/jni/main.cpp` | Java 传入缓存目录；工程链接 `breakpad_client`。 |
| iOS | KSCrash，当前 AppDelegate 组装 Quincy installation | `FireClientAppDelegate.mm` | 上报地址由 `GetQuincyServerAddress()` 等当前配置提供。 |

Android 没有统一实现：LocojoyProject 是空桩，common、JoysdkProject、YijieProject 才创建 `google_breakpad::ExceptionHandler`。任何结论必须先绑定到实际构建渠道。

## 2. Win32 主链

```text
_tWinMain
  -> CrashDump_Init(dumpPath, reportExe)
  -> SetUnhandledExceptionFilter
  -> unhandled exception
  -> MiniDumpWriteDump
  -> CrashDump_Clean
```

直接证据：

- [`CrashDump.cpp`](../../../client/MT3Win32App/CrashDump.cpp)
- [`CrashDump.h`](../../../client/MT3Win32App/CrashDump.h)
- [`main.cpp`](../../../client/MT3Win32App/main.cpp)

分析 DMP 前必须保留同一构建的 EXE、PDB、模块清单、构建配置和源码提交。

## 3. Android 主链

四份工程都在 `JNI_OnLoad()` 中设置 JavaVM，Java `GameApp` 也都声明并调用 `setUpBreakpad(getCacheOutDir())`，但 JNI 行为不同：

| 工程 | `setUpBreakpad()` 行为 | 构建侧证据 |
| --- | --- | --- |
| `LocojoyProject` | 只记录 disabled/stub 日志，不读取路径、不创建处理器 | `jni/Android.mk` 编译本目录 `main.cpp`；非 arm64 分支仍声明 `breakpad_client`，但这不会改变空桩行为。 |
| `common` | 读取 Java 路径，创建 `MinidumpDescriptor` 和 `ExceptionHandler` | `jni/Android.mk` 编译本目录 `main.cpp` 并链接 `breakpad_client`。 |
| `JoysdkProject` | 同 common 的实际创建逻辑 | `jni/Android.mk` 编译本目录 `main.cpp` 并链接 `breakpad_client`。 |
| `YijieProject` | 同 common 的实际创建逻辑 | `jni/Android.mk` 编译本目录 `main.cpp` 并链接 `breakpad_client`。 |

排障顺序：

1. 从实际构建命令、项目目录和 APK 来源确认渠道工程，不能只查看 `client/android/common/`。
2. 回读该渠道的 `jni/main.cpp`、`jni/Android.mk` 和 `GameApp.java`，确认 JNI 是空桩还是创建处理器。
3. 对 LocojoyProject，先记录“Java 调用成功但 native 未安装处理器”这一事实；对其余三份实现，再检查 dump 目录权限、ABI 与 `breakpad_client` 是否进入产物。
4. 触发受控崩溃后确认原始 minidump 是否实际落地，再使用对应 ABI 的未裁剪符号和同一源码提交解析。

## 4. iOS 主链

[`FireClientAppDelegate.mm`](../../../client/FireClient/FireClient/FireClientAppDelegate.mm) 引入 KSCrash 并创建 Quincy installation。维护时需分开：

- KSCrash 安装时序。
- 本地报告保留/删除策略。
- 上报 URL 和网络失败处理。
- dSYM、Archive 与源码提交对应关系。

## 5. 日志与崩溃证据

| 证据 | 最低要求 |
| --- | --- |
| 复现信息 | 平台、版本、渠道、时间、首个异常点和操作步骤。 |
| 可执行文件 | 文件哈希、构建配置、工具链、时间戳。 |
| 符号 | Win32 PDB、Android unstripped symbols、iOS dSYM。 |
| dump/report | 原始产物和解析后栈，保留原始产物不覆写。 |
| 日志 | 同一时间窗的 `mt3`/CEGUI/平台日志，先找首个阻断。 |

上传或分享前处理账号、token、cookie、用户输入、地址和设备隐私。

## 6. 变更验证

1. 冷启动应用，确认崩溃处理器只安装一次。
2. 使用可控测试入口触发崩溃，不在用户数据上试验。
3. 验证 dump/report 落地或上报，记录路径和哈希。
4. 使用当次符号成功解析到源文件/行。
5. 验证应用下次启动的报告扫描、重试和清理策略。
