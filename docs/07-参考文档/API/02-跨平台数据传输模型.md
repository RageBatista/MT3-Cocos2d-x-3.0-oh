# 跨平台数据传输模型

> **定位**：游戏客户端共享 C++ 网络层的字节容器、序列化与协议生成参考。
> **当前事实**：Windows、Android、iOS 共享 `FireNet::Octets`、`FireNet::Marshal` 与生成的 `aio::Protocol`。
> **维护日期**：2026-07-15

## 1. 数据链

```text
协议 XML 源定义
      │ rpcgen.jar
      ▼
ProtoDef 生成类（aio::Protocol）
      │ marshal / unmarshal
      ▼
FireNet::Marshal::OctetsStream
      ▼
FireNet::Octets
      ▼
IConnector / INetIO
```

| 组件 | 当前路径 | 职责 |
| --- | --- | --- |
| `Octets` | [`common/cauthc/include/octets.h`](../../../common/cauthc/include/octets.h) | 可增长字节容器、共享表示与写时唯一化 |
| `Marshal` | [`common/cauthc/include/marshal.h`](../../../common/cauthc/include/marshal.h) | 序列化接口、OctetsStream、容器编码和事务 |
| Marshal 实现 | [`common/cauthc/authc/share/marshal.cpp`](../../../common/cauthc/authc/share/marshal.cpp) | 字节序、紧凑整数和基础类型读写 |
| `Protocol` | [`common/cauthc/include/protocol.h`](../../../common/cauthc/include/protocol.h) | 协议基类、类型注册、编码与分发 |
| 客户端连接 | [`NetConnection.cpp`](../../../client/FireClient/Application/Framework/NetConnection.cpp) | 协议/Octets 发送与 C++/Lua 分发 |

`server/core/common` 也有服务端 Octets/Marshal 实现；客户端文档以 `common/cauthc` 的 FireNet 实现为直接事实源。

## 2. `FireNet::Octets`

`Octets` 通过 `Octets_Rep` 管理容量、长度和引用计数：

```cpp
struct Octets_Rep
{
    size_t mCap;
    size_t mLen;
    volatile size_t mRef;
};
```

主要能力包括 reserve/resize/replace、insert/erase/clear、begin/end/size/capacity、拷贝/交换/比较。多个对象可共享底层表示，写操作前通过 `unique()` 获得可写存储。

## 3. `Marshal::OctetsStream`

`OctetsStream` **组合**一个 `Octets data`，并维护读取位置与事务位置；它不继承 `Octets`。

```cpp
class Marshal::OctetsStream
{
    Octets data;
    mutable uint32_t pos;
    mutable uint32_t tranpos;
};
```

当前基础类型重载覆盖 char/bool、16/32/64 位整数、float/double、Marshal、Octets 和单字节字符串。容器通过 `MarshalContainer` 编码长度与元素，覆盖 vector/list/deque/map 等类型。

### 3.1 事务读取

`Marshal::Transaction` 提供 Begin、Commit 和 Rollback，用于解析失败后回退流位置。

## 4. 紧凑整数

`compact_uint32()` 的当前编码分段来自 `marshal.cpp`：

| 数值范围 | 编码长度 | 前缀处理 |
| --- | ---: | --- |
| `< 0x80` | 1 字节 | 直接写入 |
| `< 0x4000` | 2 字节 | 与 `0x8000` 合并 |
| `< 0x20000000` | 4 字节 | 与 `0xc0000000` 合并 |
| 其他 `uint32` | 5 字节 | 先写 `0xe0`，再写 32 位值 |

`compact_sint32()` 对正负数使用不同前缀。调用方不应复制另一套编码器。

## 5. 字节序

多字节基础类型通过 `BYTE16Order`、`BYTE32Order`、`BYTE64Order` 读写。协议字段使用固定宽度类型，避免把平台相关的 `long` 大小写入线格式。

## 6. `aio::Protocol`

`aio::Protocol` 继承 `FireNet::Marshal`，持有协议类型并提供 encode、getType、Process/Dispatch、Clone、优先级/等待/大小策略和 Stub/TStub 注册机制。

`aio::LuaProtocol` 保存协议类型和 `FireNet::Octets data`，由 Lua 协议分发链处理。

## 7. 生成协议

以 [`CEnterWorld`](../../../client/FireClient/Application/ProtoDef/fire/pb/CEnterWorld.hpp) 为例，生成片段包含 `PROTOCOL_TYPE`、字段、构造、validator、marshal/unmarshal、Clone 和 SizePolicy。

生成代码按字段顺序写入和读取。因此协议号、字段顺序/类型、默认值、校验和包大小策略必须由源定义和生成器统一维护。

## 9. 三端一致性

| 项目 | Windows | Android | iOS |
| --- | --- | --- | --- |
| 游戏网络主链 | 共享 C++ FireNet | 同左 | 同左 |
| 协议类型 | 生成的 `aio::Protocol` | 同左 | 同左 |
| 字节容器 | `FireNet::Octets` | 同左 | 同左 |
| 序列化 | `FireNet::Marshal` | 同左 | 同左 |
| 平台职责 | Win32 壳层 | JNI/Activity/SDK | ObjC++/UIApplication/SDK |

平台对象序列化和 Launcher JSON 都不是游戏协议线格式的替代实现。

## 10. 安全与大小边界

1. 安全/压缩算法以连接初始化与服务端协商为准。
2. 不绕过生成代码的 validator 与 SizePolicy。
3. 外部长度先做范围检查，再分配 Octets 或容器。
4. Marshal 异常日志记录协议类型和阶段，不记录账号、Token 或完整敏感包体。
5. 协议变更保持客户端、服务端与 Lua 镜像定义同步。
