# MT3 文档与工程术语表

> **最后更新**：2026-07-15
> **用途**：统一当前文档角色、构建工具链和证据口径。

## 1. 文档角色

### 现行基线

当前仍应优先执行或引用的指南、架构、排障、平台、工具和治理文档。位于 `01-快速入门/` 至 `07-参考文档/`、`10-管理文档/`。

### 专题研究

对架构、算法、版本或工具的分析与设计，位于 `08-技术研究/`。研究结论需要工程实物支持后才能提升为现行基线。

### 历史归档

绑定特定日期、批次或里程碑的审计、验收和变更记录，位于 `09-历史归档/`。历史数字和路径只说明当时状态。

### 机器产物

扫描或分析流程生成的 JSON、CSV、TXT 等结构化证据，位于 `generated/`。使用时需核对生成脚本、批次、Git LFS 状态和上游源码。

### 审计证据

P0 等专项执行过程产生的 CSV 等结构化证据，位于 `audit/`。由专项流程生成，不作为规范入口。

### 事实源（Source of Truth）

用于裁决当前事实的工程文件、脚本、配置、日志、构建输出和目录实物。文档与事实源冲突时，应修正文档。

## 2. Windows 构建

### Visual Studio 2013 / VS2013

MT3 Win32 主线使用的微软 C/C++ 开发环境。

### v120 / `PlatformToolset=v120`

VS2013 对应的平台工具集。主线 Win32 工程需保持 `v120`，不能与新工具集产物混编。

### Windows SDK 8.1

Win32 主线使用的 Windows SDK。环境检查不仅要核对注册表，还要核对 `Include\um\Windows.h` 等实物。

### MSBuild 12.0

VS2013 对应的构建引擎版本。

### Canonical 构建入口

仓库对外统一的 Win32 构建入口：`tools/scripts/Build-MT3-Exe-Canonical.ps1`。

### ABI 安全链

由 `client/Build-MT3-v120.ps1` 承载的内部依赖构建链。涉及 ABI 敏感改动时，需要按影响范围重建 `engine`、`FireClient` 和 `MT3`，不能以单个工程编译成功替代整链一致性。

### CRT / `/MD` / `/MT`

C/C++ 运行时库选项。不同运行时或工具集产物混用常触发 `LNK2038` 或运行时不一致。

## 3. Android 与资源

### Android 主线工具链

当前免费服主线为 NDK r16 clang、Ant、JDK 8、Python 2.7。

### 资源源目录

`client/resource/res/**`，业务资源修改从这里开始。

### Android 资源生成目录

`client/android/LocojoyProject/assets/res/**`，由 `client/resource/tools/LJFilePack_打包安卓.bat` 和后续构建链生成，不作为业务手工修改入口。

### 生成代码

由 `rpc`、`xbean`、`tolua++`、`ProtoDef` 等定义或生成器产生的文件。长期修复应回到源定义和生成入口。

## 5. 审查术语

### 保留 / 修订 / 合并 / 归档 / 删除

- **保留**：主题唯一且内容准确。
- **修订**：主题保留，但事实、路径或表达需要校正。
- **合并**：提取独有内容到权威目标后删除来源。
- **归档**：保留日期化证据并迁入历史目录。
- **删除**：已被覆盖、无独有证据或仅为失效流水账。

### 本地链接

Markdown 中指向仓库内文件或目录的相对链接。目标必须存在；历史文本中的旧路径应作为代码文本保留并注明语境，而不是伪装成可点击入口。

### 严格 UTF-8

使用会对非法字节报错的 UTF-8 解码。`docs/` Markdown 的目标格式为 UTF-8 无 BOM、LF。
