# 客户端打包指南

> 本页是 Windows、Android、iOS 客户端交付入口。构建细节由各平台文档负责，跨平台发布门禁由发布检查清单负责。

## 1. 平台入口

| 平台 | 当前入口 | 主产物 | 发布前文档 |
| --- | --- | --- | --- |
| Windows Win32 | `tools/scripts/Build-MT3-Exe-Canonical.ps1` | `client/resource/bin/Release/MT3.exe` | [Windows 完整构建指南](../03-开发指南/02-Windows完整构建指南.md) |
| Android free | `tools/scripts/Build-Android-Locojoy-WithGate.ps1` | `client/android/LocojoyProject/bin/mt3-debug.apk` 或 `mt3-release.apk` | [Android 索引](android/00-README.md) |
| iOS | Xcode 工程与人工闸门 | 对应 Archive/IPA | [iOS 发布前闸门清单](ios/01-iOS发布前闸门清单.md) |

## 2. 通用打包顺序

1. 固定版本号、渠道、服务器/热更新环境与签名来源。
2. 资源变更先执行资源生成链，禁止手工修改平台生成目录。
3. 使用平台当前入口构建，不用历史批处理替代 Canonical wrapper。
4. 校验包体结构、哈希、签名、运行依赖和版本配置。
5. 在目标环境完成冷启动、登录、入世界和关键业务冒烟。
6. 保存构建日志、产物哈希、发布说明与回滚目标。

## 3. 资源边界

Android 必须遵守：

```text
源目录: client/resource/res/**
打包入口: client/resource/tools/LJFilePack_打包安卓.bat
生成目录: client/android/LocojoyProject/assets/res/**
规则: 生成目录不接受业务手工修改
```

完整资源与热更新流程见 [资源打包与热更新发布指南](../03-开发指南/06-资源打包与热更新发布指南.md)。

## 4. 平台最低验收

### Windows

- `Build-MT3-Exe-Canonical.ps1` 返回成功。
- `client/resource/bin/Release/MT3.exe` 与运行依赖齐全。
- 新进程启动、登录和入世界通过；严格发布使用 runtime audit。

### Android

- 主线固定为 `NDK r16 clang + Ant + JDK 8 + Python 2.7`。
- 当前只复验 `LocojoyProject` 的 `free` 渠道。
- wrapper 的结构、ABI、资源路径、JNI、黑屏防护与 `zipalign` 门禁通过。
- APK 安装、首屏、连续入世界与 logcat 门禁通过。

### iOS

- iOS 配置哈希、更新入口、Lua/C++ 导出、ATS 与引擎库重编状态通过。
- 使用目标证书/描述文件完成 Archive、安装和真机冒烟。

## 5. 发布与回滚

- 跨平台发布入口：[发布检查清单](../06-工具链/workflows/01-发布检查清单.md)。
- 任何平台失败都保留失败产物和日志，不用其他平台结果替代验收。
- 热更新回滚必须成套恢复索引与资源；平台包回滚必须同时恢复匹配配置。
