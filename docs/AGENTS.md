# MT3 文档子树规则

> **定位**：`docs/` 只接受源码、脚本、配置、日志和目录实物驱动的更新；默认叠加根 `AGENTS.md`。

## 1. 首轮路由

- `01-快速入门/`：最短启动路径和项目概览。
- `02-技术架构/`：当前架构基线与跨平台专题。
- `03-开发指南/`：构建、资源、规格和开发流程。
- `04-问题排查/`：可复现故障、错误码和诊断流程。
- `05-平台专项/`：Android、iOS、Windows 专项。
- `06-工具链/`：已验证的工具构建、依赖和发布工作流。
- `07-参考文档/`：术语、总索引和当前 API 参考。
- `08-技术研究/`：专题分析、设计和可行性研究。
- `09-历史归档/`：日期化审计、里程碑、变更记录和原始证据。
- `10-管理文档/`：维护、审查和通知规则。

例外目录：

- `generated/` 是机器产物目录；默认由来源脚本重建，不手工改写结构化产物。
- `audit/` 是审计证据目录；保存 P0 等专项执行过程产生的 CSV 等结构化证据，不作为规范入口。

## 2. 角色边界

- 现行基线：`01` 至 `07`、`10`。
- 专题研究：`08`。
- 历史归档：`09`。
- 机器产物：`generated`。
- 审计证据：`audit`。

历史报告、研究方案和生成数据涉及当前行为时，必须回到工程实物和现行基线复核，不得反向覆盖当前事实。

## 3. 事实裁决顺序

1. 工程文件、源码、构建脚本、配置、日志、构建输出和目录实物。
2. 根与就近 `AGENTS.md`。
3. `.claude/RULES.md` 与 `.claude/BUILD_GUIDE.md`。
4. 当前基线文档。
5. 历史报告、研究资料、机器产物和 Agent 计划。

## 4. 修改要求

- 先定位事实源和目标读者，再决定修订、合并、归档或删除。
- 当前基线只写仓库中真实存在的路径、命令和接口。
- 历史资料保留原日期、原始结论和证据边界；必要时增加当前基线跳转。
- 目录或文件移动后直接更新真实引用，不创建旧路径跳转页。
- `docs/README.md`、`07-参考文档/02-文档索引.md` 和 `10-管理文档/` 必须与实物结构一致。
- 不为一次性审查创建临时脚本；优先使用 `rg`、`Get-ChildItem`、`git diff` 和 `git status` 取证。

## 5. 编码与链接

- Markdown 固定使用 UTF-8 无 BOM、LF。
- 修改前检查 BOM 和换行；修改后执行严格 UTF-8、BOM、乱码特征和回读校验。
- 本地 Markdown 链接必须指向真实文件或目录；代码块中的历史路径应明确标注其日期语境。
- 不引用本机绝对路径、虚构脚本或未落库的计划产物作为当前入口。

## 6. 最小验证

```powershell
$files = @(Get-ChildItem docs -Recurse -File)
$md = @($files | Where-Object Extension -eq '.md')
$dirs = @(Get-ChildItem docs -Directory)
"files=$($files.Count); markdown=$($md.Count); topdirs=$($dirs.Count)"
git diff --check
```

涉及全量治理时，继续执行 [文档审查机制](10-管理文档/02-文档审查机制.md) 中的链接、编码、围栏和旧路径检查。
