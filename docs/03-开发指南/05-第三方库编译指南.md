# 05-第三方库编译指南

> **适用范围**：MT3 Win32 主线第三方链接输入的核对、按需重编与回滚。
> **原则**：逐库取证，不批量改写 vendor 工程，不用新工具集二进制替换 v120 主线。

## 1. 首选入口

`tools/scripts/Build-MT3-Exe-Canonical.ps1` 在调用内部主链前会自动执行：

```text
tools/scripts/Ensure-MT3-Win32-LinkDeps.ps1
```

因此常规构建直接使用 canonical wrapper：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\scripts\Build-MT3-Exe-Canonical.ps1 -Configuration Release -Platform Win32 -BuildMode SafeChain -MaxParallelJobs 8 -StrictRuntimeAudit
```

只有定位第三方链接输入时才单独运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\scripts\Ensure-MT3-Win32-LinkDeps.ps1 -Configuration Release -Platform Win32 -Json
```

## 2. 自动校验范围

> Win32 `Upgrade30` 的 Cocos/CEGUI 输入来自 `cocos2d-x-3.0-oh/build/**` 与 `tools/CEGUI-0.7.9-r5/`；下文出现的 2.2.6 工程只适用于 Android/iOS 或历史兼容链。

当前脚本按实际存在的来源校验或补齐：

| 链接输入 | 当前来源/工程 |
| --- | --- |
| `esUtil.lib` | `cocos2d-x-2.2.6/cocos2dx/platform/third_party/winrt/libraries/vs2013/Win32/` |
| `libspeex.lib` | `dependencies/speex-1.2rc2/win32/VS2008/libspeex/libspeex.vcxproj` |
| `libogg.lib` | `dependencies/libogg-1.3.2/win32/VS2010/libogg_static.vcxproj` |
| `libvorbis.lib` | `dependencies/libvorbis-1.3.7/win32/VS2010/libvorbis/libvorbis_static.vcxproj` |

- `client/MT3Win32App/<Configuration>.win32/`
- `lib/vs2013/Win32/<Configuration>/`

## 3. Cocos2d-x 与 CEGUI

当前内部主链（`EngineProfile=Upgrade30`）直接构建以下工程：

- `cocos2d-x-3.0-oh/build/**` 下的 `cocos30_*` CMake 生成工程
- `tools/CEGUI-0.7.9-r5/cegui-0.7.9.win32.vcxproj`

Win32 CEGUI 当前运行依赖版本是 0.7.9-r5。`dependencies/cegui/` 及 `tools/CEGUI-0.7.1/` 仅供 Android/iOS、旧工具或差异研究，不能混入 Win32 `Upgrade30`。

## 4. 逐库重编模板

先确认工程、配置名、平台和输出路径，再执行单库重编：

```powershell
$project = 'DEPENDENCY_PROJECT.vcxproj'
$configuration = 'Release'
$platform = 'Win32'
$vcvars = Join-Path $env:VS120COMNTOOLS '..\..\VC\vcvarsall.bat'
$msbuild = if ($env:MT3_MSBUILD_PATH) {
    $env:MT3_MSBUILD_PATH
} else {
    Join-Path ${env:ProgramFiles(x86)} 'MSBuild\12.0\Bin\MSBuild.exe'
}

cmd /c "call `"$vcvars`" x86 && `"$msbuild`" `"$project`" /t:Rebuild /p:Configuration=`"$configuration`" /p:Platform=$platform /p:PlatformToolset=v120 /p:VisualStudioVersion=12.0 /nr:false /m /nologo"
```

模板中的配置名必须以目标工程的真实 `ProjectConfiguration` 为准；不要假设所有旧工程都使用相同的 `Debug/Release` 名称。

## 5. 修改边界

### 可以做

- 针对一个已确认的主线依赖修复源码或工程配置；
- 保持原编码、BOM、换行和配置名；
- 记录修改前后的 `PlatformToolset`、`RuntimeLibrary`、预处理器宏和输出路径；
- 用 v120 重编，并继续验证下游 `engine -> FireClient -> MT3`。

### 不应做

- 递归替换仓库所有 `.vcxproj` 的 `PlatformToolset` 或 `RuntimeLibrary`；
- 把 Debug/Release、静态/动态 CRT 统一成一个未经验证的值；
- 对 `dependencies/**` 批量格式化、转码或升级工程格式；
- 手工修改 `.lib`、`.dll`、`.exe`；
- 使用 v140+ 产物或 `/FORCE` 掩盖符号/CRT 冲突；
- 从历史 Cocos 2.0 树复制库覆盖当前 `cocos2d-x-2.2.6` 主线。

## 6. 验证与回滚

```powershell
# 查看本次生成/暂存的库
Get-ChildItem .\client\MT3Win32App\Release.win32 -Filter '*.lib' | Sort-Object Name | Select-Object Name, Length, LastWriteTime
Get-ChildItem .\lib\vs2013\Win32\Release -Filter '*.lib' | Sort-Object Name | Select-Object Name, Length, LastWriteTime

# 重新进入主线构建
powershell -ExecutionPolicy Bypass -File .\tools\scripts\Build-MT3-Exe-Canonical.ps1 -Configuration Release -Platform Win32 -BuildMode SafeChain -MaxParallelJobs 8 -StrictRuntimeAudit
```

失败时优先回退本次单库源码/工程修改，再从受影响层开始重编；不要通过删除整棵 vendor 目录或批量改工程来恢复。

常见链接错误见 [编译问题排查](../04-问题排查/01-编译问题排查.md)。
