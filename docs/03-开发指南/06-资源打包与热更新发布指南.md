# 资源打包与热更新发布指南

> 适用范围：Windows、Android、iOS 客户端资源生成、热更新发布与回滚。
> 工程事实优先级：资源源目录与打包脚本 > 构建/同步脚本 > 发布目录与历史文档。

## 1. 资源目录边界

Android 资源链固定为：

```text
源目录: client/resource/res/**
打包入口: client/resource/tools/LJFilePack_打包安卓.bat
生成目录: client/android/LocojoyProject/assets/res/**
规则: 生成目录不接受业务手工修改
```

其中 `client/res_android/res/**` 是 `LJFilePack` 生成后的 Android 同步输入；`Build-Android-Locojoy-WithGate.ps1 -SyncRes` 再将它同步到 APK 工程。业务修改必须回到 `client/resource/res/**`，禁止直接补写、删除或覆盖 `assets/res/**`。

资源改动后从仓库根目录执行：

```powershell
cmd /c "cd /d E:\MT3\client\resource\tools && LJFilePack_打包安卓.bat"
```

## 2. 热更新运行链

当前代码锚点：

- 公共更新引擎：`common/updateengine/**`
- Windows Launcher：`client/Launcher/Code/Update/**`
- PFS 工具：`tools/engine/pfs/**`
- Android 下载器：`client/android/*/src/com/locojoy/mini/mt3/FileDownloader.java`
- iOS 下载器：`common/updateengine/ios/FileDownloader.mm`

核心产物与职责：

| 产物 | 职责 |
| --- | --- |
| `ver.ljvi` | 版本与更新站点信息 |
| `fl.ljpi` | 文件列表、Size/CRC32 与补丁索引 |
| `fl.ljzip` | 传输中的压缩索引 |
| `UpdateJson` | 版本、渠道与下载地址决策输入 |
| `PackInfo` | Add/Mod/Del 差异计算与应用依据 |

运行流程为：加载本地索引 -> 请求更新描述 -> 下载并解压新索引 -> 计算 Add/Mod/Del -> 下载到 `cache/update` -> 校验 Size/CRC32 -> 更新运行资源 -> 清理缓存。

## 3. 发布前生成与静态校验

1. 确认本轮业务资源仅从 `client/resource/res/**` 修改。
2. 重新执行对应平台资源打包链，禁止复制旧生成目录冒充新产物。
3. 确认同一发布目录中的 `ver.ljvi` 与 `fl.ljpi` 成对存在且非空。
4. 抽样核对 Add/Mod/Del、文件大小与 CRC32；配置哈希文件必须与源配置一致。
5. Android 使用 Canonical wrapper 同步资源并重打 APK，不直接提交手工修改的 `assets/res/**`。

补丁目录静态检查：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\.agents\skills\resource-packaging-pipeline\scripts\verify-patch-layout.ps1 -Json
```

## 4. 平台发布验证

### 4.1 Windows

- 用 Launcher 从旧版本执行一次完整升级。
- 检查 `cache/update` 下载、校验、应用与清理日志。
- 核对 `client/resource/bin/Release/` 中主程序、运行库和本轮资源。

### 4.2 Android

- 当前免费服构建入口：`tools/scripts/Build-Android-Locojoy-WithGate.ps1`。
- 当前 wrapper 输出：`client/android/LocojoyProject/bin/mt3-debug.apk` 或 `mt3-release.apk`。
- 验证 APK 内资源、`aapt dump badging`、ABI/结构门禁和安装结果。
- 完整流程见 [Android 构建流程](../05-平台专项/android/04-构建流程.md)。

### 4.3 iOS

- 核对 `client/resource/res/cfg/clientsetting_ios.ini` 与 `client/res_ios/res/1912606767`。
- 核对热更新目录中的 iOS 哈希配置，不使用 Android 的 `2863654426` 代替。
- 完整门禁见 [iOS 发布前闸门清单](../05-平台专项/ios/01-iOS发布前闸门清单.md)。

## 5. 运行验收

- 空缓存冷启动可完成更新并进入登录界面。
- 下载中断后恢复网络，客户端可重试或重新进入更新流程。
- 旧包升级到新版本时 Add/Mod/Del 均生效。
- Windows、Android、iOS 分别完成登录、选服、入世界和切场景。
- 日志中无新增校验失败、解包失败、资源缺失或平台下载器崩溃。

## 6. 回滚

1. 发布前保留上一版 `ver.ljvi`、`fl.ljpi` 和对应资源快照。
2. 回滚时先停止继续分发，再恢复成套索引与资源，禁止只回退其中一个索引。
3. 平台包与热更新资源必须回到同一兼容版本。
4. 回滚后重新执行冷启动、跨版本升级和关键业务冒烟。
5. 记录失败文件、Size/CRC32、下载日志、影响平台与回滚时间。
