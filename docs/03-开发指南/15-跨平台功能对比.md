# 跨平台功能对比规格书（代码基线版）

> **文档版本**: 2.0.0
> **最后更新**: 2026-03-28
> **审计范围**: `client/android/common/`、`client/android/LocojoyProject/`、`client/android/JoysdkProject/`、`client/android/YijieProject/`、`client/FireClient/FireClient/`、共享 `GameApplication` C++ 主链；`LocojoyProject64` 为历史废弃目录

---

## 1. 结论摘要

Android 与 iOS 的主线并不是“两套独立游戏实现”，而是：

- 共享同一套 `GameApplication + Nuclear + Cocos2d-x + FireClient` C++ 主链
- Android 用 Java + JNI 承担平台桥接
- iOS 用 Objective-C / Objective-C++ 承担平台桥接

因此跨平台差异主要集中在：

1. 启动壳层
2. SDK 集成
3. 权限 / plist 声明
4. 系统能力桥接

## 2. 启动链对比

| 维度 | Android | iOS |
|---|---|---|
| Application 入口 | `Mt3Application.attachBaseContext()` | `main.m -> UIApplicationMain` |
| 多 dex | `MultiDex.install(this)` | 无 |
| 主壳层 | `GameApp extends Cocos2dxActivity` | `FireClientAppDelegate + FireClientViewController` |
| 崩溃初始化 | 四份 `GameApp.java` 均在 `onCreate()` 早期调用 `setUpBreakpad()`；LocojoyProject JNI 为空桩，common/JoysdkProject/YijieProject JNI 创建 `ExceptionHandler` | `installCrashHandler()` 在首轮 `gRunGameApplication()` 之后安装 |
| 分享 SDK 初始化 | `SDKShare.init()` | `ShareSDK registerApp` |
| 客服 SDK 初始化 | `MQManager.init(...)` | `MQManager initWithAppkey` |
| 进入共享主链 | `nativeStartResourceUpdate()` 线程进入更新链，随后由 JNI 落到共享 C++ 主链 | 非 `UPDATE_ENGINE_ENABLE` 分支直接 `gRunGameApplication()`；开启更新界面时在更新完成后进入 |

共同点：

- 最终都落到共享 C++ 主链。
- 登录、支付、资源更新、协议和场景/战斗核心都不在 Java / Objective-C 独立实现。

### 2.1 Android 崩溃初始化的渠道差异

| Android 工程 | Java 层 | JNI 层 |
|---|---|---|
| `LocojoyProject` | `GameApp.onCreate()` 调用 `setUpBreakpad(getCacheOutDir())` | `main.cpp` 保留 JNI 空桩，只记录 disabled 日志，不创建 `ExceptionHandler` |
| `common` | `GameApp.onCreate()` 调用 `setUpBreakpad(getCacheOutDir())` | 创建 `MinidumpDescriptor` 和 `google_breakpad::ExceptionHandler` |
| `JoysdkProject` | `GameApp.onCreate()` 调用 `setUpBreakpad(getCacheOutDir())` | 创建 `MinidumpDescriptor` 和 `google_breakpad::ExceptionHandler` |
| `YijieProject` | `GameApp.onCreate()` 调用 `setUpBreakpad(getCacheOutDir())` | 创建 `MinidumpDescriptor` 和 `google_breakpad::ExceptionHandler` |

因此 Android Java 调用入口一致，但 native 崩溃处理是否实际安装必须按当前构建工程判断。

## 3. 共享能力与差异能力

### 3.1 共同能力

| 能力 | Android | iOS | 说明 |
|---|---|---|---|
| 资源更新 | 是 | 是 | 共享 `UpdateEngine` 主链 |
| 渠道登录 | 是 | 是 | 均有平台 SDK 包装类 |
| 支付 | 是 | 是 | 均通过平台 SDK 回调进入 C++ |
| 分享 | 是 | 是 | 均集成 ShareSDK |
| 客服 | 是 | 是 | 均集成 MeiQia |
| 公告 / WebView | 是 | 是 | Android `HTML5WebView`，iOS `showWebView` |
| 语音相关 | 是 | 是 | Android `WavRecorder`；iOS 录音 / 语音桥接 |

### 3.2 Android 特有或更强依赖的能力

| 能力 | 代码证据 |
|---|---|
| MultiDex | `Mt3Application.attachBaseContext()` |
| JNI 回调集合 | `GameSDK.java` 的 `loginCb / payCb / logoutCb / YYBLoginCb ...` |
| Manifest 权限分渠道差异 | 四套源码工程权限数不同 |
| Baidu 定位 | `GameApp.java` 中 `LocationClient` / `BDLocation` |
| 语音录制实现 | `WavRecorder.java` |

### 3.3 iOS 特有或更强依赖的能力

| 能力 | 代码证据 |
|---|---|
| `AVAudioSession` 音频会话 | `FireClientAppDelegate.mm` |
| 本地通知注册 | `registerUserNotificationSettings` |
| ReplayKit 屏幕录制 | `FireClientViewController.mm` 的 `startRecord / stopRecord` |
| Chartboost | `FireClientViewController.mm` |
| KSCrash | `FireClientAppDelegate.mm` |

## 4. 登录 / 支付 / 分享对比

| 流程 | Android | iOS | 一致性结论 |
|---|---|---|---|
| 登录 | `GameSDK.login -> sdk.login -> loginCb` | `GameSdk.login -> 平台 SDK -> callback` | 业务结果一致，桥接不同 |
| 支付 | `GameSDK.pay -> payCb` | `GameSdk.pay -> pay callback` | 业务结果一致，桥接不同 |
| 分享 | `SDKShare -> GameApp.shareSucceed()` | `oneKeyShareToPlatform` | 都通过原生分享 SDK 回调到主链 |
| 客服 | MeiQia Activity | MeiQia ViewController / Manager | 平台 UI 容器不同 |

## 5. 权限与配置对比

### 5.1 Android

Android 当前并不是统一一份权限配置：

- `LocojoyProject`：21 项唯一权限
- `JoysdkProject` / `YijieProject`：29 项唯一权限；`LocojoyProject64` 为历史废弃目录，不再作为当前权限基线

### 5.2 iOS

iOS 当前默认 target 使用 `FireClient-Info.plist`，但仓库存在 17 个 `FireClient*.plist` 渠道 / 分支配置文件。

当前默认 `FireClient-Info.plist` 中可直接验证：

- `CFBundleShortVersionString = 0.0.71`
- `NSLocationWhenInUseUsageDescription`
- ShareSDK / WeChat / QQ / Weibo URL Scheme
- `UIApplicationShortcutItems`

## 6. 构建系统对比

| 维度 | Android | iOS |
|---|---|---|
| 主构建系统 | `ndk-build + Ant` | Xcode 工程 |
| 主工具链 | NDK r16 clang + Ant + JDK8 | Xcode / clang |
| 资源桥接 | Java 调 JNI | Objective-C++ 调 C++ |
| 包管理口径 | Ant + 内置 jar/so | Xcode 工程 + 嵌入 framework |
| 64 位差异 | 当前免费服在 `LocojoyProject` 内固定 arm64-v8a/r16；`LocojoyProject64` 已废弃 | plist / target 配置分支 |

结论：

- 当前代码没有证据支持“iOS 主线使用 CocoaPods”的说法。
- Android 已经出现 64 位目录与 toolchain 分支，文档必须把它和 32 位渠道一起纳入范围。

## 7. 当前文档已纠正的典型偏差

- 旧文档把 Android WebView 写成缺失；当前代码显示 Android 与 iOS 都具备 WebView 能力。
- 旧文档把 Android 屏幕录制写成具备；当前主线更明确的是语音录制，屏幕录制证据在 iOS ReplayKit 侧。
- 旧文档把 iOS 写成五层独立核心；当前更准确的说法是共享四层核心 + Objective-C 平台桥接。
- 旧文档把 iOS 构建写成 `Xcode + CocoaPods`；当前代码只验证到 Xcode 工程与嵌入 framework。
