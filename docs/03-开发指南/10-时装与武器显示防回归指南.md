# 时装切换武器显示：共享 C++ 规则与防回归手册

## 1. 目标行为（跨平台统一）

目标行为：

- 切换时装后，仍显示角色武器
- 时装只替换外观（body/造型），不读取时装模型下的武器资源

适用范围：

- Windows 客户端（`MT3.exe`）
- Android 客户端（`mt3-release.apk`）
- iOS 客户端（共享引擎规则同源）

本规则属于共享 C++ 引擎行为，不是 Lua 侧可最终兜底的问题。

## 3. 主链路（从组件刷新到武器资源解析）

### 3.1 FireClient 组件刷新层

关键入口：

- `client/FireClient/Application/GameUI/UISprite.cpp`
- `client/FireClient/Application/SceneObj/ComponentsObject.cpp`

组件关系：

- `eSprite_Fashion`：时装组件
- `eSprite_Weapon`：武器组件

这些函数负责刷新组件，但“武器是否最终显示”取决于引擎资源解析规则。

### 3.2 Engine 资源解析层（根因修复点）

文件：

- `engine/sprite/nuspritemanager.cpp`

固定规则：

1. `fashion-*` 的 `weapon` 层是可选层，缺失不阻断整模
2. `ResolveWeaponSourceModel(...)` 会把时装映射回 `role-*`
3. `ResolveWeaponAniUri(...)` 会从 `role-*` 读取武器动画资源
4. `GetComponent(...)` 对 `weapon` 层回退到 `role-*` 组件表

## 4. 为什么“只改 Lua”会失效

Lua 可以控制组件下发与界面刷新，但不能改变引擎底层的武器资源解析路径。

结论：

- Lua 侧临时兜底不能作为正式修复点
- 正式行为必须以共享 C++ 规则为准

## 5. 防回归红线

禁止项：

1. 不要删除 `ResolveWeaponSourceModel` 在 `weapon` layer 的使用
2. 不要把 `ResolveWeaponAniUri` 改回直接拼 `fashion-*` 的武器目录
3. 不要把时装 `weapon` 层恢复成“缺失即失败”
4. 不要移除 `GetComponent` 对 `role-*` 的 weapon 回退
5. 不要只在单平台做分支修补
