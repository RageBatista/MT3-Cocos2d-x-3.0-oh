# MT3 当前依赖矩阵

> **定位**：本页是仓库唯一的当前依赖矩阵。
> **口径**：“目录存在”只代表资产存在；“当前使用”必须有工程、构建脚本或源码引用证据。
> **文档索引**：[docs/07-参考文档/02-文档索引.md](../07-参考文档/02-文档索引.md)

## 1. 状态定义

| 状态 | 含义 |
| --- | --- |
| 当前主线 | 由交付工程或 Canonical 脚本直接编译/链接。 |
| 工具专用 | 被某个编辑器或辅助工程引用，不等同于游戏客户端主线。 |
| 研究/历史 | 用于升级评估、产物对照或回滚，不可写成现行依赖。 |
| 资产待复核 | 目录存在，本页未找到足以宣告当前使用的直接引用。 |

## 4. Win32 主链构建顺序

[`tools/scripts/Build-MT3-Exe-Canonical.ps1`](../../tools/scripts/Build-MT3-Exe-Canonical.ps1) 完成工具链、链接输入和 LFS 预检后，调用 [`client/Build-MT3-v120.ps1`](../../client/Build-MT3-v120.ps1)。内部脚本的编译依赖顺序是：12 个 `buildSteps` 工程、`lua51-output-sync`、`link-input-sync`、`MT3`。前 11 个工程构成 `FireClient` 前的基础依赖层：

| 序号 | 步骤 | 工程 |
| --- | --- | --- |
| 1 | platform | `common/platform/platform.win32.vcxproj` |
| 2 | ljfm | `common/ljfm/ljfm.win32.vcxproj` |
| 3 | cauthc | `common/cauthc/projects/windows/cauthc.win32.vcxproj` |
| 4 | libBox2D | `cocos2d-x-2.2.6/external/Box2D/proj.win32/Box2D.vcxproj` |
| 5 | libchipmunk | `cocos2d-x-2.2.6/external/chipmunk/proj.win32/chipmunk.vcxproj` |
| 6 | liblua | `cocos2d-x-2.2.6/scripting/lua/proj.win32/liblua.vcxproj` |
| 7 | cocos2d | `cocos2d-x-2.2.6/cocos2dx/proj.win32/cocos2d.vcxproj` |
| 8 | CocosDenshion | `cocos2d-x-2.2.6/CocosDenshion/proj.win32/CocosDenshion.vcxproj` |
| 9 | libExtensions | `cocos2d-x-2.2.6/extensions/proj.win32/libExtensions.vcxproj` |
| 10 | CEGUI | `dependencies/cegui/project/win32/cegui.win32.vcxproj` |
| 11 | engine | `engine/engine.win32.vcxproj` |
| 12 | FireClient | `client/MT3Win32App/FireClient.win32.vcxproj` |
| 13 | lua51-output-sync | 将当前配置可用的 `lua51.lib` / `lua51.dll` 同步到 Cocos2d-x 当前配置输出目录 |
| 14 | link-input-sync | 将最终链接所需 `.lib` 同步到 `client/MT3Win32App/<Configuration>.win32/` |
| 15 | MT3 | `client/MT3Win32App/mt3.win32.vcxproj` |

### 4.1 `lua51-output-sync` 输入、输出与作用

| 项目 | 当前脚本行为 |
| --- | --- |
| `lua51.lib` 输入候选 | 依次检查 `client/resource/bin/<Configuration>/lua51.lib`、`client/MT3Win32App/<Configuration>.win32/lua51.lib`，再检查对应 Release 回退位置。 |
| `lua51.dll` 输入候选 | 依次检查 `client/resource/bin/<Configuration>/lua51.dll`、Release、Debug 运行目录。 |
| 输出 | `cocos2d-x-2.2.6/<Configuration>.win32/lua51.lib` 与 `lua51.dll`。 |
| 作用 | 先补齐 `Get-LinkInputMap()` 所声明的 `lua51.lib` 标准位置，再由 `link-input-sync` 汇总最终链接输入；同时为后续 runtime sync 提供当前配置的 `lua51.dll`。脚本对每个必需文件按候选顺序选择首个存在项，前序候选缺失时会继续回退；只有 `lua51.lib` 或 `lua51.dll` 的全部候选都不存在时，该必需文件才会使步骤失败。文件仅在内容变化时复制。 |

`MT3` 链接完成后，内部脚本还会执行 `runtime-sync` 和 `runtime-audit`；它们属于交付门禁，不改变上述编译依赖顺序。

## 5. ABI 与运行库约束

| 维度 | Debug | Release |
| --- | --- | --- |
| PlatformToolset | v120 | v120 |
| 平台 | Win32 | Win32 |
| CRT | `/MDd` | `/MD` |
| 工具构建 | 必须与自身依赖配置一致 | 必须与自身依赖配置一致 |

修改跨库公共头文件、编译开关、CRT 或依赖版本时，按 [Windows 完整构建指南](../03-开发指南/02-Windows完整构建指南.md) 整链重编，不交付混编产物。

## 6. 复查命令

```powershell
rg -n '<PlatformToolset>|<RuntimeLibrary>|AdditionalDependencies|AdditionalLibraryDirectories' client engine common dependencies cocos2d-x-2.2.6 --glob '*.vcxproj'
rg -n 'dependencies[/\\]cegui|CEGUI-0\.7\.1|CEGUI-0\.7\.9' client tools --glob '*.{vcxproj,props,mk,pbxproj}'
```
