# Cocos2d-x 2.2.6 构建依赖引用审计报告

---
**日期**: 2026-07-03
**范围**: Cocos2d-x 版本事实、Win32/Android 构建脚本、工程引用、文档纠偏
**结论**: 当前主线已升级到 `cocos2d-x-2.2.6`
---

## 1. 当前事实

仓库根目录同时存在：

- `cocos2d-x-2.2.6/`：当前主线 Cocos2d-x 目录。
- `cocos2d-2.0-rc2-x-2.0.1/`：历史/回滚/差异基线，不作为当前 Win32 主构建路径。

版本标记已核验：

- `cocos2d-x-2.2.6/cocos2dx/cocos2d.cpp` 返回 `cocos2d-x 2.2.6`。
- `cocos2d-x-2.2.6/cocos2dx/include/cocos2d.h` 中 `COCOS2D_VERSION` 为 `0x00020206`。

### 2.2 Android

`.claude/BUILD_GUIDE.md` 与 `tools/scripts/Assert-AndroidArm64Migration.ps1` 已把 Android arm64 门禁绑定到 `cocos2d-x-2.2.6`，并检查 `libxml2/libwebp` 等预编译库不得漂回旧 2.0 树。

### 2.3 需要继续关注的旧引用

以下引用不代表当前 Win32 主线，但需要在后续专项中分流治理：

| 范围 | 现状 | 建议 |
|---|---|---|
| `client/FireClient/FireClient.sln` | 仍引用不存在的 `cocos2d-x-2.2.6-mt3` | 不作为当前 canonical 构建入口；若恢复使用该解决方案，应先改到 `cocos2d-x-2.2.6` |
| `common/updateengine/updateengine.win32.vcxproj`、`common/updateengine/updateengine.vcxproj` | 仍有 `cocos2d-2.0-rc2-x-2.0.1` include 路径 | 属于 updateengine / WP / WinRT 遗留链路，不作为当前 MT3.exe canonical 构建入口；需专项决定是否迁移或归档 |
| iOS / Xcode 工程 | `common/platform/share.xcodeproj/project.pbxproj`、`dependencies/cegui/CEGUI.xcodeproj/project.pbxproj` 仍有旧 2.0 搜索路径 | 作为 iOS/CEGUI Xcode 遗留项专项评估，不能覆盖当前 Win32/Android 主线结论 |
| `client/luajit.py` | 仍指向旧 2.0 树下的 iOS LuaJIT 工具路径 | 仅作为 LuaJIT 字节码工具脚本残留记录；当前 Win32 主线 `liblua` 工程位于 `cocos2d-x-2.2.6/scripting/lua/proj.win32` |
| `tools/scripts/Build-Android-Arm64-PrebuiltLibs.ps1` | 仍把部分 arm64 预编译输出写回旧 2.0 树 | 与 `Assert-AndroidArm64Migration.ps1` 的 2.2.6 门禁存在方向冲突，需单独修脚本后再封板 |
| 历史审计/迁移文档 | 保留 2026-06-10 前后的旧结论 | 已补充历史快照/时效声明；按历史快照阅读，不覆盖当前主线事实 |

## 3. 文档修正原则

本次修正遵循以下规则：

- 当前事实入口、快速入门、构建步骤、依赖清单和排障命令必须写 `cocos2d-x-2.2.6`。
- `cocos2d-2.0-rc2-x-2.0.1` 只作为历史/回滚/差异基线出现。
- 带明确日期的历史报告不伪造当时结论；通过本报告和索引标注其时效。
- `-FmodDll` 已被当前 Win32 Cocos2d-x 2.2.6 迁移链忽略，不再作为构建前置依赖。

## 5. 后续建议

1. 单独修复 `client/FireClient/FireClient.sln` 的 `cocos2d-x-2.2.6-mt3` 残留，或在文档中明确该解决方案停止作为构建入口。
2. 单独审核 `common/updateengine/*.vcxproj`、WP/WinRT 工程是否仍需维护；若不维护，应转为历史平台说明，避免影响 Win32 主线判断。
3. 单独审核 iOS / Xcode 工程中的旧 2.0 搜索路径，确认 iOS 是否跟随当前 2.2.6 主线迁移，或明确归档为历史平台链路。
4. 单独审核 `client/luajit.py` 的旧 LuaJIT 路径，确认它是否仍参与 iOS 字节码生成；若保留，应迁移到当前工具位置或写明历史用途。
5. 单独审核 `tools/scripts/Build-Android-Arm64-PrebuiltLibs.ps1`，使 arm64 预编译输出与 `Assert-AndroidArm64Migration.ps1` 的 2.2.6 门禁一致。
