## 6. 文档-代码同步机制建议

### 6.1 现有机制评估

项目已具备较完善的文档治理体系（`docs/10-管理文档/` 两篇 + `docs/AGENTS.md`），含审查周期、检查清单、通过标准和事实裁决顺序。本次发现的 27 个问题中，多数属于"代码演进后文档未同步"的漂移，而非治理框架缺失。

### 6.2 强化建议

1. **关键工程事实锚点化**：对 IntDir/OutDir、Cocos 物理依赖、CEGUI 版本、NDK/JDK 版本、构建入口脚本等高频事实，在 `docs/10-管理文档/` 增设"工程事实锚点表"，每次构建入口或 ABI 变更触发锚点回核。
2. **统计数字去快照化**：现行基线文档中凡含具体文件数、行数、行号的内容，应标注"截至 YYYY-MM-DD"或改为"数量级参考"。本次 layout 822→857、res\_win 493→数万、main.cpp 行号偏移均属此类。
3. **目录实物对账自动化**：将 `docs/AGENTS.md` 第 6 节的最小验证脚本扩展为 CI 钩子，每次提交触发：顶层目录枚举、统计数字校验、`superpowers`/`audit` 等关键目录存在性检查、Markdown 链接可达性检查。
4. **幻影目录防护**：本次 `superpowers/` 被多处引用但从未进入 git 历史。建议在审查机制中增加"索引中引用的目录必须 `git ls-files` 非空"门禁。
5. **事实源上行同步**：当根 `AGENTS.md` 或 `.trae/rules/project_rules.md` 的声明与工程实物冲突时，应先修正事实源再下行同步 docs/。本次 iOS Cocos 2.0 声明即为事实源本身过时的案例。
