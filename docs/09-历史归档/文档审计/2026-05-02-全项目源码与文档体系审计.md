## 十二、文档-代码同步机制

### 12.1 同步机制设计

为确保文档与代码的长期一致性，建立以下三层同步机制：

#### 12.1.1 第一层：代码变更触发文档审查

| 变更类型 | 触发条件 | 需审查的文档 |
|----------|----------|-------------|
| 协议定义变更 | `ProtoDef/rpcgen/**/*.inc` 文件修改 | `api/跨平台API接口文档.md` |
| 新增/修改API接口 | `controllers/*.php` 新增 public 方法 | `server/**/doc/*.txt` |
| 架构层级变更 | `engine/`、`FireClient/` 头文件修改 | `02-技术架构/19-项目架构分析报告.md` |
| 构建流程变更 | `.ps1`、`.xml`、`.vcxproj` 修改 | `03-开发指南/06-编译完整指南.md` |
| 平台配置变更 | `AndroidManifest.xml`、`.plist` 修改 | `05-平台专项/**/*.md` |

#### 12.1.2 第二层：定期审计周期

| 审计频率 | 审计范围 | 执行方式 |
|----------|----------|----------|
| **每次PR** | 变更文件关联的文档 | 人工审查 + 检查清单 |
| **每月** | API文档全量协议号验证 | 自动化脚本 `verify_protocol_docs.ps1` |
| **每季度** | 全量文档-代码对齐审计 | 完整审计报告 |

#### 12.1.3 第三层：自动化校验

建议在 CI/CD 流程中增加以下自动化检查：

```yaml
文档校验流水线:
  - 协议号校验:
      脚本: tools/scripts/verify_protocol_docs.ps1
      触发: ProtoDef/ 目录变更
      动作: 比对 api/跨平台API接口文档.md 中的协议号与实际 .inc 文件
  
  - API接口校验:
      脚本: tools/scripts/verify_api_docs.ps1
      触发: controllers/ 目录变更
      动作: 比对 server/**/doc/*.txt 中的接口列表与实际 public 方法
  
  - 构建命令校验:
      脚本: tools/scripts/verify_build_docs.ps1
      触发: .ps1/.xml/.vcxproj 变更
      动作: 比对开发指南中的构建命令与实际脚本
```

### 12.2 文档更新检查清单

每次代码变更后，开发者应确认以下事项：

- [ ] 协议号/字段定义变更 → 已更新 `api/跨平台API接口文档.md`
- [ ] 新增 public 方法 → 已更新对应 `doc/接口文档.txt`
- [ ] 删除/重命名方法 → 已更新对应文档并标注废弃
- [ ] 参数变更 → 已更新文档中的参数表
- [ ] 返回值变更 → 已更新文档中的返回值示例
- [ ] 构建流程变更 → 已更新开发指南中的构建命令
- [ ] 文档版本号和日期已更新

## 一、执行摘要

### 1.1 审计目标

本次审计对 MT3 项目全部源代码执行系统性模块化深度分析，并基于分析结果对 `docs/` 文件夹及所有子目录中的文档体系进行全面审计与优化。具体包括：

1. 验证架构设计文档与实际代码实现的一致性
2. 核对核心模块说明文档与代码功能的匹配度
3. 确保 API 参考文档中的接口定义、参数说明、返回值格式与代码实现完全一致
4. 更新开发指南以反映当前代码库的最佳实践和工作流

### 1.2 审计范围

| 审计维度 | 覆盖范围 |
|----------|----------|
| **源码分析** | `client/`、`engine/`、`cocos2d-2.0-rc2-x-2.0.1/`、`common/`、`server/`、`tools/` |
| **文档审计** | `docs/` 全部子目录，含 `api/`、`architecture/`、`audit/`、`generated/` |
| **协议验证** | `ProtoDef/rpcgen/` 全部 `.inc` 协议定义文件 |
| **构建验证** | `Build-MT3-Exe-Canonical.ps1`、`Build-MT3-v120.ps1`、`build.xml` |

### 1.3 关键发现

| 指标 | 数值 |
|------|------|
| **已验证文档数** | 30+ |
| **发现差异总数** | 21 |
| **P0-严重差异** | 7（API协议号与字段定义错误 + spirit_server参数缺失） |
| **P1-重要差异** | 12（文档版本/日期滞后 + 缺失接口文档） |
| **P2-一般差异** | 2（功能规格书索引引用过期 + 接口名称错误） |

| **已确认一致** | 架构报告、功能规格书、构建指南、跨平台对比 |

### 1.4 总体结论

**架构设计文档**（`19-项目架构分析报告.md`）与代码实现高度一致，四层架构模型、启动链、模块结构、服务端架构等核心描述均通过源码验证。

**API参考文档**（`跨平台API接口文档.md`）存在严重偏差：3个核心协议的协议号与字段定义均与实际代码不符，**已全部修正**。

**服务器端文档**（`zone_server/doc/接口文档.txt`、`spirit_server/doc/说明文档.txt`）存在8个缺失接口和2处参数/返回值错误，**已全部修正**。

**功能规格书**与**开发指南**整体准确，仅存在版本日期滞后问题。

## 十五、文档更新与代码变更同步机制

### 15.1 同步机制设计

```yaml
机制名称: 文档-代码双向同步机制 (Doc-Code Bidirectional Sync)
触发条件:
  - 代码变更: 任何涉及公开API、协议定义、配置项的代码修改
  - 文档变更: 任何文档内容更新
  - 定期审计: 每季度一次全量对齐审计

同步流程:
  代码变更 → 自动检测影响范围 → 标记需更新文档 → 文档更新 → 审计验证
  文档变更 → 记录变更日志 → 通知相关开发者 → 代码验证（如涉及）

工具支持:
  - 协议号自动比对: grep PROTOCOL_TYPE 批量提取 + diff 比对
  - API接口扫描: 扫描控制器 public function 方法列表
  - 文档版本追踪: 文档头部版本号与日期自动校验
```

### 15.2 具体实施建议

1. **协议号自动校验脚本**：在 CI 流程中增加协议号比对步骤
   ```powershell
   # 提取所有协议号
   grep -r "PROTOCOL_TYPE" ProtoDef/rpcgen/ > protocol_numbers.txt
   # 与文档中的协议号比对
   diff protocol_numbers.txt docs/api/protocol_numbers_doc.txt
   ```

2. **API接口清单自动生成**：扫描控制器代码生成接口清单
   ```php
   // 扫描所有 public function（排除 __construct）
   grep -r "public function" controllers/ | grep -v "__construct"
   ```

3. **文档版本号统一管理**：所有文档头部统一格式
   ```yaml
   > **文档版本**: vX.Y.Z
   > **更新日期**: YYYY-MM-DD
   > **对应代码版本**: 基于 commit hash 或 tag
   ```

4. **定期审计周期**：每季度执行一次全量文档-代码对齐审计

#### 3. 发现的主干偏差

##### 3.1 Windows 构建入口口径漂移

旧口径：

- 多处基线文档仍把 `client/Build-MT3-v120.ps1` 写成对外主入口。

当前事实：

- 对外固定入口应为 `tools/scripts/Build-MT3-Exe-Canonical.ps1`
- `client/Build-MT3-v120.ps1` 是内部 ABI 安全链路

##### 3.2 Win32 构建顺序缺项

旧口径：

- 多处文档把主线构建顺序写成 10 步，漏掉 `libCocosDenshion`

当前事实：

- 正确主线顺序为 11 项：
  `platform -> ljfm -> lua -> cauthc -> Box2D -> liblua -> libcocos2d -> libCocosDenshion -> engine -> FireClient -> MT3`

##### 3.3 Android 包路径与权限口径失真

旧口径：

- `GameSDK` 被写成 `com.locojoy.mini.mt3.GameSDK`
- 权限口径被统一写成“28 项”

当前事实：

- `GameSDK` / `SDKShare` 实际在 `com.locojoy.sdk`
- `LocojoyProject` 为 21 项唯一权限
- `LocojoyProject64` / `JoysdkProject` / `YijieProject` 为 29 项唯一权限

##### 3.4 iOS 架构层级和配置数量失真

旧口径：

- iOS 被写成“五层独立核心架构”
- iOS 包管理被写成 `CocoaPods`
- 渠道配置被写成 13 个 plist

当前事实：

- iOS 仍是共享四层核心，Objective-C 只是平台桥接层
- 当前验证到的是 Xcode 工程与嵌入 framework，不是 CocoaPods 主线
- 仓库内实际存在 17 个 `FireClient*.plist`

##### 3.5 跨平台功能对比存在反向失真

旧口径：

- 把 Android WebView 写成缺失
- 把 Android 屏幕录制写成具备

当前事实：

- Android `GameApp` 明确实现公告 WebView 能力
- iOS ReplayKit 代码清晰；Android 当前更明确的是语音录制，而非屏幕录制
