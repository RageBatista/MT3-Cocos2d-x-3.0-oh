# MT3 Codex 全链路治理实施报告

> 日期：2026-07-12
> 范围：`.codex/`、`.agents/skills/`、`.claude/config/`、`.claude/workflows/`、治理脚本与 GitHub Actions

## 1. 结论

本轮已按“立即处理 → P1 运行面收敛 → 工作流与审计重构 → 效率优化”四批完成治理。Codex 原生运行配置、Agent、技能、声明式工作流、Claude 兼容层和 CI 现在使用同一组项目事实与失败语义。

最终治理基线：

- 13 个 Agent 配置均由 `.codex/config.toml` 相对路径加载并继承会话模型。
- 16 个 repo-local skills 通过官方 `quick_validate.py`，技能审计 0 error / 0 warning。
- 13 条 workflow graph、127 个节点全部通过 Schema、连通性、边和跨文件引用校验。
- Execpolicy 25 个用例、PreToolUse 80 个用例、技能脚本 33 个 fixture、治理回归 11 个用例全部通过。
- Strict quality gate：`.codex` 26/26、`.claude` 162/162、`.agents` 68/68。
- Lua/Android/Win32 三个长技能正文由 36,893 bytes 降至 15,785 bytes，减少 57.2%。
- `.codex/**`、`.claude/config/**/*.json`、`.claude/hooks/hooks.json` 和技能治理文本不再依赖 Git LFS 指针。

## 3. 当前配置链路

```text
工程实物 / AGENTS / RULES / BUILD_GUIDE
                    |
                    v
.codex/config.toml + rules + hooks + agents      (Codex 原生运行面)
                    |
                    v
project-map + schemas + workflow-catalog         (声明式治理事实)
                    |
                    v
claude-bridge + router + manifests + workflows   (兼容/人工视图)
                    |
                    v
sidecar / skills / guardrails / quality audits   (动态验证)
                    |
                    v
GitHub Actions fail-closed gate
```

失败语义统一为：证据满足才 PASS；外部条件或继承漂移为 WARN/BLOCKED/EXTERNAL_REQUIRED；配置不可解析、图断边、必需输入缺失或关键 LFS pointer 为 FAIL。

## 5. 保留的真实边界

以下不是未修复缺陷，而是项目层无法伪装消除的环境事实：

1. 本机合并 MCP 为 configured=23、enabled=17、project-default=1、继承差集=16。差集记录为 WARN，项目 manifest 不声称能关闭用户/系统/managed 配置。
2. `tools/CEGUI-0.7.1`、`tools/engine/SpriteEditor`、部分资源打包脚本/目录可能只存在于运行时工作区；clean checkout 缺失时工作流返回 BLOCKED/EXTERNAL_REQUIRED。
3. iOS 构建需要 macOS/Xcode；Windows 只能执行静态入口检查。
4. 项目 hook 定义变更后需要用户在 `/hooks` 复审并信任新哈希。
5. 本轮是治理配置变更，未替代 Win32、Android、Server 或 iOS 的完整交付构建；对应工作流仍要求真实工具链和产物证据。

## 6. 回滚与维护

- 各批采用独立小提交，可按配置阻塞、技能/守卫、工作流/审计、效率优化分别回滚。
- 新增 Agent/skill/workflow 时必须同步 Schema、bridge/manifest、审计测试和 CI。
- 新增外部或 runtime-local 路径时必须声明 availability，禁止通过忽略缺失来换取 PASS。
- 运行态数字、Codex CLI/官方 validator 版本和 MCP 差集应由 CI/本机命令重新取证，不在长期文档中推断。
