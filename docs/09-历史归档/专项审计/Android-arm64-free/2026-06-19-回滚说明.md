# Android arm64 free 回滚说明（2026-06-19）

> **适用范围**：`client/android/LocojoyProject` / `free` 渠道 / `arm64-only`  
> **对象**：`mt3-release.apk` 候选包及其对应文档封板  
> **目的**：当候选包在安装、启动、登录、入世界或热更新链路出现不可接受问题时，提供统一回滚动作

---

## 1. 回滚目标

本说明定义两层回滚：

1. **产物回滚**
   - 停止分发当前 arm64 候选 APK
   - 恢复上一版已验证、已对外发布或已内部准入的 APK

2. **文档/基线回滚**
   - 保留本轮归档文档不删除
   - 将“当前有效发布基线”切回上一版发布清单与哈希冻结文件

说明：

- 本轮文档封板不会删除历史基线；
- 回滚动作应优先回滚“当前使用中的产物与分发指向”，而不是先删档案。

---

## 2. 回滚触发条件

出现以下任一项，应触发产物回滚评估：

### 2.1 安装级

- APK 无法安装
- 签名冲突无法覆盖升级
- 安装后 `dumpsys package` 不再显示 `primaryCpuAbi=arm64-v8a`

### 2.2 启动级

- `GameApp` 无法拉起
- 启动即崩溃
- logcat 出现：
  - `FATAL EXCEPTION`
  - `SIGSEGV`
  - `UnsatisfiedLinkError`
  - `No implementation found`

### 2.3 登录/入世界级

- 登录后卡死在选服、选角或加载流程
- 再次出现：
  - `ProcessKeyExchange identity empty`
  - `服务器断开连接`
- 无法稳定进入主场景

### 2.4 发布链路级

- 正式签名后出现与开发签名验证结论不一致的问题
- 渠道分发、升级覆盖、渠道 SDK 回调出现阻断

---

## 3. 不触发本轮产物回滚的情况

以下现象默认**不单独触发 APK 回滚**，而是先记录并转专项处理：

1. MuMu 测试环境内 `adbd` 未监听 `5555`
   - 这是模拟器环境故障，不是 APK 产物故障

2. 日志出现：

```text
java.net.ConnectException: failed to connect to /193.112.65.157 (port 21)
```

前提是同时满足：

- `GameApplication::OnInit final success`
- 已能进入游戏场景
- 没有崩溃级错误

这类问题归入 FTP / 热更新专项，不直接作为本轮 APK 回滚条件。

---

## 4. 产物回滚步骤

### 4.1 停止继续分发当前候选包

执行人：

- 发布负责人 / 渠道负责人 / 包管理负责人

动作：

1. 停止继续向测试组、渠道组或发布仓推送当前候选 APK；
2. 从“当前待发目录 / 当前待测目录 / 当前渠道投放目录”中移除本候选 APK；
3. 恢复上一版已验证 APK 的分发指向。

### 4.2 恢复上一版 APK

恢复原则：

- 以“上一版已验证发布基线清单”中的 APK 哈希为准；
- 不使用“看起来差不多”的本地副本替代；
- 不允许手工重签当前候选包冒充上一版。

### 4.3 回退测试设备

在测试设备 / MuMu 上执行：

```powershell
$rollbackApk = "ROLLBACK_APK"
adb uninstall com.locojoy.mini.mt3.locojoy
adb install -r $rollbackApk
```

若是正式签名升级回退场景，应按实际签名兼容策略决定：

- 可覆盖安装
- 或先卸载再安装

## 5. 文档/基线回滚步骤

### 5.1 保留档案，不删文档

本轮新增文档：

- `2026-06-19-最终发布说明.md`（已吸收发布基线、交付和源码级封板清单）
- `2026-06-19-发布基线哈希冻结.sha256.txt`
- `2026-06-19-APK重编与MuMu全链路验证.md`
- `2026-06-19-回滚说明.md`

这些文档**属于历史档案**，回滚时不删除。

### 5.2 恢复“当前有效基线”指向

需要修改或替换的不是档案文件本身，而是：

- 当前版发布清单中的“当前有效基线链接”
- 发布负责人正在使用的发布批注
- 实际投放的 APK 文件和哈希清单

---

## 6. 回滚后验证

回滚完成后至少执行以下验证：

### 6.1 静态验证

- APK 哈希与上一版基线一致；
- 包名 / versionCode / versionName 与上一版档案一致；
- ABI 与上一版发布策略一致。

### 6.2 运行验证

至少验证：

1. 能安装；
2. 能启动；
3. 能进入登录页；
4. 能完成登录/选服/入世界；
5. logcat 无崩溃级错误。

---

## 7. 与源码回滚的关系

本轮回滚说明优先针对：

- **APK 产物**
- **发布基线**
- **发布文档指向**

不直接等同于“源码 git 回滚”。

原因：

- 当前 Android 相关工作树仍存在大量未提交 Native / 资源 / 构建改动；
- 因此源码层回滚必须由后续源码封板提交来承接；
- 不应把“只回退 docs commit”误当成 APK 运行时回滚。

若需要做源码级回滚，应在后续代码封板完成后，以对应 commit / tag 为准。

## 9. 结论

本轮回滚策略的核心原则是：

> **先回退“正在分发和正在使用的 APK / 基线指向”，后处理源码与专项问题；历史档案保留，不做覆盖式修改。**
