## 4. 阻断修正记录

### 表 B-1: C1083 根因与修正

| 项 | 内容 |
|---|---|
| 现象 | `test_corona.cpp(7): fatal error C1083`，无法打开 `cegui/include/ImageCodecModules/CoronaImageCodec/CEGUICoronaImageCodec.h` |
| 根因 | `tools\CEGUI-0.7.1\cegui\include` 与 `tools\CEGUI-0.7.1\dependencies\include` 不存在；真实头文件在仓库根 `dependencies\cegui\CEGUI\include` |
| 修改 1 | `test_corona.cpp` include 改为 `ImageCodecModules/CoronaImageCodec/CEGUICoronaImageCodec.h` |
| 修改 2 | `test_corona.vcxproj` Debug/Release IncludePath 改为 `..\..\dependencies\cegui\CEGUI\include` 与 `..\..\common\platform` |
| 验证 | 路径门禁通过，后续 Debug/Release 构建不再出现 C1083 |

### 表 B-2: C2259 根因与修正

| 项 | 内容 |
|---|---|
| 现象 | C1083 解除后，`new CEGUI::CoronaImageCodec()` 报 C2259，不能实例化抽象类 |
| 根因 | `CEGUIImageCodec.h:107` 的纯虚函数为 `load(..., bool bSyn=true)`；Corona 旧头文件只有两个参数，未覆盖纯虚函数 |
| ABI 证据 | 现有 `CEGUICoronaImageCodec(_d).lib/.dll` 导出的 `load` 符号包含 `_N`，即 bool 参数 |
| 修改 1 | `CEGUICoronaImageCodec.h` 声明改为 `Texture* load(const RawDataContainer& data, Texture* result, bool bSyn=true);` |
| 修改 2 | `CEGUICoronaImageCodec.cpp` 实现增加 `bool bSyn`，并传入 `result->loadFromMemory(..., bSyn)` |
| 验证 | 后续 Debug/Release 构建退出码均为 0 |

说明：`CoronaImageCodec` 构造函数 public 只是访问条件；旧文档将其直接写成“可实例化”不完整，因为纯虚函数未覆盖时类仍是抽象类。

## 9. 后续建议

1. 若目标是运行通过，需要补齐同版本 `CEGUIBase_d.dll` / `CEGUIBase.dll` 的可信来源，并明确是否应纳入 `tools\CEGUI-0.7.1\bin`。
2. Debug 运行还需要 VS2013 Debug CRT（`MSVCP120D.dll` / `MSVCR120D.dll`），通常只应在开发机环境中满足，不建议作为发布产物随意分发。
3. 可在 `test_corona.vcxproj` 中补 `_CRT_SECURE_NO_WARNINGS` / `_SCL_SECURE_NO_WARNINGS`、禁用 4267/4251/4244、启用 SDLCheck；这属于规范对齐，不是当前编译阻断。
4. 可把 `test_corona.cpp` 的裸指针改为 RAII，并补充运行依赖说明；这属于测试代码质量改进。
