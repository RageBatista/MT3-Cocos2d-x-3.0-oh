- Visual Studio 2013

- `dsound.lib`
- `strmbase.lib`
- `libogg_static*.lib`

- 打开 `tools/engine/SpriteEditor/SpriteEditor.vcxproj`
- 选择 `Release|Win32` 或 `Debug|Win32`
- 确认工具集为 `v120`

## 3. 首次运行

### 3.1 工作目录认知

该工具强依赖项目资源树与 PFS 路径约定，推荐从资源环境下启动，使 `.ani`、图片与 PFS 路径解析保持一致。

### 3.2 启动行为

应用启动时会：

- 创建日志目录
- 读取注册表中的布局配置
- 恢复主窗口大小和 splitter 比例
- 初始化主视图运行时

---

## 4. 常见使用流程

### 4.1 打开 `.ani`

方式一：菜单或按钮打开。  
方式二：拖拽 `.ani` 到窗口，见 [OnDropFiles](file:///e:/MT3/tools/engine/SpriteEditor/MainFrm.cpp#L54-L131)。

拖拽注意：

- 只支持 `.ani`
- 更适合拖入 `client\resource\res` 下资源
- 若路径无法映射为 PFS，会提示失败

### 4.2 预览与编辑

- 主视图通过定时器持续渲染
- 右侧面板控制帧、方向、边界框、基点、缩放
- 中下装备面板控制 12 层装备显示与切换
- 左侧面板负责模型/动作打开、切换与管理

### 4.3 PNG 导出

使用当前菜单命令导出：

- 标准分辨率
- HD x2
- HD x4

导出结果默认包含：

- PNG 序列帧
- metadata 文件
- 失败项统计

### 4.4 手动打包

适用于将目录下图片序列打成 `.ani`：

- 选择源目录
- 设置输出目标和参数
- 调用打包核心生成图集和新 ANI

### 4.5 使用 `pack.ini` 批量打包

当目录下存在 `pack.ini` 时：

- 触发 `OnToolPack()`
- 询问是否按 INI 批量执行
- 每个 section 代表一组打包任务

当前示例配置位于 [pack.ini](file:///e:/MT3/tools/engine/SpriteEditor/pack.ini)。

## 6. 常见问题

### 6.1 无法编译

优先检查：

- 是否误用非 v120 工具集
- 是否缺失 DirectX SDK
- 是否缺失 Win32/MFC 组件
- `DXSDK_DIR` 是否可用

### 6.2 启动即异常或黑屏

优先检查：

- Direct3D 9 运行环境
- 显卡驱动
- 工作目录与资源路径
- 渲染初始化是否成功

### 6.3 拖拽 `.ani` 无法打开

可能原因：

- 文件不在资源目录映射范围内
- Native 路径无法转为 PFS 路径
- PFS 中资源实际不存在

### 6.4 PNG 导出失败

可能原因：

- 当前不是已加载完成的 `.ani` 图片模式
- 导出目录不可写
- 输出尺寸或内存计算超过限制

### 6.5 `pack.ini` 无效

优先检查：

- section 是否存在
- 键名是否拼写正确
- 路径是否可访问
- 输出目录是否可写

## 7. 使用建议

- 日常编辑以 GUI 为主，批量任务优先走 `pack.ini`
- 修改打包与导出功能时，先阅读 `SpritePackCoreService` 和 `PngExporter`
- 如需修复 UI 或交互问题，优先从 `SpriteEditorView.cpp` 与 `MainFrm.cpp` 取证
- 如需确认是否已真正接入主线，不以历史报告为准，直接以当前源码为准
