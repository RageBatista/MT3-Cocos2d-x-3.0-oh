## 模块职责

| 模块 | 主职责 | 备注 |
|------|--------|------|
| `CSpriteEditorApp` | 启动、命令行、文档模板 | 入口层职责清晰 |
| `CMainFrame` | 三栏布局、拖拽、快捷键、布局持久化 | 壳层边界清晰 |
| `CSpriteEditorDoc` | 资源状态、保存、导出、打包、配置桥接 | 当前最大职责中心 |
| `CSpriteEditorView` | 渲染、输入、可视化编辑 | 渲染与交互仍耦合 |
| `SpritePackCoreService` | 图集装箱与 ANI 重写 | 单一职责较强 |
| `PngExporter` | PNG 导出、缩放、结果汇总 | 边界保护较完整 |

## 当前技术债

- `CSpriteEditorDoc.cpp` 职责过多，导出/打包/配置桥接尚未拆分
- `SpriteEditorView.cpp` 同时承载渲染、交互和表单辅助逻辑
- `DirtyFlags` 与 legacy bool 并存，唯一脏状态源尚未确立
- `CommandManager` 已接入，但只覆盖部分编辑路径
- `EquipmentLayer` 已存在，但主线仍围绕 `m_CurEquips`
- 部分错误处理仍依赖消息框，不利于自动化与非 GUI 调用
