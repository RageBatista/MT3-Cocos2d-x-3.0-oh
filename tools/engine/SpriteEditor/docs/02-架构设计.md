# SpriteEditor 架构设计

> **校对基线**: 当前源码实现  
> **校对日期**: 2026-04-23

---

## 1. 总体架构

SpriteEditor 使用 **MFC SDI + Nuclear 引擎桥接 + 工具侧算法服务** 的组合架构。

```text
CSpriteEditorApp
  └─ CMainFrame
      ├─ CAnimationOpView      左侧：模型/动作/列表/音量频率
      ├─ CSpriteEditorView     中上：主渲染与交互
      ├─ CEquipSelectView      中下：12 层装备 UI
      └─ CActionControlView    右侧：帧、方向、边界框、时间、缩放
                │
                ▼
           CSpriteEditorDoc
      ├─ 引擎桥接接口（Renderer/Sprite/Ani/FileIO/Config/Title）
      ├─ 模型/动作/动画/装备/显示状态
      ├─ 打包/导出/保存/兼容转换
      └─ CommandManager / DirtyFlags / ConfigBridge
                │
                ├─ SpritePackCoreService
                ├─ PngExporter
                ├─ OldAniPack
                ├─ HelpDialogs
                └─ 各类 MFC 对话框
```

### 2.1 应用初始化

- 第一层 `m_wndSplitter`：1 行 3 列
- 第二层 `m_wndSplitter2`：在中列做 2 行 1 列嵌套分割

形成布局：

```text

中列上: CSpriteEditorView
中列下: CEquipSelectView
右列:  CActionControlView
```

## 4. 视图层职责划分

### 4.1 CSpriteEditorView

主职责：

- 定时渲染
- 鼠标选择、拖拽、缩放、方向切换
- 边界框/基点/轨迹叠加绘制
- 运行时初始化与视口同步

关键链路：

- [OnInitialUpdate](file:///e:/MT3/tools/engine/SpriteEditor/SpriteEditorView.cpp#L2757-L2762) 设置定时器
- [OnTimer](file:///e:/MT3/tools/engine/SpriteEditor/SpriteEditorView.cpp#L2746-L2755) 每 tick 调用 `Render()`
- [Render](file:///e:/MT3/tools/engine/SpriteEditor/SpriteEditorView.cpp#L3380-L4348) 完成主渲染
- [TryBeginTrajectoryControlDrag](file:///e:/MT3/tools/engine/SpriteEditor/SpriteEditorView.cpp#L1163-L1193) / [UpdateTrajectoryControlDrag](file:///e:/MT3/tools/engine/SpriteEditor/SpriteEditorView.cpp#L1195-L1230) 处理轨迹控制点拖拽

### 4.2 CAnimationOpView

主职责：

- 模型与动作列表同步
- 打开/新建/删除/重命名动作
- 音量与频率控制
- 与文档状态联动更新列表缓存

### 4.3 CEquipSelectView

当前实现已采用 **统一消息分发**，不再是 72 个分散处理函数主导。

关键处理器：

- `OnEquipLayerCheckChanged`
- `OnEquipLayerNew`
- `OnEquipLayerReload`
- `OnEquipLayerDelete`
- `OnEquipLayerColorChange`
- `OnEquipLayerComboChanged`

消息映射位于 [SpriteEditorView.cpp](file:///e:/MT3/tools/engine/SpriteEditor/SpriteEditorView.cpp#L3102-L3159)。

### 4.4 CActionControlView

主职责：

- 调整播放方向、帧序、缩放、边界框、基点、时间
- 将部分编辑操作包装进 `ExecuteCommand()`
- 驱动帧序、方向、层级顺序等更新

## 5. 算法模块

### 5.1 SpritePackCoreService

[SpritePackCoreService](file:///e:/MT3/tools/engine/SpriteEditor/SpritePackCoreService.cpp#L181-L575) 是打包核心。

#### 处理阶段

1. `RectPacking()`：将碎图放入若干 bin
2. `GetBigPicSize()`：计算各 bin 图集尺寸
3. `PicArrange()`：绘制图集并保存纹理文件
4. `WriteConvertedAni()`：重写 `.ani` 数据引用到新图集

#### 核心算法

- 采用 MaxRects 风格的空闲矩形装箱
- `TryPlacePicInBin()` 以短边剩余量 / 长边剩余量为评分
- `SplitFreeRects()` 对已使用矩形切分空闲区域
- `PruneContainedFreeRects()` 消除被包含的冗余空闲块

这套实现比简单逐行排布更节省图集空间，但仍是工具侧离线算法，不依赖客户端运行时。

### 5.2 PngExporter

[PngExporter](file:///e:/MT3/tools/engine/SpriteEditor/PngExporter.cpp) 用于将 `.ani` 的帧数据反向导出为 PNG 序列。

关键特性：

- 导出方向表构建：`BuildExportDirections()`
- 尺寸/内存保护：`TryComputeImageLayoutA8R8G8B8()`
- 高质量缩放：`ResizeBufferHighQualityA8R8G8B8()`
- Alpha 边缘抗锯齿：`ApplyAlphaEdgeAntialiasA8R8G8B8()`
- 输出 metadata 与帧级错误收集

### 5.3 OldAniPack

负责旧 ANI 数据兼容读取，为重新打包和格式转换提供输入。

## 6. 横向支撑模块

### 6.1 CommandManager

[CommandManager](file:///e:/MT3/tools/engine/SpriteEditor/CommandManager.h) 提供：

- `Execute`
- `Undo`
- `Redo`
- merge 机制
- 历史长度裁剪
- saved position 跟踪

当前接入点主要集中在：

- 边界框应用到所有方向
- 帧时间调整
- 层级顺序调整
- 装备可见性/切换相关操作

### 6.2 DirtyFlags

[DirtyFlags](file:///e:/MT3/tools/engine/SpriteEditor/DirtyFlags.h) 将脏状态分为：

- 文档类：`Document/Maze/MazeSize/Animation`
- 显示类：`PixelList/Unwrap/Background/...`
- 装备层类：12 个 layer bit
- 渲染类：`Transform/Color/Texture/Geometry`

但当前工程仍保留部分 legacy bool 标志，因此这是“过渡中架构”，不是完全替代完成态。

### 6.3 ConfigBridge

[CSpriteEditorDoc](file:///e:/MT3/tools/engine/SpriteEditor/SpriteEditorDoc.h#L331-L348) 维护 `ConfigBridgeTableInfo`、`RefreshConfigBridge()`、`BuildConfigBridgeSummary()`，说明编辑器已具备一层与配置表资源的桥接检查能力。

## 7. 主要业务流程

### 7.1 打开动画流程

```text
用户打开/拖拽 .ani
  → CSpriteEditorDoc::OpenAnimationFile()
  → FileIO / AniManager / SpriteManager 加载资源
  → 当前模型/动作/动画状态刷新
  → UpdateControlView()
  → CSpriteEditorView::Render()
```

### 7.2 PNG 导出流程

```text
菜单命令
  → OnExportPngSequence / Hd2 / Hd4
  → ExportPngSequenceWithScale()
  → 构建输出目录
  → PngExporter::ExportAni()
  → 逐方向/逐帧/逐 region 导出 PNG 与 metadata
```

### 7.3 手动打包流程

```text
菜单命令 OnPack()
  → 选择源目录
  → 收集图像文件
  → 读取/推导打包参数
  → SpritePackCoreService::BuildAtlas()
  → WriteConvertedAni()
```

### 7.4 pack.ini 批处理流程

```text
OnToolPack()
  → 检查 pack.ini
  → 询问是否使用批处理
  → PackFromIni()
  → 读取 section 与 key
  → 对每项调用 PackByDir()
  → 汇总成功/失败结果
```

## 8. 架构结论

当前 SpriteEditor 的架构特点是：

- **主干稳定**：MFC 文档/视图 + 文档集中调度仍清晰可维护
- **工具能力集中**：打包、导出、兼容转换都汇聚于工具侧文档类与算法服务
- **演进未完全收敛**：新命令系统、脏标志系统和装备层抽象已接入，但仍有过渡痕迹
- **适合继续增量治理**：最优策略是围绕 `CSpriteEditorDoc`、`CSpriteEditorView`、`SpritePackCoreService` 做分阶段重构，而不是推翻式改造
