## 2. electron-vite 配置

### 2.1 配置文件

[`electron.vite.config.ts`](../electron.vite.config.ts)（57 行）定义三个构建目标：

```typescript
export default defineConfig({
  main: { ... },      // 主进程
  preload: { ... },   // Preload 桥接层
  renderer: { ... },  // 渲染进程（React SPA）
});
```

### 2.2 主进程构建 (`main`)

```typescript
main: {
  plugins: [externalizeDepsPlugin()],  // 外部化所有依赖（不打包进 bundle）
  resolve: {
    alias: { '@shared': resolve(__dirname, 'src/shared') },
  },
  build: {
    outDir: 'dist/main',
    rollupOptions: {
      input: { index: resolve(__dirname, 'src/main/index.ts') },
    },
  },
}
```

**特点**：
- `externalizeDepsPlugin()`：所有 `dependencies` 和 `devDependencies` 都不打包，运行时从 `node_modules` 加载
- 这是必须的，因为 `sharp` 等原生模块无法被 Rollup 打包
- 输出：`dist/main/index.js`

### 2.3 Preload 构建 (`preload`)

```typescript
preload: {
  plugins: [externalizeDepsPlugin()],
  resolve: {
    alias: { '@shared': resolve(__dirname, 'src/shared') },
  },
  build: {
    outDir: 'dist/preload',
    rollupOptions: {
      input: { index: resolve(__dirname, 'src/preload/index.ts') },
    },
  },
}
```

**特点**：
- 同样外部化所有依赖
- 输出：`dist/preload/index.js`
- 通过 `contextBridge` 运行在隔离环境中

### 2.4 渲染进程构建 (`renderer`)

```typescript
renderer: {
  plugins: [react()],                  // @vitejs/plugin-react（JSX 转换 + HMR）
  root: resolve(__dirname, 'src/renderer'),
  resolve: {
    alias: {
      '@shared': resolve(__dirname, 'src/shared'),
      '@renderer': resolve(__dirname, 'src/renderer'),
    },
  },
  build: {
    outDir: resolve(__dirname, 'dist/renderer'),
    rollupOptions: {
      input: { index: resolve(__dirname, 'src/renderer/index.html') },
    },
  },
}
```

**特点**：
- 使用 `@vitejs/plugin-react` 支持 JSX 和 Fast Refresh
- 两个路径别名：`@shared` → `src/shared`，`@renderer` → `src/renderer`
- 以 `index.html` 为入口的 SPA 构建
- 输出：`dist/renderer/`

### 2.5 路径别名

| 别名 | 指向 | 可用范围 |
|------|------|---------|
| `@shared` | `src/shared` | main + preload + renderer |
| `@renderer` | `src/renderer` | renderer only |

## 4. 开发模式

### 4.1 启动开发环境

```bash
cd tools/LnFEditor
npm install
npm run dev
```

`electron-vite dev` 会：

1. 启动 Vite dev server（渲染进程 HMR）
2. 编译主进程和 preload
3. 启动 Electron，加载渲染进程

### 4.2 开发模式下的渲染进程加载

[`index.ts`](../src/main/index.ts:25) 中：

```typescript
if (process.env.ELECTRON_RENDERER_URL) {
  mainWindow.loadURL(process.env.ELECTRON_RENDERER_URL);  // 开发模式：Vite dev server
} else {
  mainWindow.loadFile(path.join(__dirname, '../renderer/index.html'));  // 生产模式：静态文件
}
```

## 5. 生产构建

### 5.1 构建流程

```bash
npm run build
```

等价于 `electron-vite build`，执行三个并行构建：

```
electron-vite build
  │
  ├── main → dist/main/index.js        (SSR bundle, externalized deps)
  ├── preload → dist/preload/index.js   (SSR bundle, externalized deps)
  └── renderer → dist/renderer/         (React SPA, fully bundled)
                  ├── index.html
                  ├── assets/
                  │   ├── index-[hash].js
                  │   └── index-[hash].css
                  └── ...
```

### 5.2 构建产物结构

```
dist/
├── main/
│   └── index.js           # 主进程入口
├── preload/
│   └── index.js           # Preload 脚本
└── renderer/
    ├── index.html          # HTML 入口
    └── assets/             # JS/CSS/静态资源
```

## 6. electron-builder 打包

### 6.1 打包配置

[`package.json`](../package.json) 中的 `build` 字段（[行 44–93](../package.json:44)）：

```json
{
  "build": {
    "appId": "com.mt3.lnf-editor",
    "productName": "LnF Editor",
    "directories": { "output": "release" },
    "files": ["dist/**/*"],
    "win": {
      "target": [
        { "target": "nsis", "arch": ["x64"] },
        { "target": "portable", "arch": ["x64"] }
      ]
    },
    "nsis": {
      "oneClick": false,
      "allowToChangeInstallationDirectory": true,
      "createDesktopShortcut": true,
      "createStartMenuShortcut": true,
      "shortcutName": "LnF Editor"
    },
    "portable": {
      "artifactName": "LnF-Editor-${version}-Portable.${ext}"
    },
    "asar": true,
    "asarUnpack": [
      "**/*.node",
      "node_modules/sharp/**/*"
    ],
    "fileAssociations": [
      {
        "ext": "looknfeel",
        "name": "CEGUI LookNFeel",
        "description": "CEGUI LookNFeel File",
        "role": "Editor"
      }
    ]
  }
}
```

### 6.2 打包目标

| 目标 | 格式 | 说明 |
|------|------|------|
| NSIS | `.exe` 安装程序 | 支持自定义安装目录、桌面快捷方式、开始菜单 |
| Portable | `.exe` 便携版 | 单文件可执行，无需安装 |

### 6.3 ASAR 打包

- `asar: true`：应用代码打包为 `app.asar`
- `asarUnpack`：以下内容不打包进 ASAR（需要原生加载）：
  - `**/*.node` — 所有原生 Node 模块
  - `node_modules/sharp/**/*` — sharp 图像处理库

### 6.4 文件关联

注册 `.looknfeel` 文件关联：

| 属性 | 值 |
|------|---|
| 扩展名 | `.looknfeel` |
| 名称 | CEGUI LookNFeel |
| 角色 | Editor |

### 6.5 打包命令

```bash
# 完整打包（NSIS + Portable）
npm run package

# 仅打包到目录（快速测试）
npm run package:dir

# 仅便携版
npm run package:portable
```

### 6.6 输出目录

```
release/
├── win-unpacked/                          # 解压后的应用目录
│   ├── LnF Editor.exe
│   ├── resources/
│   │   ├── app.asar                       # 打包后的应用代码
│   │   └── app.asar.unpacked/             # 原生模块（sharp）
│   └── ...
├── LnF Editor Setup 0.1.0.exe            # NSIS 安装程序
└── LnF-Editor-0.1.0-Portable.exe         # 便携版
```

### 7.3 sharp 原生模块注意事项

`sharp` 是原生 Node.js 模块，需要特殊处理：

1. **构建时**：`externalizeDepsPlugin()` 不将其打包进 bundle
2. **打包时**：`asarUnpack` 将其排除在 ASAR 之外
3. **运行时**：从 `app.asar.unpacked/node_modules/sharp/` 加载

## 8. 常见问题

### Q: 构建报错 "sharp module not found"

确保已执行 `npm install`，sharp 的原生二进制会在 install 时下载。

### Q: 开发模式下白屏

检查 `ELECTRON_RENDERER_URL` 环境变量是否正确设置。electron-vite dev 会自动设置此变量。

### Q: 打包后 sharp 无法加载

确认 `asarUnpack` 配置包含 `node_modules/sharp/**/*`。如果仍有问题，检查 `**/*.node` 是否也被排除。
