## 1. 插件系统

### 1.1 架构概述

LnF Editor 内置插件系统，位于 [`plugin-system.ts`](../src/renderer/services/plugin-system.ts)（284 行），提供 5 个扩展点。

```
PluginManager（单例）
  ├── propertyEditors[]    → 自定义属性编辑器
  ├── exporters[]          → 自定义导出格式
  ├── validators[]         → 自定义验证规则
  ├── toolbarActions[]     → 自定义工具栏按钮
  └── renderers[]          → 自定义渲染器
```

全局实例：[`pluginManager`](../src/renderer/services/plugin-system.ts:283)

### 1.5 编写插件示例

```typescript
// my-plugin.ts
import type { Plugin, CustomValidator } from './services/plugin-system';

const MyPlugin: Plugin = {
  manifest: {
    id: 'com.mt3.lnf-plugin-naming',
    name: '命名规范检查',
    version: '1.0.0',
    description: '检查 WidgetLook 命名是否符合项目规范',
    author: 'MT3 Team',
    main: 'my-plugin.ts',
  },

  activate(context) {
    const validator: CustomValidator = {
      name: 'naming-convention',
      validate(widgetLook) {
        const errors = [];
        if (!widgetLook.name.startsWith('MT3/')) {
          errors.push({
            level: 'warning',
            message: `WidgetLook "${widgetLook.name}" should start with "MT3/"`,
          });
        }
        return errors;
      },
    };

    context.registerValidator(validator);
  },

  deactivate() {
    console.log('Plugin deactivated');
  },
};

// 注册
import { pluginManager } from './services/plugin-system';
pluginManager.registerPlugin(MyPlugin);
```

### 4.1 步骤

1. **主进程添加 handler**：在 [`src/main/index.ts`](../src/main/index.ts) 中注册

```typescript
  const params = JSON.parse(paramJson);
  // 执行主进程操作（文件系统、外部命令等）
  return { success: true, data: result };

```

2. **Preload 暴露方法**：在 [`src/preload/index.ts`](../src/preload/index.ts) 的 `api` 对象中添加

```typescript

  // ... 现有方法
  myCustomAction: (paramJson: string) => ipcRenderer.invoke('my-custom-action', paramJson),

```

3. **渲染进程调用**：

```typescript
const result = await window.lnfAPI.myCustomAction(JSON.stringify({ ... }));
```

### 4.2 IPC 设计规范

| 规范 | 说明 |
|------|------|
| 通道命名 | kebab-case（如 `my-custom-action`） |
| Preload 方法 | camelCase（如 `myCustomAction`） |
| 参数传递 | JSON 序列化（复杂对象用 `JSON.stringify`） |
| 返回值 | 始终返回对象（`{ success, data/error }`） |
| 错误处理 | try-catch 包裹，返回 `{ success: false, error }` |

## 8. 开发注意事项

### 8.1 共享类型优先

所有跨进程使用的类型必须定义在 [`src/shared/model/`](../src/shared/model) 中，通过 `@shared` 别名引用。主进程和渲染进程都依赖此目录。

### 8.2 IPC 序列化约束

IPC 传输的数据必须可 JSON 序列化。不可传输：
- `Map` → 转换为 `Record<string, T>` 或 `[key, value][]`
- `Set` → 转换为 `T[]`
- `Function` → 不支持
- `HTMLCanvasElement` → 转换为 Base64 Data URL

### 8.3 渲染进程安全限制

渲染进程不能直接访问：
- `fs`（文件系统）
- `path`（路径操作）
- `sharp`（图像处理）
- `dialog`（系统对话框）

所有这些操作必须通过 `window.lnfAPI` IPC 调用主进程完成。

### 8.4 Store 修改规范

- 使用 Immer 的 `set(state => { ... })` 模式修改状态
- 不要直接修改 store 外部的状态
- 修改 WidgetLook 后必须调用 `updateWidgetLook()` 以触发 dirty 标记
- 需要撤销支持的操作必须在修改前调用 `pushHistory()`
