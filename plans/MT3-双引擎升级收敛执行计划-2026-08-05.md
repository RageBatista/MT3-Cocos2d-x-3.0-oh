# MT3 双引擎升级收敛执行计划

> 日期：2026-08-05  
> 基线：Win32 `cocos2d-x-3.0-oh + CEGUI-0.7.9-r5`；Android/iOS `cocos2d-x-2.2.6`  
> 固定工具链：VS2013/v120/Windows SDK 8.1；NDK r16 clang/Ant/JDK8；服务端 JDK7/8/Ant

## 1. 目标与成功标准

本轮不重复升级已经落地的 Cocos/CEGUI 业务源码，而是收敛升级后的构建、门禁、技能、Codex sidecar 和现行文档，使所有入口基于同一份平台化工程事实工作。

成功标准：

1. Win32 `Upgrade30` 的构建、v120 门禁和分析器使用同一份项目清单；当前工作区本地 D3D9 检查同步消费该清单，但不作为 clean checkout 强制入口。
2. `Check-v120Toolset.ps1` 默认检查 Upgrade30 的 28 个直接构建工程；`Legacy226` 仍可显式检查其 13 个工程。
3. canonical wrapper 与 FullValidation 把 `EngineProfile` 传给工具链门禁。
4. `.agents/skills`、`.codex` sidecar 和现行 Windows 文档准确描述分平台 Cocos/CEGUI 架构。
5. 技能审计、sidecar 审计、v120 门禁、静态构建配置检查和 Win32 canonical 构建形成验证闭环。

## 2. 已确认的升级事实

- Win32 工程的 `EngineProfile=Upgrade30` 路径检查已通过，核心工程不再混入 Cocos 2.2.6 或 CEGUI 0.7.1。
- Cocos 3.0-oh 已通过 CMake 生成 v120 工程；CEGUI 0.7.9-r5、Nuclear、FireClient 和 MT3 已纳入 canonical 顺序。
- Android Locojoy free 仍以 2.2.6、arm64-v8a、NDK r16 clang、Ant 和 JDK8 为平台基线。
- iOS 已迁移到 2.2.6 工程路径，但运行构建只在 macOS/Xcode 执行器验收。
- 生成代码与资源产物继续通过 XML/pkg/资源源定义和 canonical 生成入口更新。

## 3. 当前差距

| 差距 | 影响 | 处理 |
| --- | --- | --- |
| `Check-v120Toolset.ps1` 仍检查旧 2.2.6 Win32 清单 | Upgrade30 可出现“检查通过但对象错误” | 按 `EngineProfile` 读取共享项目清单 |
| 技能预检和 D3D9 测试复制旧清单 | 技能与自动化测试结论失真 | 改为消费共享清单 |
| Win32 分析器靠正则猜构建步骤 | 漏掉 `$cocosBuildRoot` 下 CMake 工程 | 直接读取共享清单 |
| skills/sidecar 仍有 0.7.1 或单一 2.2.6 当前主线表述 | 任务路由到错误引擎目录 | 更新为分平台矩阵 |
| Windows 指南仍记录 12/13 个旧步骤 | 人工构建和审查口径错误 | 更新为 27 个依赖工程 + MT3 |

## 4. 实施步骤与文件

1. 在 `tools/scripts/build-config.psm1` 增加 `Get-MT3Win32ProjectManifest`，集中维护 Upgrade30/Legacy226 项目清单。
2. 修改 `client/Build-MT3-v120.ps1` 使用共享清单，保持原有构建顺序和 `DisableProjectReferences` 行为。
3. 修改 `Check-v120Toolset.ps1`、canonical wrapper、FullValidation、Win32 分析器及其测试；同步当前工作区本地 D3D9 检查并记录其忽略边界。
4. 更新 `windows-v120-build`、任务架构路由和编码守卫技能；保留 `android-r10e-build` 名称作为兼容 ID，但正文继续固定 r16 主线。
5. 更新 `.codex/project-map.json`、schema 和 workflow catalog，补齐 Win32 3.0-oh/CEGUI 0.7.9-r5 路由。
6. 更新 `.claude/BUILD_GUIDE.md`、Windows 指南、依赖矩阵、文档索引和实施记录。
7. 生成升级总结报告，记录变更、验证、遗留问题和回滚方式。

## 5. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 共享清单顺序变化导致链接或 ABI 问题 | 清单严格复制当前 `Build-MT3-v120.ps1` 的顺序；执行 Release SafeChain/canonical 验证 |
| Legacy226 兼容入口被误删 | 为两个 profile 分别保留清单并单独运行 v120 门禁 |
| CMake 生成工程被漏检 | Upgrade30 清单逐项覆盖当前 21 个 `cocos30_*` 工程 |
| JSON sidecar 结构漂移 | 运行 schema、guardrail 和 quality gate 五项治理审计 |
| 文档编码或换行漂移 | 修改前后检查严格 UTF-8、BOM、换行和 `git diff --check` |

## 7. 回滚

- 共享清单异常：回退 `build-config.psm1` 和四个消费者，恢复原内联 `buildSteps`。
- sidecar 路由异常：回退 `.codex` 三个文件，不影响业务源码或构建产物。
- 构建失败：保留首个失败日志，不覆盖现有二进制；从失败前最后可用源码状态重新执行 canonical SafeChain。
