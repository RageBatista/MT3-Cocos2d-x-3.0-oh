# P0 高清化快赢实施方案（1080p/1440p + AA + LUT/锐化/柔和发光 + 更好的水面/夜景）

## 1. 文档信息

| 字段 | 内容 |
|------|------|
| 文档版本 | v1.0 |
| 生成日期 | 2026-03-06 |
| 目标周期 | 2-3 周 |
| 适用范围 | MT3 客户端 Win32 主线，iOS 同步验证，Android 仅保留参数链路可用性 |
| 目标定位 | 在不升级 Cocos2d-x 主版本的前提下，最快拿到肉眼可见的画质提升 |

## 2. 目标与成功标准

### 2.1 目标

1. Win32 内部渲染分辨率提升到 `1920x1080`，并保留 `2560x1440` 实验开关。
2. 补齐 AA 路线：
   - iOS：MSAA 0/2/4 配置化与失败降级。
   - Win32：优先保留原后端，增加 FXAA 兜底；如 ANGLE/EGL 链路可控，再评估 MSAA。
3. 在现有 `CCRenderTexture + ShaderCache` 能力上加一条轻量后处理链：
   - LUT/色调映射
   - 轻锐化
   - 柔和发光
4. 不重写地图系统的前提下，提升夜景和水面观感：
   - 夜景 ColorBalance 稳定生效
   - 水面扭曲/亮度/边缘过渡更自然

### 2.2 成功标准

1. 视觉：1080p 窗口下，文字、UI、人物轮廓、地表纹理相较当前基线有明确清晰度提升。
2. 稳定：0 个阻断级黑屏，0 个新增高频崩溃。
3. 性能：
   - Win32：1080p 模式平均 FPS 回退不超过 12%
   - iOS：开启 2x MSAA 平均 FPS 回退不超过 15%
4. 回滚：关闭新增开关后可回退到当前渲染路径。

## 3. 代码现状结论

### 3.1 当前瓶颈

1. `client/MT3Win32App/main.cpp` 只设置窗口大小，不控制内部渲染分辨率。
2. `client/FireClient/Application/Framework/ResolutionAdapter.cpp` 在 Win32 默认把逻辑分辨率上限收口到 `1200x720` 级别，导致大窗口也无法获得等比清晰度提升。
3. iOS 启动层 `client/FireClient/FireClient/FireClientAppDelegate.mm` 明确关闭了 `multiSampling`。
4. `engine/renderer/nucocos2d_render.cpp` 已经具备 `CCRenderTexture`、HSV、Gray 等 shader 入口，但 `GetAvailableMultiSampleType()` 仍是空壳，说明 AA 能力没有被完整做通。
5. `engine/renderer/nuibaserenderer.h` 暴露的 `XPRENDER_EFFECT` 很少，现有效果主要还是夜景色彩平衡和扭曲，无法直接满足完整后处理链目标。

### 3.2 当前可复用能力

1. `engine/world/nuworld.cpp` 已有夜景 effect 调用和水面渲染区域更新逻辑。
2. `engine/world/nuworld.cpp`、`engine/world/nudistortbase.*`、`engine/world/nudistort.*` 已有扭曲能力，可作为水面增强的基础。
3. `client/FireClient/Application/Framework/GameApplication.cpp` 已有主绘制入口，适合插入全屏后处理链。
4. `client/FireClient/Application/Manager/GameUIManager.cpp` 已有 `XPRenderEffect` 与 UI 裁剪逻辑，适合决定 UI 是否走后处理。

## 5. 实施分期

### Phase A：内部渲染分辨率提升

#### 目标

1. 先让 Win32 真正跑到 `1920x1080` 内部渲染。
2. 保留 `2560x1440` 实验开关，但不作为默认发布值。

#### 改动点

1. 把 `ResolutionAdapter.cpp` 的 Win32 上限从固定值改为配置化：
   - 默认 `1920x1080`
   - 可通过 `frameResolutionSize.txt` 覆盖为 `2560x1440`
2. 区分：
   - 窗口尺寸
   - 内部渲染尺寸
   - UI 逻辑尺寸
3. 在启动日志中回读：
   - `screen_w/h`
   - `logic_w/h`
   - `display_w/h`

#### 验收

1. `1920x1080` 窗口下，日志显示 `logic` 不再落到 `720p` 级别。
2. UI 不发生明显错位，输入区域不漂移。
3. 2D 地图和角色边缘较基线更清晰。

### Phase B：AA 路线

#### 目标

1. iOS 先做真 MSAA。
2. Win32 优先做稳定可交付的 FXAA；只有在 ANGLE/EGL 栈确认安全时才尝试 Win32 MSAA。

#### 改动点

1. iOS：
   - `FireClientAppDelegate.mm` 改为读配置决定 `multiSampling` 与 `numberOfSamples`
   - 保留 `0 -> 2 -> 4` 逐级降级
2. Win32：
   - 先增加后处理 FXAA pass，避免直接触碰高风险 EGL 多采样初始化
   - 如果后续验证可行，再补 Win32 EGL/MSAA 探测
3. `engine/renderer/nucocos2d_render.cpp`：
   - 把 `GetAvailableMultiSampleType()` 从空壳变成显式能力探测或显式声明不支持

#### 验收

1. iOS 2x MSAA 开关可切换，失败自动回退 0。
2. Win32 FXAA 可开关，关闭后完全回到基线。
3. 角色与地图斜线边缘锯齿肉眼可见下降。

### Phase C：LUT / 锐化 / 柔和发光

#### 目标

1. 在不重构渲染后端的前提下，接入一条轻量 post-process chain。

#### 建议顺序

1. Scene Color Copy
2. Soft Glow Threshold + Blur
3. Composite
4. LUT / Tone
5. Sharpen
6. UI Overlay

#### 改动点

1. `nuibaserenderer.h`：
   - 新增 `XPRE_LUT`
   - 新增 `XPRE_SHARPEN`
   - 新增 `XPRE_SOFTGLOW`
2. `nustatemanager.cpp`：
   - 为新增 effect 增加参数快照尺寸
3. `nucocos2d_render.cpp`：
   - 新增全屏 pass
   - 使用 `CCRenderTexture` 做中间 RT
4. `nufxcode.cpp`：
   - 增加 LUT / sharpen / glow shader 字符串
5. `GameApplication.cpp`：
   - 在 `Scene/Battle` 绘制结束后执行后处理，再叠 UI

#### 验收

1. LUT 不改变 UI 文本锐度。
2. Soft Glow 只对高亮区域生效，不造成大面积糊光。
3. Sharpen 默认值保守，不出现过冲和白边。

### Phase D：更好的水面 / 夜景

#### 目标

1. 让夜景不再只是单一色彩压暗。
2. 让水面利用现有扭曲链路做更明显但可控的提升。

#### 改动点

1. 夜景：
   - 保留现有 `ColorBalance/ColorBalance2`
   - 加一层轻 LUT 或夜景专用 tone 参数
   - 不把 UI 一起压暗
2. 水面：
   - 复用 `XPRE_DISTORTION`
   - 提升 alpha mask 过渡与亮度变化
   - 对近景/远景水面分档调参，避免全图统一扭曲
3. 必要时：
   - `SetRenderNightEffectWithRenderTarget(true)` 做实验分支
   - 但默认不直接切到全量 RT 夜景，先保守接入

#### 验收

1. 夜晚外景和地下宫殿都能看到明显但不过分的氛围差异。
2. 水面边缘不抖、不闪、不出现大块错位。
3. 切地图和切场景时不出现 effect 残留。

## 6. 配置与开关

| 开关名 | 默认值 | 作用 |
|------|------|------|
| `InternalRenderPreset` | `1080p` | 内部渲染分辨率档位：`720p/1080p/1440p` |
| `AAMode` | `Win32=FXAA,iOS=2xMSAA` | 抗锯齿策略 |
| `PostFXEnable` | `true` | 全局后处理总开关 |
| `LUTEnable` | `true` | LUT 开关 |
| `SharpenEnable` | `true` | 锐化开关 |
| `SoftGlowEnable` | `true` | 柔和发光开关 |
| `NightQualityEnable` | `true` | 夜景增强开关 |
| `WaterQualityEnable` | `true` | 水面增强开关 |

## 7. 回滚策略

1. 出现黑屏或 RT 链路异常：先关 `PostFXEnable`。
2. 出现边缘异常或性能抖动：Win32 从 FXAA 回退关闭，iOS 从 4x/2x 回退到 0。
3. 出现 UI 颜色异常：先关 `LUTEnable` 与 `SharpenEnable`。
4. 出现地图特定伪影：单独关 `NightQualityEnable` 或 `WaterQualityEnable`。
5. 仍无法稳定：回退 `InternalRenderPreset` 到 `720p`。

## 8. 风险与边界

1. 只改代码无法把低分辨率原始资源变成高清资源；角色、地图、UI 贴图若本身分辨率不足，最终仍要补资源重出。
2. Win32 的真 MSAA 依赖 ANGLE/EGL/老 Cocos2d-x 启动链路，风险高于 FXAA，不能作为第一交付路径。
3. 后处理链一旦放到 UI 前面，容易导致字体发糊；默认应坚持“场景后处理，UI 后叠加”。
4. `1440p` 仅适合作为实验档位，默认发布档应先锁 `1080p`。

## 9. 推荐执行顺序

1. 先做 Phase A，拿到真实 1080p 内部渲染。
2. 再做 Phase B，先交付稳定的 AA。
3. 然后做 Phase C，把肉眼可见的 LUT/锐化/柔和发光接上。
4. 最后做 Phase D，收口夜景和水面。

## 10. 最小交付定义

满足以下 4 条即可视为本轮目标完成：

1. Win32 默认档内部渲染达到 1080p。
2. iOS MSAA 可配，Win32 至少有 FXAA。
3. 场景层已接入 LUT + 轻锐化 + 柔和发光，且 UI 不糊。
4. 夜景和水面均较当前基线有稳定、可复现的视觉提升。
