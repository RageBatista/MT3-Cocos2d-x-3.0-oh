## 1. 实施目标

本清单只解决两类问题：

1. **世界场景地图发虚**
2. **世界地图与地图入口 HUD 的 UI 显示发虚**

按当前任务口径，`xiaoditu_mtg` 小地图逻辑视为正确，不纳入本次改造目标。

实施原则固定如下：

1. **不改 `adapter->get_logic_w/h()` 的旧语义**
2. **先做资源与布局止损，再做场景 render scale**
3. **保持 Lua 窗口名、按钮名、事件绑定路径不变**
4. **优先新增专用资源，不直接污染复用范围大的共享 atlas**

---

## 2. 总体拆分

本次改造拆成两条工作流并行推进：

### 工作流 A：地图 UI 高清化

目标：

- 让 `worldmap.layout` 主图不再因为源图倍率不足或横向扩展而发虚
- 让主场景地图入口 HUD 不再因为共享 atlas 低倍率或 Android 比例锚点扩展而变糊

覆盖文件：

- `client/resource/res/ui/layouts/worldmap.layout`
- `client/android/梦屿西游/assets/unpacked/ui/layouts/worldmap.layout`
- `client/resource/res/ui/layouts/logoinfo.layout`
- `client/android/梦屿西游/assets/unpacked/ui/layouts/logoinfo.layout`
- 新增地图专用高清 imageset

### 工作流 B：场景地图高清化

目标：

- 在不改变玩法逻辑尺寸的前提下，提高世界场景地图 render density
- 把“逻辑尺寸”和“渲染尺寸”拆开，避免战斗坐标、世界 viewport、投影矩阵一起漂移

覆盖文件：

- `client/FireClient/Application/Framework/ResolutionAdapter.h`
- `client/FireClient/Application/Framework/ResolutionAdapter.cpp`
- `engine/engine/nuiadapter.h`
- `engine/engine/nuengine.cpp`
- `engine/engine/nucocos2d_wraper.cpp`
- `engine/renderer/nucocos2d_render.cpp`
- `client/FireClient/Application/Framework/GameApplication.cpp`

## 3. 第一阶段：地图 UI 高清化

### 3.1 世界地图主图改造策略

当前问题：

- PC 主图走 `ccditu image:ccditutupian`
- Android 主图走 `worldmapbg image:bg`
- 两边主图源尺寸都在 `1614 x 533` 量级，高分屏下被统一放大后容易发软
- Android 主图容器还存在 `right.scale = 1` 的横向扩展问题

对应锚点：

- `client/resource/res/ui/layouts/worldmap.layout`
- `client/resource/res/ui/imagesets/ccditu.imageset`
- `client/android/梦屿西游/assets/unpacked/ui/layouts/worldmap.layout`
- `client/android/梦屿西游/assets/unpacked/ui/imagesets/worldmapbg.imageset`

建议做法：

1. **不要直接替换整张 `ccditu` 或 `worldmapbg` 共享 atlas**
2. **单独为“世界地图主图”建立专用高清 imageset**
3. **只改主图控件的 `Image` 属性，不动热点按钮和外框装饰图**

建议新增文件：

- `client/resource/res/ui/imagesets/worldmap_main_hd.imageset`
- `client/android/梦屿西游/assets/unpacked/ui/imagesets/worldmap_main_hd.imageset`

建议资源组织：

- imageset 名称使用新名字，例如 `worldmap_main_hd`
- 只包含主图一张图，例如 `map_main`
- 布局里把 `WorldMap/MapImage/map1` 或 `WorldMap/MapImage/map` 的 `Image` 改成新 imageset

这样做的好处：

- 不会把 `ccditu` 里的边框、按钮、遮罩、箭头一起拉高倍率
- 不会因为共享 atlas 变化把其它 UI 一起放大
- 回滚简单，只要把 `Image` 属性切回原 imageset 即可

### 3.2 Android 世界地图布局治理

当前风险点：

- `WorldMap/MapImage/map` 目前使用 `{{0,276},{0,12},{1,276},{1,-34}}`
- `right.scale = 1` 会导致主图区随父容器宽度继续被撑开

对应锚点：

- `client/android/梦屿西游/assets/unpacked/ui/layouts/worldmap.layout`

建议改法：

1. 保留 `WorldMap/MapImage` 居中面板
2. 把 `WorldMap/MapImage/mapbg` 改成固定像素宽度的内容框
3. 把 `WorldMap/MapImage/map` 改成固定像素显示区或居中固定宽度区
4. 主图是否显示为 `1:1`、`1.25x` 或 `1.5x`，只通过主图区尺寸表控制，不再通过比例锚点撑宽

推荐原则：

- **PC 与 Android 主图区都收敛到“固定显示区 + 居中”**
- 资源清晰度由高清主图提供
- 布局只负责稳定显示，不再承担缩放职责

### 3.3 主场景地图入口 HUD 改造策略

当前问题：

- PC 地图入口主要是固定块，被全局 UI 放大
- Android 地图入口区域 `LogoInfo/backImage/smallmap` 使用比例锚点，宽度跟父级一起变化
- 当前入口图块分别来自 `ccui1`、`mainui` 这类共享 atlas，直接替换共享 atlas 风险偏高

对应锚点：

- `client/resource/res/ui/layouts/logoinfo.layout`
- `client/android/梦屿西游/assets/unpacked/ui/layouts/logoinfo.layout`
- `client/resource/res/ui/imagesets/ccui1.imageset`
- `client/resource/res/ui/imagesets/mainui.imageset`
- `client/android/梦屿西游/assets/unpacked/ui/imagesets/mainui.imageset`

建议做法：

1. **为地图入口 HUD 单独建专用 atlas / imageset**
2. **布局只切图片引用，不直接回写到 `ccui1` / `mainui` 大共享图**
3. **Android 把 `LogoInfo/backImage/smallmap` 从比例锚点改成固定像素区域**

建议新增文件：

- `client/resource/res/ui/imagesets/maphud_entry_hd.imageset`
- `client/android/梦屿西游/assets/unpacked/ui/imagesets/maphud_entry_hd.imageset`

建议迁移资源：

- 地图入口底板
- 世界地图按钮底座
- 地图入口中心图标

建议布局变更点：

- PC：只切 `Image` 来源到专用高清 imageset
- Android：除了切图，还要把 `LogoInfo/backImage/smallmap` 的 `UnifiedAreaRect` 改成固定区域

### 3.4 第一阶段实际改动顺序

1. 新增 `worldmap_main_hd.imageset`
2. 新增 `maphud_entry_hd.imageset`
3. 改 PC `worldmap.layout` 主图引用
4. 改 Android `worldmap.layout` 主图引用与主图区尺寸
5. 改 PC `logoinfo.layout` 地图入口图片引用
6. 改 Android `logoinfo.layout` 地图入口图片引用与区域锚点

### 3.5 第一阶段验收标准

验收页面：

- 世界场景内普通地图
- 世界地图打开页
- 主场景地图入口 HUD

验收口径：

1. `1080p / 1440p / 2K` 截图下，世界地图主图边缘不再明显发软
2. Android 超宽屏设备上，世界地图主图区宽度不再继续被拉长
3. Android 主场景地图入口区域在不同宽高比下不再横向撑开
4. `worldmapdlg.lua` 和 `logoinfodlg.lua` 不需要改窗口路径和按钮名

## 4. 第二阶段：场景 render scale 基建

### 4.1 目标

场景 render scale 只解决一个问题：

- **世界场景地图与对象是按多高密度渲染出来的**

它不负责：

- 改战斗站位
- 改世界逻辑坐标
- 改 UI 布局坐标
- 改 Lua 里通过 UI logic 取到的宽高

### 4.2 必须坚持的接口边界

以下旧语义必须保持不动：

- `iadapter::get_logic_w/h()` 继续表示世界逻辑尺寸
- `iadapter::get_ui_logic_w/h()` 继续表示 UI 逻辑尺寸
- `Engine::GetLogicWidth/Height()` 继续走 UI logic 语义
- `World(this, m_adapter->get_logic_w(), m_adapter->get_logic_h())` 不改

对应原因：

- `engine/engine/nuengine.cpp` 里世界对象创建直接吃 logic size
- `BattleManagerOperate.cpp`、`SkillBuilder.cpp`、世界对象投影与布点都绑定旧语义
- 直接改旧接口会把“高清化”变成“玩法坐标漂移”

### 4.3 render scale 建议接口

建议新增而不是复用旧接口：

- `iadapter::get_scene_render_w()`
- `iadapter::get_scene_render_h()`
- 或者 `iadapter::get_scene_render_scale()`

推荐优先选择：

- **宽高接口优先**

原因：

- 渲染入口最终要吃的就是实际 render target size
- `1.25x / 1.5x` 这类倍率最终都要落成像素尺寸
- 多端和未来分档时，宽高接口更直接

### 4.4 第二阶段代码改动点

第一批迁移只限 render-only 路径：

1. `ResolutionAdapter.h/.cpp`
   - 增加场景 render size 成员
   - 保留旧 logic size 不动
2. `engine/engine/nuiadapter.h`
   - 增加 render size 访问接口
3. `engine/renderer/nucocos2d_render.cpp`
   - `GetDisplayMode()` 改为返回场景 render size
4. `client/FireClient/Application/Framework/GameApplication.cpp`
   - `BeginDraw(...)` 改吃 render size，而不是 logic size
5. `engine/engine/nucocos2d_wraper.cpp`
   - 梳理 `EngineLayer::draw()` 中投影与 viewport 使用的尺寸来源

先不动的路径：

- `nuengine.cpp` 世界对象初始化尺寸
- `World::SetScale()` 的 gameplay camera 语义
- battle 布点、skill builder、世界对象逻辑坐标换算

### 4.5 render scale 分档建议

建议以设备档位控制：

| 档位 | 场景 render scale | 说明 |
| --- | --- | --- |
| 低端 Android | `1.0x` 或 `1.15x` | 先保帧率 |
| 中端 Android | `1.25x` | 默认推荐档 |
| 高端 Android / Win32 | `1.5x` | 高清优先 |

说明：

- `1.25x` 像素面积约是 `1.56x`
- `1.5x` 像素面积约是 `2.25x`
- render scale 只允许通过设备档位或调试开关打开，不要直接写死全平台

### 4.6 第二阶段验收标准

1. 世界场景地图纹理观感优于当前基线
2. 战斗站位、点击落点、世界角色屏幕位置不发生系统性漂移
3. Lua UI 取 `GetLogicWidth/Height()` 的行为不变
4. Android 中端机 `p95 frame time` 不显著劣化

## 5. 资源与性能预算

### 5.1 地图 UI 预算

建议预算：

- 世界地图主图高清资源：单张控制在 `8 MB ~ 16 MB` 级别的压缩后体积
- 地图入口 HUD 高清资源：单 atlas 控制在 `2 MB` 内
- 世界地图界面打开时新增显存占用：控制在 `20 MB` 内

建议：

- 世界地图主图与地图入口 HUD 分开打包
- 主图允许按需加载
- HUD 资源常驻，主图资源按页面生命周期释放

### 5.2 场景 render scale 预算

目标帧预算：

- 低端 Android：`30 FPS` 保底
- 中高端 Android / Win32：`60 FPS` 目标

必看指标：

- scene fps
- `p95 frame time`
- `/map/*` 纹理上传次数
- render target size
- 世界地图打开耗时
- 世界地图主图纹理驻留大小

## 6. 推荐实施顺序

### 批次 1：立即可做

1. 世界地图主图专用高清 imageset
2. 地图入口 HUD 专用高清 imageset
3. Android `worldmap.layout` 主图区固定化
4. Android `logoinfo.layout` 地图入口区域固定化

### 批次 2：基建改造

1. `iadapter` 增加 scene render size 接口
2. `ResolutionAdapter` 增加 render size 计算
3. `BeginDraw / renderer display mode / draw pass` 切到 render size

### 批次 3：灰度与回归

1. 选 2 张世界场景地图做 A/B 截图
2. 选世界地图页做 PC/Android 对比截图
3. 选 3 个典型宽高比做 Android 回归

---

## 7. 明确不做

1. 不在本批次处理 `xiaoditu_mtg`
2. 不直接修改 `adapter->get_logic_w/h()` 语义
3. 不把 `World::SetScale()` 当成高清开关
4. 不直接替换复用范围极大的共享 atlas 作为首选方案
5. 不把世界场景 `/map/*` 的采样优化误当成世界地图 UI 已经一起修好

---

## 8. 下一步建议

如果按“先止损再基建”的顺序推进，建议下一步直接进入**批次 1 的代码与布局实装**：

1. 先把世界地图主图与地图入口 HUD 的高清资源接入方式定下来
2. 再改 Android `worldmap.layout` 与 `logoinfo.layout` 的横向扩展锚点
3. 这批稳定后，再开 `scene render scale` 接口改造

这样推进的收益最大：

- 最快解决用户最容易感知的 UI 发虚
- 不会先踩战斗/世界逻辑尺寸风险
- 为后续场景高清化留出干净接口面
