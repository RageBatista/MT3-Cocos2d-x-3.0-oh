# MT3 项目 VS2013 编译构建脚本梳理（2026-03-07）

## 1. 范围与结论

- 范围：`E:\MT3` 中与 `VS2013 / v120 / MSBuild 12.0 / vcvarsall` 相关的构建与验证脚本。
- 结论：
  - **主线客户端入口已统一**为 `tools/scripts/Build-MT3-Exe-Canonical.ps1`，并固定 `VS2013 + v120` 链路。
  - **实际执行构建的核心链路**是：`Build-MT3-Exe-Canonical.ps1 -> client/Build-MT3-v120.ps1`。
  - 仓库存在多条“工具类/专项构建脚本”也会调用 VS2013 或 MSBuild 12.0，但约束强度不一致。
  - `.github/workflows` 当前未发现直接触发主线 Windows 客户端编译脚本的工作流。

## 5. 调用关系（主链）

1. `tools/scripts/Build-MT3-Exe-Canonical.ps1`
2. `client/Build-MT3-v120.ps1`
3. `msbuild` 依次构建：
   - `common/platform`
   - `common/ljfm`
   - `common/lua`
   - `common/cauthc`
   - `cocos2d` 相关
   - `engine`
   - `FireClient`
   - `MT3`
4. 运行 `runtime-sync` + `runtime-audit`
5. 校验 `MT3.exe` 存在

## 6. 当前风险点（按优先级）

1. 主线外的若干脚本未显式传 `/p:PlatformToolset=v120`，依赖项目文件默认值。
2. `Build-EngineTools-v120.ps1` 与 `Validate-CELayoutEditorS6.ps1` 都存在“可能使用 PATH 中 msbuild”的路径，环境不干净时有偏移风险。
3. 仓库中存在多套旧项目（例如部分 `v110/v110_xp`），若误纳入统一批量构建，可能破坏“v120 主线假设”。

## 7. 建议执行策略

1. 主线 MT3 客户端编译：只走 `tools/scripts/Build-MT3-Exe-Canonical.ps1`。
2. 直接调用 `msbuild` 的场景：优先通过 `.codex/scripts/invoke-msbuild-guarded.ps1` 包装。
3. 工具链脚本（CEGUI/Editor/EngineTools）如需长期维护，建议补齐：
   - 显式 `/p:PlatformToolset=v120`
   - 或接入统一 `guarded msbuild` 包装。
