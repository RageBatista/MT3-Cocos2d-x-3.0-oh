## 🎯 案例研究结构

每个案例包含以下标准结构:

```yaml
案例目录/
├── README.md                    # 案例概述与索引
├── problem-statement.md         # 问题陈述
├── investigation.md             # 调查过程
├── solution.md                  # 解决方案
├── verification.md              # 验证与测试
└── lessons-learned.md           # 经验教训
```

## 🔍 如何使用案例

### 使用场景 1: 遇到类似问题

```yaml
步骤:
  1. 浏览案例目录，找到相似问题
  2. 阅读 problem-statement.md 确认问题匹配
  3. 参考 solution.md 应用解决方案
  4. 参考 verification.md 验证修复效果
```

### 使用场景 2: 学习最佳实践

```yaml
步骤:
  1. 阅读 investigation.md 了解问题分析方法
  2. 阅读 lessons-learned.md 吸取经验教训
  3. 应用到自己的问题诊断中
```

### 使用场景 3: 新人入职培训

```yaml
步骤:
  1. 按顺序阅读完整案例
  2. 理解 MT3 项目的典型问题模式
  3. 掌握标准化的问题解决流程
```

## 🚀 案例贡献指南

如果你解决了一个有价值的问题，欢迎贡献案例:

```yaml
贡献流程:
  1. 创建案例目录: cases/your-case/
  2. 编写标准结构文档 (6个文件)
  3. 提交 Pull Request
  4. 团队审查后合并

案例要求:
  - ✅ 问题真实且具有代表性
  - ✅ 解决方案经过验证
  - ✅ 包含完整的调查过程
  - ✅ 有明确的经验教训总结
```
