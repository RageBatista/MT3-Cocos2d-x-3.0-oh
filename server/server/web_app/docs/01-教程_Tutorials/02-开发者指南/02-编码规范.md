## 1. PSR-12 编码标准

本项目遵循 [PSR-12](https://www.php-fig.org/psr/psr-12/) PHP 编码规范扩展包。

### 1.1 基本格式

#### 文件格式

```php
<?php
// 文件必须使用 <?php 标签开始
// 文件必须使用 UTF-8 无 BOM 编码
// 文件必须以一个空行结束

declare(strict_types=1);

namespace App\Module;

use App\Service\UserService;

// 类定义...
```

#### 缩进和行长度

- 使用 **4 个空格** 缩进（不使用 Tab）
- 每行代码不超过 **120 字符**
- 每个语句后必须有分号

### 1.2 类和方法

#### 类定义

```php
<?php
namespace App\Service;

use App\Model\User;
use think\facade\Db;

/**
 * 用户服务类
 * 
 * 提供用户相关的业务逻辑处理
 */
class UserService
{
    /**
     * @var User 用户模型
     */
    protected $userModel;
    
    /**
     * 构造函数
     * 
     * @param User $userModel 用户模型实例
     */
    public function __construct(User $userModel)
    {
        $this->userModel = $userModel;
    }
    
    /**
     * 获取用户信息
     * 
     * @param int $userId 用户ID
     * @return array|null 用户信息数组，未找到返回 null
     */
    public function getUserInfo(int $userId): ?array
    {
        $user = $this->userModel->find($userId);
        
        if ($user === null) {
            return null;
        }
        
        return $user->toArray();
    }
}
```

#### 方法定义规则

- 左花括号必须在方法声明后另起一行
- 右花括号必须在方法体后另起一行
- 参数列表中每个逗号后必须有一个空格
- 参数有默认值时，等号两边各有一个空格

```php
// 正确示例
public function createOrder(
    int $userId,
    float $amount,
    string $type = 'normal'
): int {
    // 方法体
}

// 错误示例
public function createOrder(int $userId,float $amount,string $type='normal'):int{
    // 方法体
}
```

### 1.3 控制结构

#### if 语句

```php
// 正确
if ($condition) {
    // 代码
} elseif ($anotherCondition) {
    // 代码
} else {
    // 代码
}

// 错误
if($condition){
    // 代码
}
```

#### for 循环

```php
// 正确
for ($i = 0; $i < 10; $i++) {
    // 代码
}

// foreach
foreach ($items as $key => $value) {
    // 代码
}
```

#### switch 语句

```php
switch ($status) {
    case 'pending':
        $message = '待处理';
        break;
    case 'completed':
        $message = '已完成';
        break;
    default:
        $message = '未知状态';
        break;
}
```

## 2. 命名规范

### 2.1 类命名

使用 **大驼峰** 命名法（PascalCase）：

```php
// 控制器
class PlayerController {}
class OrderManager {}

// 模型
class User {}
class OrderRecord {}

// 服务类
class CommissionService {}
class PaymentHandler {}
```

### 2.2 方法命名

使用 **小驼峰** 命名法（camelCase）：

```php
// 正确
public function getUserInfo() {}
public function calculateCommission() {}
public function sendEmail() {}

// 错误
public function get_user_info() {}
public function GetUserInfo() {}
```

### 2.3 变量命名

使用 **小驼峰** 命名法：

```php
// 正确
$userName = 'John';
$orderList = [];
$totalAmount = 100.00;

// 错误
$UserName = 'John';
$order_list = [];
```

### 2.4 常量命名

使用 **全大写+下划线**：

```php
// 正确
const MAX_RETRY_COUNT = 3;
const DEFAULT_PAGE_SIZE = 20;
const STATUS_PENDING = 'pending';

// 错误
const maxRetryCount = 3;
const DefaultPageSize = 20;
```

### 2.5 数据库命名

使用 **小写+下划线**：

```sql
-- 表名
user_account        -- 账号表
user_order          -- 订单表
agent_relation      -- 代理关系表

-- 字段名
user_id
player_name
created_at
updated_at
```

### 2.6 命名对照表

| 类型 | 命名风格 | 示例 |
|------|----------|------|
| 类名 | 大驼峰 | `UserService` |
| 方法名 | 小驼峰 | `getUserInfo()` |
| 变量名 | 小驼峰 | `$userName` |
| 常量 | 全大写下划线 | `MAX_SIZE` |
| 数据库表 | 小写下划线 | `user_account` |
| 数据库字段 | 小写下划线 | `created_at` |

## 3. 注释规范

### 3.1 文件头注释

```php
<?php
/**
 * 用户服务类
 * 
 * 提供用户相关的业务逻辑处理，包括：
 * - 用户信息获取
 * - 用户创建和更新
 * - 用户权限验证
 * 
 * @package    App\Service
 * @author     开发团队
 * @copyright  Copyright (c) 2024
 * @version    1.0.0
 */
```

### 3.2 类注释

```php
/**
 * 订单处理服务
 * 
 * 负责订单的创建、查询、更新等操作
 * 
 * @package App\Service
 * @see Order 订单模型
 */
class OrderService
{
    // ...
}
```

### 3.3 方法注释

使用 PHPDoc 格式：

```php
/**
 * 创建新订单
 * 
 * 根据用户ID和商品信息创建订单，同时处理库存扣减
 * 和佣金计算等关联操作
 * 
 * @param int   $userId    用户ID
 * @param array $items     商品列表，格式：[['id' => 1, 'qty' => 2], ...]
 * @param float $totalAmount 订单总金额
 * 
 * @return array 返回订单信息，包含 order_id 和 order_no
 * 
 * @throws \Exception 当库存不足时抛出异常
 * @throws \Exception 当用户不存在时抛出异常
 * 
 * @example
 * ```php
 * $order = $service->createOrder(123, [
 *     ['id' => 1, 'qty' => 2],
 *     ['id' => 5, 'qty' => 1]
 * ], 299.00);
 * echo $order['order_no'];
 * ```
 */
public function createOrder(int $userId, array $items, float $totalAmount): array
{
    // 实现...
}
```

### 3.4 行内注释

```php
// 单行注释：说明下一行代码的作用
$commission = $amount * 0.1;  // 计算10%的佣金

/*
 * 多行注释：
 * 用于解释复杂的逻辑块
 * 可以跨越多行
 */
if ($user->level >= 10) {
    // VIP用户享受额外折扣
    $discount = 0.1;
} else {
    // 普通用户无折扣
    $discount = 0;
}
```

### 3.5 TODO 注释

```php
// TODO: 后续需要添加缓存支持
// FIXME: 这里有性能问题，需要优化
// HACK: 临时解决方案，需要重构
// NOTE: 重要说明，需要注意
```

## 4. Git 提交规范

### 4.1 提交信息格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 4.2 类型（type）

| 类型 | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | feat(player): 添加玩家搜索功能 |
| `fix` | 修复 Bug | fix(order): 修复订单金额计算错误 |
| `docs` | 文档更新 | docs: 更新部署文档 |
| `style` | 代码格式（不影响功能） | style: 格式化代码缩进 |
| `refactor` | 重构 | refactor(service): 重构佣金计算逻辑 |
| `test` | 测试相关 | test: 添加订单服务单元测试 |
| `chore` | 构建/工具相关 | chore: 更新 composer 依赖 |
| `perf` | 性能优化 | perf(query): 优化玩家列表查询性能 |

### 4.3 范围（scope）

可选的范围标识，表示影响的模块：

```
feat(player): 添加玩家封禁功能
fix(order): 修复订单状态更新问题
docs(api): 更新 API 文档
refactor(agent): 重构代理佣金计算
```

### 4.4 主题（subject）

- 使用简短的描述（50 字符以内）
- 使用祈使句（如 "添加" 而非 "添加了"）
- 不以句号结尾

### 4.5 完整示例

```
feat(order): 添加订单自动取消功能

- 添加定时任务检查超时未支付订单
- 超时订单自动取消并恢复库存
- 发送订单取消通知给用户

Closes #123
```

```
fix(player): 修复玩家余额显示错误

玩家余额在小数点后两位时显示不正确，
原因是浮点数精度问题。

修复：使用 bcmath 扩展进行精确计算

Fixes #456
```

### 4.6 分支命名规范

| 分支类型 | 命名格式 | 示例 |
|----------|----------|------|
| 功能分支 | `feature/功能描述` | `feature/player-search` |
| 修复分支 | `fix/问题描述` | `fix/order-amount` |
| 发布分支 | `release/版本号` | `release/v1.2.0` |
| 热修复分支 | `hotfix/问题描述` | `hotfix/security-patch` |

## 5. 代码审查清单

提交代码前，请确认：

### 5.1 格式检查

- [ ] 代码缩进使用 4 空格
- [ ] 行尾无多余空格
- [ ] 文件末尾有空行
- [ ] 大括号位置正确

### 5.2 命名检查

- [ ] 类名使用大驼峰
- [ ] 方法名使用小驼峰
- [ ] 常量使用全大写下划线
- [ ] 变量名有意义

### 5.3 注释检查

- [ ] 复杂逻辑有注释说明
- [ ] 公共方法有 PHPDoc 注释
- [ ] TODO 标记已记录

### 5.4 功能检查

- [ ] 代码可正常运行
- [ ] 无明显性能问题
- [ ] 无安全漏洞
- [ ] 已处理边界情况

## 6. 工具配置

### 6.1 PHP_CodeSniffer

安装并配置代码检查工具：

```bash
# 安装
composer require --dev squizlabs/php_codesniffer

# 检查代码
./vendor/bin/phpcs --standard=PSR12 app/

# 自动修复
./vendor/bin/phpcbf --standard=PSR12 app/
```

### 6.2 PHP-CS-Fixer

```bash
# 安装
composer require --dev friendsofphp/php-cs-fixer

# 检查
./vendor/bin/php-cs-fixer fix --dry-run --diff app/

# 修复
./vendor/bin/php-cs-fixer fix app/
```

### 6.3 Git Hooks

配置 pre-commit 钩子自动检查：

```bash
#!/bin/sh
# .git/hooks/pre-commit

# 检查代码规范
./vendor/bin/phpcs --standard=PSR12 app/
if [ $? -ne 0 ]; then
    echo "代码规范检查失败，请修复后提交"
    exit 1
fi
```

## 7. 常见问题

### Q: 旧代码不符合规范怎么办？

1. 新代码必须遵循规范
2. 修改旧代码时顺便调整
3. 大规模重构需要单独任务

### Q: 团队成员不遵守规范？

1. 配置 Git Hooks 强制检查
2. 代码审查时拒绝不合规范的提交
3. 定期进行规范培训

### Q: 如何在 IDE 中配置？

**VS Code**:
- 安装 PHP Intelephense 插件
- 配置 `.editorconfig` 文件

**PhpStorm**:
- Settings → Editor → Code Style → PHP
- 选择 PSR-12 预设
