# 项目结构认知（源码对齐版）

> 目标：快速建立 `web_app` 代码定位能力  
> 口径：以当前目录结构与控制器/路由实现为准

## 1. 应用架构总览

项目基于 ThinkPHP 8 多应用模式，当前主要应用：

1. `admin`：管理后台（代理、玩家、订单、GM、转区、配置）
2. `agent`：代理后台
3. `api`：客户端/三方接口（支付、回调、语音、FAQ、兼容层）
4. `player`：玩家中心（认证、资料、充值、反馈、转区、CDK）
5. `login`：历史后台登录/授权兼容入口
6. `index`：前台页面（CDK、Duty）
7. `sdk`：SDK 页面壳
8. `app/controller`：根应用兼容控制器（当前为 `Enlist`）

## 2. 顶层目录定位

```text
web_app/
├── app/                # 业务代码
├── config/             # 配置
├── route/              # 显式路由
├── database/           # SQL 基线/增量
├── public/             # Web 根目录与静态资源
├── runtime/            # 运行时缓存和日志
└── docs/               # 文档
```

## 3. 代码分层定位

## 3.1 控制器

位置：`app/{appName}/controller/*.php`  
职责：接收请求、参数校验、调用模型/服务、返回页面或 JSON。

## 3.2 模型

位置：`app/model/*.php`、`app/player/model/*.php`  
职责：表访问与查询封装（如 `User`、`Bind`、`Role`、`UserOrder`、`Transfer`）。

## 3.3 服务层

位置：`app/service/*.php`、`app/player/service/*.php`  
职责：跨控制器复用逻辑（例如转区执行、日志服务、权限审计等）。

## 3.4 视图层

位置：`app/{appName}/view/**`  
形态：服务端模板 + jQuery 脚本 + bootstrap-table。

## 4. 路由与可达性

显式路由：

1. `route/app.php`
2. `route/player.php`

隐式路由：

- `config/route.php` 中 `url_route_must` 取决于环境变量：生产环境默认强制路由，开发环境允许隐式路由（`/`{app}`/`{controller}`/`{action}``可达）。

关键兼容路由（当前已显式）：

1. `/enlist/submit_code`
2. `/user/api/index.php/role/set|get`
3. `/user/api/index/role/set|get`

## 5. 一次请求如何定位代码

示例：角色管理列表数据

1. 页面：`/index.php?s=/admin/player/roleList`
2. AJAX：`GET /index.php?s=/admin/player/role_table`
3. 控制器：`app/admin/controller/Player.php::role_table`
4. 模型：`app/model/Role.php::getListForTable`
5. 视图：`app/admin/view/player/role_list.html`

## 6. 常用排查入口

1. 代码入口：`app/BaseController.php`
2. 全局中间件：`app/middleware.php`
3. 后台鉴权中间件：`app/middleware/Check.php`
4. 玩家中间件链：`app/player/middleware.php`
5. 日志：`runtime/log/{Ymd}.log`

## 7. 开发注意点

1. 文档、接口、路由三者必须同步更新。
2. 兼容链路不能直接删，先确认客户端是否仍在访问。
3. 遇到“页面有，接口无”先查 `route/*.php` 与隐式路由可达性。
4. 涉及鉴权改动必须同时检查 `Check`、`PlayerAuth` 与 Session 键空间。
