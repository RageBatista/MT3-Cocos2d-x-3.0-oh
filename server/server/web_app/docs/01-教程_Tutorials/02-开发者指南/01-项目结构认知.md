## 1. 多应用架构说明

### 1.1 架构概述

本项目基于 **ThinkPHP 8.x** 框架，采用 **多应用模式** 架构。系统根据用户角色和功能场景，将应用划分为多个独立的子应用：

```
┌─────────────────────────────────────────────────────┐
│                    mt3_web                          │
├─────────────────────────────────────────────────────┤
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐   │
│  │  admin  │ │  agent  │ │ player  │ │   sdk   │   │
│  │ 后台管理 │ │ 代理端  │ │ 玩家端  │ │ 登录SDK │   │
│  └─────────┘ └─────────┘ └─────────┘ └─────────┘   │
│                                                     │
│  ┌─────────────────────────────────────────────┐   │
│  │              公共层 (Common)                  │   │
│  │   服务类 │ 工具类 │ 中间件 │ 配置            │   │
│  └─────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────┘
```

### 1.2 应用划分

| 应用 | 入口路径 | 目标用户 | 主要功能 |
|------|----------|----------|----------|
| **admin** | `/admin` | 系统管理员 | 后台管理、数据维护 |
| **agent** | `/agent` | 代理商 | 代理推广、佣金管理 |
| **player** | `/player` | 游戏玩家 | 玩家中心、转账记录 |
| **sdk** | `/sdk` | 游戏客户端 | 登录、注册接口 |
| **api** | `/api` | 游戏客户端 | 游戏内接口 |

### 1.3 架构优势

- **职责分离**：各应用独立维护，互不干扰
- **安全隔离**：不同角色的代码物理隔离
- **便于扩展**：新增功能模块不影响现有应用
- **团队协作**：不同团队可并行开发不同应用

## 3. 各目录职责详解

### 3.1 应用目录 (`app/`)

应用目录是项目的核心，包含所有业务代码。

#### 单应用结构示例（以 admin 为例）

```
app/admin/
├── controller/             # 控制器
│   ├── Index.php          # 首页控制器
│   ├── Player.php         # 玩家管理
│   ├── Order.php          # 订单管理
│   ├── Agent.php          # 代理管理
│   └── ...
│
├── view/                   # 视图模板
│   ├── player.html        # 玩家列表页
│   └── agent/
│       ├── list.html      # 代理列表
│       └── add.html       # 添加代理
│
├── middleware.php          # 中间件配置
├── common.php              # 应用公共函数
├── event.php               # 事件配置
└── security_config.php     # 安全配置
```

#### 控制器职责

| 控制器 | 职责 |
|--------|------|
| `Index.php` | 首页展示、数据统计 |
| `Player.php` | 玩家 CRUD 操作 |
| `Order.php` | 订单查询、处理 |
| `Agent.php` | 代理管理、结算 |
| `Item.php` | 物品管理 |
| `Log.php` | 日志查询 |

### 3.2 服务层 (`app/service/`)

服务层包含可复用的业务逻辑类：

```
app/service/
├── CommissionService.php        # 佣金计算服务
├── PermissionAuditService.php   # 权限审计服务
└── TransferExecutionService.php # 转账执行服务
```

**使用示例**：

```php
use app\service\CommissionService;

// 计算佣金
$commission = CommissionService::calculate($orderId);
```

### 3.3 配置目录 (`config/`)

```
config/

├── database.php     # 数据库配置
```

## 4. 关键文件说明

### 4.1 入口文件

**`public/index.php`**

```php
<?php
// [ 应用入口文件 ]
namespace think;

require __DIR__ . '/../vendor/autoload.php';

// 执行HTTP应用并响应
$http = (new App())->http;

$response = $http->run();

$response->send();

$http->end($response);
```

### 4.2 基础控制器

**`app/BaseController.php`**

所有控制器的基类，提供公共方法：

```php
<?php
namespace app;

use think\App;
use think\exception\ValidateException;
use think\Validate;

abstract class BaseController
{
    // 应用实例
    protected $app;
    
    // 请求实例
    protected $request;
    
    // 初始化
    public function __construct(App $app)
    {
        $this->app     = $app;
        $this->request = $this->app->request;
    }
    
    // ... 公共方法
}
```

## 5. 请求处理流程

理解请求处理流程有助于快速定位代码：

```
用户请求
    │
    ▼
public/index.php (入口)
    │
    ▼
路由解析 (route/)
    │
    ▼
中间件处理
    │
    ▼
控制器 (app/{应用}/controller/)
    │
    ├──► 服务类 (app/service/)
    │
    ├──► 模型 (app/{应用}/model/)
    │
    ▼
视图渲染 (app/{应用}/view/)
    │
    ▼
响应返回
```

### 示例：访问玩家列表

```
URL: /admin/player/list

1. 入口：public/index.php
2. 路由：解析到 admin 模块
3. 控制器：app/admin/controller/Player.php::list()
4. 视图：app/admin/view/player.html
5. 响应：渲染玩家列表页面
```

## 6. 快速定位代码

### 6.1 根据功能定位

| 功能 | 位置 |
|------|------|
| 玩家管理 | `app/admin/controller/Player.php` |
| 订单处理 | `app/admin/controller/Order.php` |
| 代理管理 | `app/admin/controller/Agent.php` |
| 登录接口 | `app/sdk/controller/Login.php` |
| 注册接口 | `app/sdk/controller/Register.php` |

### 6.2 根据配置定位

| 配置项 | 文件 |
|--------|------|
| 数据库连接 | `config/database.php` |
| 缓存设置 | `config/cache.php` |
| 路由规则 | `route/` 目录 |
| 安全策略 | `config/security.php` |

### 6.3 根据问题定位

| 问题类型 | 检查位置 |
|----------|----------|
| 页面报错 | `runtime/log/` 日志 |
| 数据库错误 | `config/database.php` + 模型文件 |
| 权限问题 | `app/{应用}/middleware.php` |
| 性能问题 | `config/cache.php` 缓存配置 |

## 7. 开发建议

### 7.1 新增功能

1. 在对应应用的 `controller/` 创建控制器
2. 在 `view/` 创建视图模板
3. 如需复用逻辑，在 `app/service/` 创建服务类
4. 配置路由（如需要）

### 7.2 修改现有功能

1. 根据功能定位控制器
2. 理解现有逻辑
3. 小步修改，及时测试
4. 遵循编码规范

### 7.3 调试技巧

```php
// 打印变量
dump($variable);

// 打印并终止
halt($variable);

// 写入日志
\think\facade\Log::info('调试信息：' . $data);
```

## 8. 常见问题

### Q: 如何新增一个应用？

1. 在 `app/` 下创建新目录
2. 创建 `controller/` 和 `view/` 目录
3. 配置路由和入口（如需要）

### Q: 控制器找不到？

1. 检查命名空间是否正确
2. 检查类名和文件名是否一致
3. 运行 `composer dump-autoload`

### Q: 视图模板不生效？

1. 检查视图文件路径
2. 确认视图配置 `config/view.php`
3. 清除运行时缓存
