## 7. 同步机制：文档与代码 100% 同步

### 7.1 触发条件

以下情况必须触发文档更新：

1. **新增控制器**：添加新的控制器文件
2. **新增方法**：在现有控制器中添加新的公开方法
3. **修改接口**：修改路由、参数、响应格式
4. **删除接口**：移除或废弃现有接口
5. **配置变更**：修改影响公开接口的配置项

### 7.2 责任人

| 角色 | 职责 |
|------|------|
| 开发者 | 在代码提交前更新相关文档 |
| Code Reviewer | 在代码审查时检查文档同步情况 |
| 技术文档负责人 | 定期（每月）审计文档与代码一致性 |

### 7.3 门禁检查

在代码合并前必须通过以下检查：

1. **文档存在性检查**：新增接口必须在对应 API 文档中有条目
2. **文档完整性检查**：接口条目必须包含路径、方法、参数、响应
3. **链接有效性检查**：文档内部引用链接必须有效
4. **编码规范检查**：文档文件必须使用 UTF-8（无 BOM）

### 7.4 发布前核对清单

在发布新版本前，必须完成以下检查：

- [ ] 所有新增接口已录入对应 API 文档
- [ ] 所有修改接口已更新对应 API 文档
- [ ] 所有废弃接口已在文档中标注
- [ ] 所有文档内部链接有效
- [ ] 所有文档文件编码正确（UTF-8 无 BOM）
- [ ] CHANGELOG 已更新本次变更
- [ ] 文档目录 README 已更新导航

### 7.5 自动化建议

建议引入以下自动化工具：

1. **文档生成工具**：基于源码注释自动生成 API 文档骨架
2. **链接检查工具**：自动检测文档中的失效链接
