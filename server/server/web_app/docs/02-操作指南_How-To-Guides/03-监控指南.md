# 监控指南（实战版）

> 适用项目：`web_app`  
> 目标：让运维/值班同学能在 5 分钟内判断“是否有故障、故障在哪一层”

## 1. 监控对象清单

## 1.1 应用日志（核心）

日志目录：

```text
runtime/log/
```

当前日志形态（来自 `config/log.php` + 实际运行）：

1. 主日志：`YYYYMMDD.log`
2. 分级日志：`YYYYMMDD_warning.log`、`YYYYMMDD_error.log`（按级别拆分）
3. 支付回调专项日志：`YYYYMMDD_pay_callback.log`（`api/Call.php` 写入）

日志内容为 JSON 行格式（适合 grep/jq/ELK）。

## 1.2 运行时目录健康

重点关注：

1. `runtime/log` 持续可写
2. `runtime/cache` 不异常膨胀
3. `runtime/*/temp` 模板缓存可正常生成

## 1.3 基础服务

1. Web：Nginx/Apache
2. PHP-FPM
3. MySQL
4. Redis（建议启用）

## 2. 快速巡检命令

## 2.1 Linux

```bash
# 1) 今日日志尾部
tail -n 100 runtime/log/$(date +%Y%m%d).log

# 2) warning/error 快速查看
tail -n 100 runtime/log/$(date +%Y%m%d)_warning.log
tail -n 100 runtime/log/$(date +%Y%m%d)_error.log

# 3) 支付回调链路
tail -n 100 runtime/log/$(date +%Y%m%d)_pay_callback.log

# 4) 服务状态
systemctl status nginx php8.1-fpm mysql redis --no-pager
```

## 2.2 Windows PowerShell

```powershell
$d = Get-Date -Format yyyyMMdd
Get-Content -Encoding utf8 "runtime/log/$d.log" -Tail 100
if (Test-Path "runtime/log/${d}_warning.log") { Get-Content -Encoding utf8 "runtime/log/${d}_warning.log" -Tail 100 }
if (Test-Path "runtime/log/${d}_error.log")   { Get-Content -Encoding utf8 "runtime/log/${d}_error.log" -Tail 100 }
if (Test-Path "runtime/log/${d}_pay_callback.log") { Get-Content -Encoding utf8 "runtime/log/${d}_pay_callback.log" -Tail 100 }
```

## 4. 告警规则建议（按优先级）

## 4.1 P1（立即告警）

1. `*_error.log` 出现 `Fatal error|Uncaught|Call to undefined`
2. 支付回调日志出现连续 `签名验证失败` 或 `防重放保护触发`（5分钟>20次）
3. 登录链路出现持续 `CSRF令牌无效`（5分钟>30次）
4. GM/JMX 出现 `GM命令执行失败` 连续失败（5分钟>5次）

## 4.2 P2（值班确认）

1. `warning.log` 中 404 扫描噪音突增（10分钟>200条）
2. `verifyPlayerAdminAuth FAILED` 突增（10分钟>50次）
3. `拦截疑似扫描请求` 持续增长（判断是否真实攻击）

## 4.3 P3（趋势监控）

1. `runtime/log` 日志总量日环比增长 > 200%
2. `runtime/cache` 体积异常增长
3. PHP-FPM worker 持续满载

## 5. 告警脚本模板（Linux）

```bash
#!/usr/bin/env bash
set -euo pipefail

BASE="/var/www/web_app/runtime/log"
D=$(date +%Y%m%d)
ERR="$BASE/${D}_error.log"
WAR="$BASE/${D}_warning.log"
PAY="$BASE/${D}_pay_callback.log"

fatal_count=$(grep -Eic "Fatal error|Uncaught|Call to undefined" "$ERR" 2>/dev/null || true)
csrf_count=$(grep -Eic "CSRF|令牌无效" "$WAR" 2>/dev/null || true)
pay_fail_count=$(grep -Eic "签名验证失败|防重放保护触发|发货失败" "$PAY" 2>/dev/null || true)
jmx_fail_count=$(grep -Eic "GM命令执行失败" "$WAR" 2>/dev/null || true)

if [ "$fatal_count" -gt 0 ] || [ "$pay_fail_count" -gt 20 ] || [ "$csrf_count" -gt 30 ] || [ "$jmx_fail_count" -gt 5 ]; then
  echo "$(date '+%F %T') ALERT fatal=$fatal_count pay_fail=$pay_fail_count csrf=$csrf_count jmx_fail=$jmx_fail_count"
  # TODO: 接入企业微信/钉钉/邮件
fi
```

crontab 示例（每 5 分钟）：

```bash
*/5 * * * * /usr/local/bin/web_app_alert.sh >> /var/log/web_app_alert.log 2>&1
```

## 6. 噪音与误报处理

当前环境常见噪音：

1. 扫描器请求 `/sitemap.xml`
2. 扫描器请求 `/.well-known/security.txt`

建议：

1. 这类 404 计入“安全扫描噪音”看趋势，不作为单条 P1 告警
2. 若同一 IP 高频命中，可在 Web 层限速或临时封禁

## 7. 每日值班 checklist

1. 查看今日 `warning/error` 是否有新增关键异常
2. 抽查支付回调日志是否有连续失败
3. 抽查 GM/JMX 操作是否成功闭环
4. 抽查兼容路由是否出现异常激增
5. 记录当天异常摘要（时间、现象、影响、处置）
