# 发布检查清单（P0-P2）

## 一、发布前准备

- 确认 `.env` 已配置且未使用占位值：
  - `ADMIN_AUTH_SECRET_KEY`
  - `OP_SECRET_SALT`
  - `MASTER_VERIFY_PASSWORD`
  - 支付通道密钥（如 `pay_key`）
- 确认生产环境：
  - `APP_ENV=production`
  - `COOKIE_SECURE=1`
  - `ROUTE_MUST=1`
- 确认支付网关地址为 `https://`。

## 二、数据库变更

- 确认 `database/mhxy.sql` 基线表结构完整（28 表）
- 校验关键字段与索引：
  - `cdks.pass_hash` 字段存在
  - `user_bind` 新索引存在
  - `user_account.idx_username` 存在
- 如需增量迁移，确认迁移脚本在 `database/` 目录下存在后再执行

## 三、代码与配置验证

- PHP 语法检查：
  - `php -l app/api/controller/Sdk.php`
  - `php -l app/api/pay/EpayCore.php`
  - `php -l app/middleware/Check.php`
  - `php -l app/login/controller/Index.php`
  - `php -l app/player/service/AuthService.php`
  - `php -l app/api/controller/Game.php`
  - `php -l app/api/controller/Call.php`
- Composer 检查：
  - `composer run check`

## 四、安全验证

- 登录与注册接口不再返回明文密码。
- 后台登录成功后，验证 Redis/File 缓存存在 `admin_auth_token:*` 会话键。
- 支付回调缺失 `nonce` 时应被拒绝。
- SDK 登录在 `OP_SECRET_SALT` 为空时应返回安全配置错误。
- Cookie 响应头验证：
  - `Secure`
  - `HttpOnly`
  - `SameSite=Strict`（生产）

## 五、灰度与回滚策略

- 灰度阶段优先验证：
  - 后台登录/退出
  - 支付回调链路
  - SDK 登录注册
  - API v1 兼容性
- 回滚顺序：
  1. 代码回滚
  2. 执行 SQL 回滚脚本
  3. 清理缓存键 `admin_auth_token:*`
  4. 重新验证登录与支付链路
