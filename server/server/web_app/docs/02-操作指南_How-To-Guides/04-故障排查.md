# 故障排查指南（源码对齐版）

> 目标：用最短路径定位 `web_app` 常见线上问题  
> 建议先看：`runtime/log/{Ymd}.log` 与 `runtime/log/{Ymd}_warning.log`

## 1. 快速排查流程

1. 先确认“是否可复现”（时间、账号、URL、参数）
2. 读取当日日志（`runtime/log`）
3. 对照路由与控制器实现（`route/*.php` + `app/*/controller`）
4. 再看数据库映射关系（`user_account` / `user_bind` / `role`）

## 2. 高频问题与处理

## 2.1 登录时报 “CSRF令牌无效”

排查：

1. 刷新页面后重试
2. 检查是否跨标签页复用了旧表单
3. 确认请求是否携带 `csrf_token` 或 `X-CSRF-TOKEN`

关键代码：

1. `app/player/middleware/CsrfToken.php`
2. `app/player/common.php`
3. `app/BaseController.php`

## 2.2 角色管理列表为空

排查：

1. 确认接口实际为 `GET /admin/player/role_table`
2. 核对 `role.userid` 是否可映射 `user_account.id`
3. 核对 `user_bind.userid` 与 `role.roleid` 是否一致

关键代码：

1. `app/admin/controller/Player.php::role_table`
2. `app/model/Role.php::getListForTable`
3. `app/model/Bind.php::syncMissingRoleBindings`

## 2.3 绑定列表显示 UID 而非账号

现象：

- 页面显示 `UID:x（账号未同步）`

原因：

1. `user_bind.userid` 对应账号不存在
2. `role.userid` 未回填或指向无效账号

处理：

1. 修复 `user_account` 数据
2. 触发/执行绑定回填逻辑

## 2.4 旧客户端请求 404（`/user/api/index.php/role/*`）

当前处理机制：

1. 已有显式兼容路由到 `api/LegacyRole`
2. `Check` 中间件会拦截疑似扫描请求

排查：

1. 请求是否携带有效账号参数（兼容接口有最小参数要求）
2. 查看 warning 日志是否命中扫描拦截

## 2.5 `/enlist/submit_code` 调用异常

现状：

1. 该接口已退化为兼容提示，不再执行业务转区提交
2. 唯一处理器：`api/Enlist::submitCode`（通过 `route/app.php` 显式路由映射）

## 2.6 GM 命令执行失败

排查：

1. `.env` 中 `JMX_*` 是否正确
2. 目标区服 `serverip/gmport/gmlocal` 是否可达
3. Java/JMX 工具链是否可执行

关键代码：

1. `app/gm/Gm.php`
2. `config/security.php -> jmx_auth`

## 2.7 支付回调不入账

排查：

1. 看 `api/Call::epay` 日志（验签/防重放/幂等）
2. 核对 `user_order.status` 是否已更新
3. 核对 `pay_callback_lock:*` 与 nonce 防重放逻辑

关键代码：

1. `app/api/controller/Call.php`
2. `app/api/pay/EpayCore.php`

## 3. 常用命令

查看当日日志：

```bash
tail -f runtime/log/$(date +%Y%m%d).log
```

查看 warning：

```bash
tail -f runtime/log/$(date +%Y%m%d)_warning.log
```

筛选关键字：

```bash
grep -iE "csrf|legacyrole|enlist|error|warning" runtime/log/*.log
```

## 4. 数据核查 SQL 示例

```sql
-- 账号与绑定
SELECT id, username FROM user_account WHERE id IN (1,2,3);
SELECT id, userid, serverid, playerid, playername FROM user_bind ORDER BY id DESC LIMIT 20;

-- 角色归属
SELECT roleid, name, userid, level, profession FROM role ORDER BY roleid DESC LIMIT 20;
```

## 5. 错误码说明（务实口径）

项目返回协议并不统一，常见仅有：

1. `notify(1/0, msg)`
2. 字符串 `success/fail`
3. HTML 页面响应

不要依赖“全局统一错误码表”；应按具体接口文档与源码判断。

## 6. 升级/回滚时排查建议

发布后异常优先级：

1. 路由是否变化
2. `.env` 关键密钥是否缺失
3. 数据库结构是否与 `mhxy.sql`/增量脚本一致
4. 兼容链路（LegacyRole/Enlist）是否被误删

## 7. 需要提交给开发的信息

最小故障包：

1. 出错时间（精确到分钟）
2. 请求 URL 与参数（脱敏）
3. 当日日志片段
4. 关联账号/角色ID/订单号
5. 最近一次变更内容（代码/配置/数据库）
