# 配置文件说明（源码对齐版）

> 更新时间：2026-04-10  
> 参考基线：`00-源码静态分析与对齐基线.md`

## 1. 配置来源

当前项目配置来源分三层：

1. `.env` / `.env.example`（环境变量）
2. `config/*.php`（框架与业务配置）
3. 代码默认值（当环境变量未设置时）

## 2. 关键配置文件

## 2.1 `config/app.php`

当前仓库中为静态值：

- `app_debug => false`
- `show_error_msg => false`
- `default_timezone => Asia/Shanghai`
- `with_route => true`

说明：`APP_DEBUG` 在该文件未直接 `env()` 读取。

## 2.2 `config/database.php`

主要环境变量：

- `DB_HOST` / `DB_PORT`
- `DB_NAME` / `DB_USER` / `DB_PASS`
- `DB_CHARSET`
- `DB_PREFIX`
- `DB_DRIVER`（默认 `mysql`）

## 2.3 `config/route.php`

关键项：

- `url_route_must` 取决于环境变量 `ROUTE_MUST`（默认跟随 `APP_ENV`）：生产默认强制路由，开发环境允许隐式路由
- `middleware` 包含 `\app\middleware\Check::class`

## 2.4 `config/cache.php`

- 默认驱动：优先 `redis`，否则降级 `file`
- 代码中大量锁依赖 Redis（支付/转区），Redis 不可用时需评估并发风险

## 2.5 `config/security.php`

重点分组：

**鉴权与支付安全**：
- `admin_auth.secret_key` — 后台鉴权密钥
- `pay_callback.*` — 回调防重放、幂等、日志脱敏
- `debug_endpoints.*` — 调试探针开关
- `player_auth.*` — 玩家Token签名、有效期、强度检查
- `bind_ticket.*` — 绑定票据签发/验票、TTL、单次消费策略
- `jmx_auth.*` — JMX认证（username/password/token/enabled）

**输入防护**（Security中间件配置，当前中间件未全局挂载）：
- `sql_injection.*` — SQL注入检测（dangerous_chars、max_length、log_attacks）
- `xss_protection.*` — XSS防护（dangerous_tags、dangerous_attributes）
- `csrf_protection.*` — CSRF防护（token过期、Referer校验）
- `file_upload.*` — 文件上传安全（allowed_types、max_size、check_content）

**账号安全**：
- `password_security.*` — 密码复杂度（min_length、max_length、complexity）
- `login_security.*` — 登录保护（max_failures、lockout_time、enable_captcha）
- `session_security.*` — 会话安全（timeout、regenerate_id、secure_cookies、http_only）

**运维安全**：
- `error_handling.*` — 错误处理（show_details、log_errors、log_level）
- `ip_blacklist.*` — IP黑白名单（enabled、blacklist、whitelist）

其中：
- `debug_endpoints.pay_callback_probe_enabled=false`（默认关闭调试探针）
- `pay_callback` 控制回调防重放、幂等、日志脱敏
- `bind_ticket` 控制绑定票据签发/验票、TTL、单次消费策略
- `sql_injection`/`xss_protection` 等分组由 `Security` 中间件消费，但该中间件当前未在全局链中挂载

## 2.6 `config/player.php`

重点项：

- `auth_enabled`
- `op_secret_salt`
- `signature_timeout`
- `item_whitelist_cache_ttl`
- `pet_whitelist_cache_ttl`
- `ccs_dir` / `item_files`
- `gm_timeout`
- `tcp_direct_enabled`

说明：`SendItem` 新链路实际从 `public/txt/itemid.txt` 读取白名单，`item_files/ccs_dir` 仍用于历史兼容链路（`login/Auth`）。

## 2.7 `config/transfer.php`

重点项：

- `type.*`、`status.*`、`rules.*`、`fee.*`
- `gm_migration_enabled`（默认 `false`）

该开关决定 `TransferExecutionService` 执行模式：

- `false`：绑定级迁移（`binding_only`）
- `true`：尝试 GM 全量迁移链路

## 2.8 `config/middleware.php` 与 `app/middleware.php`

- `config/middleware.php`：注册 alias 与 priority
- `app/middleware.php`：全局实际挂载链

文档解释中必须以"实际挂载链"为准。

## 2.9 `config/permission.php`

权限点映射配置，用于 `PermissionGuard` 中间件执行细粒度权限校验。

格式：`应用.控制器.方法 => 允许的管理员类型数组`

当前已定义权限点：

| 权限点 | 允许类型 | 说明 |
|--------|---------|------|
| `admin.gmcdk.cdkgenerate` | `[1]` | CDK生成（仅 admin） |
| `admin.gmcdk.cdkdelete` | `[1]` | CDK删除（仅 admin） |
| `admin.gmcdk.cdkupdateuid` | `[1]` | CDK更新用户（仅 admin） |
| `admin.gmcdk.cdkupdatepass` | `[1]` | CDK更新密码（仅 admin） |
| `admin.gmcleandata.docleandata` | `[1]` | 数据清理（仅 admin） |
| `admin.gmcleandata.docleanall` | `[1]` | 全量清理（仅 admin） |
| `admin.configure.notice` | `[1]` | 公告配置（仅 admin） |
| `admin.configure.server` | `[1]` | 服务器配置（仅 admin） |
| `admin.player.save` | `[1]` | 玩家保存（仅 admin） |
| `agent.player.status` | `[1, 2]` | 玩家状态切换（admin + agent） |

> 类型值：`1` = admin（超管），`2` = agent（代理）。未在 `rules` 中定义的路由不受 `PermissionGuard` 限制。

## 3. 关键环境变量清单

## 3.1 鉴权与安全

- `ADMIN_AUTH_SECRET_KEY`：后台 token 密钥（必配）
- `OP_SECRET_SALT`：玩家 token/签名密钥（必配，建议>=32）
- `MASTER_VERIFY_PASSWORD`：超级管理员二次验证密钥
- `BIND_TICKET_ENABLED`
- `BIND_TICKET_REQUIRED_ON_API_BIND`
- `BIND_TICKET_REQUIRED_ON_LEGACY_ROLE_SET`
- `BIND_TICKET_REQUIRED_ON_ENLIST_SUBMIT_CODE`
- `BIND_TICKET_TTL_SECONDS`
- `BIND_TICKET_GRACE_SECONDS`
- `BIND_TICKET_SINGLE_USE`
- `BIND_TICKET_SECRET_KEY`

## 3.2 支付回调

- `PAY_CALLBACK_REPLAY_PROTECTION`
- `PAY_CALLBACK_TIMESTAMP_TTL`
- `PAY_CALLBACK_IDEMPOTENCY`
- `PAY_CALLBACK_LOG_MASKING`

## 3.3 调试探针

- `PAY_CALLBACK_DEBUG_ENABLED`
- `PAY_CALLBACK_DEBUG_LOCAL_ONLY`

## 3.4 转区

- `TRANSFER_GM_MIGRATION_ENABLED`

## 3.5 数据库

- `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASS` / `DB_CHARSET`

## 3.6 API 兼容返回开关

- `API_SDK_LEGACY_RAW`：`/api/game/sdk` 是否返回 `json_encode` 字符串
- `API_BIND_LEGACY_SCALAR`：`/api/game/bind` 是否返回 `json_encode(1|0)`
- `API_REBATE_LEGACY_TEXT`：`/api/game/rebate` 关闭态是否返回纯文本

## 4. 代码内固定值（非配置项）

当前仍存在部分硬编码值：

1. PlayerAuth 用户信息缓存 TTL：`600` 秒
2. Player Transfer 活跃服务器缓存 TTL：`3600` 秒（`server_list:active`）
3. Pay 支付通道缓存 TTL：`300` 秒（`pay_channels:*`）

## 5. 生产环境最小建议

1. 必须设置高强度 `ADMIN_AUTH_SECRET_KEY`
2. 必须设置高强度 `OP_SECRET_SALT`（至少 32 位随机串）
3. 必须设置 `MASTER_VERIFY_PASSWORD`
4. 默认保持：
   - `PAY_CALLBACK_REPLAY_PROTECTION=true`
   - `PAY_CALLBACK_IDEMPOTENCY=true`
   - `PAY_CALLBACK_LOG_MASKING=true`
5. 非必要不启用 `PAY_CALLBACK_DEBUG_ENABLED`
6. 建议启用绑定票据并设置独立密钥：`BIND_TICKET_ENABLED=true` + `BIND_TICKET_SECRET_KEY`

## 6. 与代码行为相关的易错点

1. `app_debug` 在 `config/app.php` 固定为 `false`，并非直接跟随 `.env`
2. 路由模式取决于环境变量（生产默认强制路由，开发环境允许隐式路由），安全策略应覆盖两种场景
3. `TransferExecutionService` 默认不是 GM 全量迁移
4. `Game` 兼容接口返回格式可被 `API_*_LEGACY_*` 环境变量切换，联调时需明确当前值
