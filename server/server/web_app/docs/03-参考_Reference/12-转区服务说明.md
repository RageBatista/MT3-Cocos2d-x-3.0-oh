# 转区服务说明（与当前代码对齐）

> 更新时间：2026-02-23  
> 对齐基线：当前仓库代码实现（`Transfer` 模型状态机 + `TransferExecutionService` 执行链路）

## 1. 功能概览

转区由三层组成：

1. 玩家提交申请（Player 应用）
2. 管理员审核并推进状态（Admin 应用）
3. 服务层执行迁移（Service + GM 接口）

核心代码：

- 申请与状态模型：`app/model/Transfer.php`
- 管理端流程：`app/admin/controller/Transfer.php`
- 执行服务：`app/service/TransferExecutionService.php`
- 玩家端申请：`app/player/controller/Transfer.php`
- 规则配置：`config/transfer.php`

---

## 2. 状态定义与合法迁移

状态常量定义于 `Transfer` 模型：

| 状态名 | 值 | 含义 |
|---|---:|---|
| `STATUS_PENDING` | 0 | 待审核 |
| `STATUS_APPROVED` | 1 | 审核通过 |
| `STATUS_REJECTED` | 2 | 审核拒绝 |
| `STATUS_PROCESSING` | 3 | 处理中 |
| `STATUS_COMPLETED` | 4 | 已完成 |

合法迁移由 `STATUS_TRANSITIONS` 明确约束：

- `0 -> 1/2`
- `1 -> 3/2`
- `3 -> 4`
- `2` 与 `4` 不再允许后续迁移

模型更新入口 `updateStatus()` 的并发与一致性机制：

1. Redis 锁：`transfer_status_lock:{id}`，30 秒
2. 事务包裹
3. 迁移合法性检查
4. CAS 风格条件更新：`where(id)->where(status=oldStatus)->update(...)`

## 3. 管理端流程（Admin）

控制器：`app/admin/controller/Transfer.php`

### 3.1 审核通过 `approve()`

- 仅允许当前状态为 `待审核(0)`
- 调用模型 `updateStatus(..., STATUS_APPROVED, ...)`

### 3.2 审核拒绝 `reject()`

- 仅允许当前状态为 `待审核(0)`
- 必须填写拒绝原因
- 调用 `updateStatus(..., STATUS_REJECTED, ...)`

### 3.3 开始处理 `process()`

- 需要 CSRF Token
- 仅允许当前状态为 `审核通过(1)`
- 调用 `updateStatus(..., STATUS_PROCESSING, ...)`

### 3.4 执行完成 `complete()` / `autoExecute()`

- `complete()` 与 `autoExecute()` 都要求状态为 `处理中(3)`
- 调用 `TransferExecutionService::executeTransfer($id)`
- 成功时返回目标角色 ID，失败时返回服务层错误信息

## 4. 执行服务（TransferExecutionService）

服务类：`app/service/TransferExecutionService.php`

### 4.1 并发保护

- 锁键：`transfer_execution_lock:{transferId}`
- TTL：300 秒
- 获取失败直接返回：`转区任务正在执行中，请勿重复操作`

### 4.2 主流程（`executeTransfer`）

1. 开启事务
2. 读取转区单并校验状态必须是 `处理中(3)`
3. 读取源/目标服务器
4. 读取源角色绑定
5. 检查在线状态
6. 备份角色数据
7. 迁移角色（创建目标角色 -> 属性/物品/宠物迁移 -> 删除源角色）
8. 更新 `user_transfer` 状态为完成并写入目标角色信息
9. 更新 `bind`（serverid/playerid）
10. 发送站内邮件通知
11. 提交事务

失败路径：任一步骤抛异常会回滚事务并返回 `success=false`。

## 5. 当前实现特征（按代码真实行为）

### 5.1 GM 转区方法为“显式未实现”

`app/gm/Gm.php` 中以下方法当前返回 `error`：

- `checkRoleOnline`
- `getRoleData`
- `createRole`
- `migrateRoleAttributes`
- `migrateRoleItems`
- `migrateRolePets`
- `deleteRole`
- `restoreRoleData`

这意味着执行服务在生产逻辑中会进入失败分支（例如备份阶段获取不到 `data` 时失败），不再出现旧版本“假成功”语义。

### 5.2 服务器 ID 使用存在两套语义

- 管理端详情页使用 `Server::getServerId(serverid)` 查询
- 执行服务中使用 `Server::find(id)` 查询

文档仅记录现状，不对该差异做设计性解释。

## 6. 玩家端入口与规则

玩家控制器：`app/player/controller/Transfer.php`

- 列表页 `index()`：服务器列表缓存 3600 秒（`server_list:active`）
- 提交 `submit()`：
  - CSRF 校验
  - 基础字段校验（源服、目标服、角色、联系方式、原因）
  - 调用 `TransferService` 校验资格
  - 拒绝重复未完成申请（同用户同角色，状态非完成/非拒绝）

规则来源：`config/transfer.php -> rules`，通过 `app/player/service/TransferService.php` 读取。

## 7. 配置与数据表

### 7.1 配置文件

`config/transfer.php` 包含：

- `type`（反馈/转区）
- `status`（0~4）
- `rules`（等级、充值、每月次数、冷却天数）
- `fee`（是否收费/费用）

### 7.2 关键数据表

`user_transfer`（`database/mhxy.sql`）：

- `role`：源角色 ID
- `source_server_id` / `target_server_id`
- `target_role_id` / `target_role_name`
- `status`、`reply`、`admin_id`、`processed_at`
