# 转区服务说明（源码对齐版）

> 更新时间：2026-04-10  
> 核心实现：`app/model/Transfer.php`、`app/player/controller/Transfer.php`、`app/admin/controller/Transfer.php`、`app/service/TransferExecutionService.php`

## 1. 业务分层

1. 玩家提单：`player/Transfer`
2. 管理审核：`admin/Transfer`
3. 状态机控制：`model/Transfer`
4. 执行编排：`service/TransferExecutionService`

## 2. 状态机定义

状态常量（`Transfer`）：

- `0` 待审核（`STATUS_PENDING`）
- `1` 审核通过（`STATUS_APPROVED`）
- `2` 审核拒绝（`STATUS_REJECTED`）
- `3` 处理中（`STATUS_PROCESSING`）
- `4` 已完成（`STATUS_COMPLETED`）

合法迁移：

1. `0 -> 1/2`
2. `1 -> 3/2`
3. `3 -> 4`

并发保护：

- 锁键：`transfer_status_lock:{id}`
- CAS 更新：`where(id)->where(status=oldStatus)->update(...)`

## 3. 玩家侧流程

入口：`player/Transfer::submit`

核心校验：

1. 登录与 CSRF
2. 源服/目标服/角色/联系方式/原因格式
3. 源服与目标服开放性
4. 角色归属（必须在当前账号可访问角色中）
5. 资格校验（`TransferService::canRoleTransfer`）
6. 拒绝同角色未完成申请

写入：

- 表：`user_transfer`
- 初始状态：`status=0`

## 4. 管理侧流程

入口：`admin/Transfer.php`

动作：

1. `approve`：仅 `0` 可审核通过
2. `reject`：仅 `0` 可拒绝，需填写原因
3. `process`：仅 `1` 可进入处理（需 CSRF）
4. `complete`：仅 `3` 可执行
5. `autoExecute`：仅 `3` 可执行

## 5. 执行服务真值

`TransferExecutionService::executeTransfer($transferId)` 核心步骤：

1. 获取执行锁 `transfer_execution_lock:{transferId}`
2. 事务内读取申请与角色/服务器数据
3. 校验状态必须为 `3`
4. 执行迁移逻辑
5. 更新 `user_transfer` 为完成
6. 更新 `user_bind` 到目标服
7. 发送通知邮件

## 6. 默认执行模式（重点）

当前默认：

- `execution_mode = binding_only`

含义：

- 默认不执行 GM 全量迁移链路
- 仅做转区单状态完成 + 绑定关系切换

开启全量迁移条件：

- `config('transfer.gm_migration_enabled') == true`
- 对应环境变量：`TRANSFER_GM_MIGRATION_ENABLED=true`

## 7. GM 全量迁移链路（可选）

当 `gm_migration_enabled=true` 时，会调用：

1. `checkRoleOnline`
2. `backupRoleData`
3. `migrateRoleData`（属性/物品/宠物）
4. `deleteRole`
5. 失败时 `restoreRoleData`

说明：是否可用取决于 `app/gm/Gm.php` 的实际实现与目标环境能力。

## 8. 关键锁与缓存键

1. `transfer_status_lock:{id}`（状态更新）
2. `transfer_execution_lock:{transferId}`（执行互斥）
3. `server_list:active`（玩家端服务器列表缓存）

## 9. 数据字段口径

`user_transfer` 关键字段：

- `uid`：账号ID
- `role`：源角色ID
- `source_server_id` / `target_server_id`
- `target_role_id` / `target_role_name`
- `status` / `reply` / `admin_id` / `processed_at`

`user_bind` 更新要点：

- 通过 `playerid + source_server_id` 定位记录并切换到目标服

## 10. 风险与注意事项

1. 绑定级迁移与 GM 全量迁移是两条不同口径，文档必须区分
2. 管理端动作严格受状态机约束，不能跳状态执行
3. 生产启用 GM 全量迁移前需先验证游戏服命令能力
