## 2. 核心业务表（重点）

## 2.1 `user_order`（订单表）

主要字段：

- `orderid`：业务订单号
- `agent`：代理链信息
- `user`：用户/角色快照（JSON文本）
- `item`：商品快照（JSON文本）
- `realmoney`：实付金额
- `status`：订单状态（0待支付/1已支付/2已退款）

对应模型：`app/model/UserOrder.php`

---

## 2.2 `user_transfer`（转区申请表）

该表已包含 P1-C 对齐字段，核心列如下：

- `id` 主键
- `uid` 用户 ID
- `username` 用户名
- `role` 源角色ID（转区前）
- `source_server_id` 源服务器ID
- `target_server_id` 目标服务器ID
- `target_role_id` 目标角色ID
- `target_role_name` 目标角色名
- `contact` 联系方式
- `reason` 转区原因
- `type` 类型（1反馈/2转区）
- `reply` 管理员回复
- `admin_id` 处理管理员
- `status` 状态（0待审核/1通过/2拒绝/3处理中/4完成）
- `processed_at` 处理时间
- `created_at` / `updated_at`

对应模型：`app/model/Transfer.php`

---

## 2.3 `player_login_log`（玩家登录日志）

主要字段：

- `user_id`
- `username`
- `ip`
- `platform`
- `user_agent`
- `status`（1成功/0失败）
- `remark`
- `created_at`

对应模型：`app/player/model/PlayerLoginLog.php`

---

## 2.4 `player_profile`（玩家资料）

## 4. 关键关系（逻辑层）

1. `user_account.id -> user_bind.userid`
2. `user_account.id -> user_transfer.uid`
3. `main_server.serverid <-> user_bind.serverid`
4. `user_bind.playerid <-> user_transfer.role`
5. `admin_account.id -> user_transfer.admin_id`
6. `user_account.id -> player_profile.user_id`
7. `user_account.id -> player_login_log.user_id`

说明：部分关系通过业务代码保证，并未全部以外键显式声明。

---

## 5. 与代码行为强关联的字段说明

## 5.1 订单状态字段 `user_order.status`

由 `UserOrder` 状态机控制迁移，避免非法状态跳转。

## 5.2 转区状态字段 `user_transfer.status`

由 `Transfer::STATUS_TRANSITIONS` 控制，且更新时使用锁+CAS。

## 5.3 转区源角色字段 `user_transfer.role`

该字段在玩家提单、管理员处理与执行服务中持续使用，是当前转区链路关键字段。
