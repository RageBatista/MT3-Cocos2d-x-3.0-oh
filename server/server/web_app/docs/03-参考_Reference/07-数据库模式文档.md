## 0. 字段治理约定（与 SQL 基线同步）

以下约定已同步写入 `database/mhxy.sql` 顶部注释，文档与基线保持一致：

1. 兼容字段（注释含“历史兼容字段/兼容保留”）仅用于历史数据读取与过渡，不建议新增写入。
2. 安全相关字段优先使用哈希/摘要语义（例如 `pass_hash`、`pwd` 指纹），禁止新增明文凭据写入。
3. 涉及字段下线需走“先双写兼容 -> 只读兼容 -> 结构清理”的分阶段流程，避免直接破坏线上兼容。
4. 该约定属于协作治理规范，不改变 SQL 执行行为。

## 4. 核心业务表字段说明

## 4.1 `user_order`

关键字段：

- `orderid`：业务订单号
- `user`：用户/角色快照（JSON 字符串）
- `item`：商品快照（JSON 字符串）
- `channel`：支付通道ID
- `status`：0待支付/1已支付/2已退款
- `realmoney`：实付金额

## 4.2 `user_transfer`

关键字段：

- `uid` / `username`
- `role`（源角色ID）
- `source_server_id` / `target_server_id`
- `target_role_id` / `target_role_name`
- `contact` / `reason`
- `status`（0/1/2/3/4）
- `admin_id` / `reply` / `processed_at`

## 4.3 `user_bind`

关键字段：

- `userid`（账号ID）
- `serverid`（区服ID）
- `playerid`（角色ID）
- `playername`
- `charge` / `daycharge`
- `rolelimit` / `daylimit`
- `zhuanqu`

## 4.4 `bind_ticket`

关键字段：

- `ticket_hash`：票据哈希（不明文存储）
- `nonce` / `signature`：签名校验因子
- `user_id` / `username` / `server_id`
- `issued_at` / `expires_at` / `used_at`
- `use_count` / `status` / `last_bind_roleid`

## 4.5 `player_event_log`

关键字段：

- `category`：日志大类，如 `login`、`player_action`、`cdk_auth`、`security`、`recharge`、`feedback`
- `event_type`：具体事件类型
- `uid` / `username` / `serverid`
- `resource_type` / `resource_id`：CDK、反馈等关联资源
- `order_id` / `amount` / `success` / `status`
- `trace_id` / `ip` / `user_agent` / `extra`

说明：

- `app/player/service/LogService.php` 已统一写入该表
- `app/player/model/PlayerLoginLog.php` 以兼容层方式读写该表的 `login` 分类
- 管理员操作审计统一写入 `user_log`（`lv=3`）
- 后台认证日志统一写入 `admin_auth_log`

## 4.6 `cdks`（安全治理补充）

关键字段：

- `pass`：兼容保留字段，历史逻辑读取使用，逐步由 `pass_hash` 替代
- `pass_hash`：授权密码哈希字段（`password_hash`），当前主用
- `username` / `passwd`：历史兼容字段，建议停止新增写入

说明：

- 代码已支持 `pass_hash` 校验并兼容 `pass` 回读迁移
- 基线仍保留历史字段以保障存量数据可读，后续按分阶段方案治理下线

## 5. 关系与口径说明

1. `user_bind.userid` 对应 `user_account.id`
2. `user_transfer.uid` 对应账号ID（非角色ID）
3. `user_transfer.role` 对应源角色ID（`user_bind.playerid`）
4. 多数关系由业务代码保证，非全部由数据库外键约束

## 6. 与代码一致性的重点结论

1. 当前基线确认为“28表”，不是历史口径的 24 表
2. 日志体系存在“基线表 + 运行期扩展表”双层结构
3. 文档与 SQL 基线同步时，必须同步评估 `LogService` 的扩展表访问行为
