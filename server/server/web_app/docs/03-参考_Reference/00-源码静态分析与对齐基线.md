## 2. 核心架构真值

## 2.1 多应用结构（ThinkPHP 8）

当前代码实际应用模块：

- `admin`：管理后台
- `agent`：代理后台
- `api`：开放接口与游戏侧接入
- `player`：玩家中心（认证、资料、订单、转区、CDK、SendItem）
- `login`：历史授权链路兼容入口
- `index`：前台活动/CDK页面
- `sdk`：SDK壳应用（`app/sdk/controller/*`）

## 2.2 路由策略

1. 显式路由：`route/app.php`、`route/web_admin_routes.php`、`route/player.php`
2. 路由模式：`config/route.php` 中 `url_route_must` 取决于环境变量：
   - 生产环境（`APP_ENV=production`）：默认强制路由（`url_route_must=true`），仅显式声明的路由可达
   - 开发环境：允许隐式路由（`url_route_must=false`），未显式声明的方法可通过约定路径访问
   - 可通过 `ROUTE_MUST` 环境变量显式覆盖

结论：生产环境仅显式路由可达；开发环境需同时描述”显式路由”与”隐式控制器动作可达性”。

## 2.3 中间件装配真值

- 全局中间件（`app/middleware.php`）：
  - `\think\middleware\CheckRequestCache`
  - `\think\middleware\SessionInit`
  - `\app\middleware\Check`
  - `\app\middleware\PermissionGuard`
- `Security` 中间件仅在 `config/middleware.php` 注册 alias/priority，未在全局链硬挂载
- Player 应用中间件（`app/player/middleware.php`）：
  - `TraceId`（全链路追踪，UUID v4）
  - `PlayerSecurity`
  - `PlayerAuth`
  - `CsrfToken`

## 3. API 定义真值

## 3.1 显式路由重点

来自 `route/app.php` + `route/web_admin_routes.php`：

- `admin` 后台页面与写接口：玩家、代理、订单、配置、结算、日志、反馈、转区、物品
- `admin/gm` 拆分路由：指向 `GmPlayer/GmServer/GmMail/GmCdk/GmCleanData` 子控制器
- `agent` 代理后台页面与写接口：下级代理、玩家、订单、提现
- 旧链路兼容：
  - `GET|POST /enlist/submit_code -> api.Enlist/submitCode`
  - `GET|POST /user/api/index.php/role/set -> api.LegacyRole/set`
  - `GET|POST /user/api/index.php/role/get -> api.LegacyRole/get`
  - `GET|POST /user/api/index/role/set -> api.LegacyRole/set`
  - `GET|POST /user/api/index/role/get -> api.LegacyRole/get`

来自 `route/player.php`：

- `player/auth/*`：玩家认证
- `player/cdk/*`：CDK 授权与 SendItem 子路由
- `player/admin/*`：玩家端管理员登录
- `player/*`：profile/server/role/order/recharge/feedback/service/transfer
- 历史兼容重定向：`/login/auth/*`、`/login/index`、`/login/user`

根应用兼容控制器（隐式可达）：

- `app/controller/Error.php`
  - `index`（空控制器兜底 404）

说明：`/enlist/submit_code` 路由已通过 `route/app.php` 显式映射到 `api.Enlist/submitCode`，无需根应用兜底控制器。历史文档中引用的 `app/controller/Enlist.php` 和 `app/controller/api/Enlist.php` 均不存在。

## 3.2 响应协议现状

项目不存在全局统一响应封装，实际并存：

1. `json([...])`
2. `json_encode([...])`（字符串）
3. 字符串（如 `success/fail`）
4. `view(...)`（HTML）

结论：接口文档不能假设统一 `code/msg/data`。

## 5. 关键算法与流程真值

## 5.1 支付下单（`api/Pay::getpay`）

核心机制：

1. 白名单参数接收（修复变量覆盖）
2. 分布式锁：`pay_order_lock:{roleid}:{payid}`
3. 锁内校验 `rolelimit/daylimit`
4. 通道缓存：`pay_channels:{type}`（300 秒）
5. 订单号使用 `random_int()`
6. 事务落库 `user_order`

## 5.2 支付回调（`api/Call::epay`）

核心机制：

1. 日志脱敏（`security.pay_callback.mask_fields`）
2. 防重放：`timestamp` + `nonce`
3. 幂等控制：订单状态短路 + `pay_callback_lock:{orderid}`
4. 发货与状态更新同事务

调试端点 `test/checkurl` 受 `security.debug_endpoints.*` 开关控制。

## 5.3 玩家认证（Player）

- Token 格式：`sha256(id|username|timestamp + OP_SECRET_SALT).timestamp`
- 会话键统一 `player_*` 前缀（`app/player/common.php`）
- `PlayerAuth` 校验失败会清会话并阻断

## 5.4 SendItem 安全链路

- 物品列表源：`public/txt/itemid.txt`（当前仅此）
- 物品令牌：`item_token`（HMAC + 过期时间）
- 操作签名：`op_ts + op_sig`（`computeOpSig/validateOpSignature`）
- 超限：物品数量 `1-9999`，仙玉 `1-99999999`

## 5.5 转区执行链路

- 状态机：`0->1/2`，`1->3/2`，`3->4`
- 锁：
  - 状态锁：`transfer_status_lock:{id}`
  - 执行锁：`transfer_execution_lock:{transferId}`
- 默认执行模式：`binding_only`
  - 由 `config('transfer.gm_migration_enabled', false)` 控制
  - 仅在显式开启时进入 GM 全量迁移链路

## 5.6 语音处理（`api/Voice`）

- 入参：`uuid`、`speech(base64)`、`channelId`
- 文件格式校验实际为 AMR 头校验（`#!AMR`）
- 固定落地：`public/iat/{uuid}.amr`
- 当前识别文本固定占位：`未能识别语音`

## 7. 当前实现约束（必须在文档中显式说明）

1. `TransferExecutionService` 默认是绑定级迁移（`binding_only`），不是默认 GM 全量迁移
2. `PlayerSecurity` 已按需求关闭“玩家端 IP 直接封禁拦截”，目前主要做频率限制与可疑记录
3. `Security` 中间件有实现但非全局默认挂载
4. `Voice` 当前只接受 AMR 头校验有效的音频数据
5. `api/Call::test`、`checkurl` 在未开启调试开关时返回 404
6. `api/Index::index()` 仍包含调试输出，不应作为稳定对外接口依赖
7. `/enlist/submit_code` 当前为"真实绑定兼容接口"，返回旧协议文本 `1/0`，不是停用空壳
8. `admin` GM 当前由 `GmPlayer`、`GmServer`、`GmMail`、`GmCdk`、`GmCleanData` 五个子控制器 + `GmBase` 基类承载
9. `PermissionGuard` 全局中间件基于 `config/permission.php` 执行细粒度权限点校验，仅对 `admin`/`agent` 应用生效
10. `TraceId` 中间件作为 Player 模块首个中间件，为所有请求生成/透传 UUID v4 格式的 trace_id

## 8. 对齐规则（文档维护）

1. 以代码行为为准，不以历史口径为准
2. 涉及接口参数、状态机、锁键名、表名时，必须给出代码路径
3. 对“可选/开关控制”的行为必须标注默认值与启用条件
4. `database/mhxy.sql` 为结构基线；运行期扩展表需单独注明“是否有迁移脚本/是否运行期自动建表”
