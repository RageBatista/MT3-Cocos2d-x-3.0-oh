# 业务逻辑说明（与当前代码对齐）

> 更新时间：2026-02-23  
> 说明：本文档聚焦当前实现中的核心业务链路与状态规则。

## 1. 代理与佣金

## 1.1 代理层级

- `admin_account.type=1`：管理员
- `admin_account.type=2`：代理

代理关系通过 `lastagent` 与 `agent_tree` 等字段表达。

## 1.2 佣金分配

服务：`app/service/CommissionService.php`

触发时机：

- 订单状态从非支付成功变更为支付成功时，由 `UserOrder::upOrderStatus()` 触发分佣。

分配比例：

1. 直属代理：70%
2. 一级上级：5%
3. 二级上级：5%

落库行为：

- 累加 `admin_account` 的佣金字段
- 写入 `agent_commission` 明细
- 直属流水达到 5000 时，设置 `can_create_agent=1`

## 2. 支付与订单

## 2.1 下单流程

控制器：`app/api/controller/Pay.php`

流程概述：

1. 参数白名单校验
2. 验证用户、角色、服务器、商品状态
3. 获取分布式锁 `pay_order_lock:{roleid}:{payid}`
4. 在锁内检查限购（`rolelimit/daylimit`）
5. 读取支付通道（缓存 `pay_channels:{type}` 300 秒）
6. 生成订单号（`random_int()`）
7. 事务写入 `user_order`
8. 返回支付 URL（base64）

## 2.2 回调流程

异步回调：`app/api/controller/Call.php::epay()`

核心保障（P0）：

1. 日志脱敏（敏感字段掩码）
2. 防重放（timestamp + nonce）
3. 幂等控制（已支付短路 + Redis 幂等锁）
4. 发货与订单状态更新在同一事务中

同步回跳：`app/api/controller/Notify.php::epay()`，主要用于页面展示。

## 2.3 订单状态机

模型：`app/model/UserOrder.php`

状态值：

- `0` 待支付
- `1` 已支付
- `2` 已退款

迁移规则由 `STATUS_TRANSITIONS` 限制，更新采用 CAS 条件更新。

退款逻辑使用锁：`order_refund_lock:{id}`。

## 3. 玩家认证与授权

## 3.1 Player 登录态

中间件：`app/player/middleware/PlayerAuth.php`

- Session：`id/username/token`
- Token 校验失败：清 Session + 阻断
- 玩家信息缓存：`player_user:{id}`，TTL=600 秒

## 3.2 Token 规则

函数：`app/player/common.php`

- 生成：`sha256(id|username|timestamp + OP_SECRET_SALT)`
- 格式：`hash.timestamp`
- 有效期：24 小时
- `OP_SECRET_SALT` 为空时拒绝生成/验证

---

## 4. 转区系统

## 4.1 玩家提交流程

控制器：`app/player/controller/Transfer.php`

1. 登录与 CSRF 校验
2. 字段校验（源服/目标服/角色/联系方式/原因）
3. 调用 `TransferService` 校验资格
4. 拒绝同角色未完成申请
5. 写入 `user_transfer`（状态=待审核）

性能点：活跃服务器列表缓存 `server_list:active`，TTL=3600 秒。

## 4.2 管理审核流程

控制器：`app/admin/controller/Transfer.php`

- `approve`：`0 -> 1`
- `reject`：`0 -> 2`
- `process`：`1 -> 3`（CSRF校验）
- `complete/autoExecute`：状态必须是 `3`

## 4.3 状态机与并发

模型：`app/model/Transfer.php`

- 状态：0待审核、1通过、2拒绝、3处理中、4完成
- 合法迁移由 `STATUS_TRANSITIONS` 定义
- 更新锁：`transfer_status_lock:{id}`
- CAS 更新：`where(id)->where(status=oldStatus)->update(...)`

## 4.4 执行服务

服务：`app/service/TransferExecutionService.php`

- 执行锁：`transfer_execution_lock:{transferId}`
- 事务执行：校验 -> 备份 -> 迁移 -> 更新状态 -> 更新绑定 -> 通知

当前实现约束：

- `app/gm/Gm.php` 中转区相关方法目前为显式未实现（返回 `error`），因此执行链路存在失败分支是当前真实行为。

## 5. GM 与运维相关业务点

## 5.1 GM 命令调用

文件：`app/gm/Gm.php`

- JMX 参数来自配置
- 命令参数统一转义
- 对端口/ID/IP有基础校验

## 5.2 服务器在线检测（管理端）

管理端首页逻辑会对端口做数值与范围检查后再执行统计命令，避免命令注入风险。

---

## 6. 一致性与性能要点

## 6.1 一致性

1. 支付回调：发货+状态更新同事务
2. 订单状态更新：状态机+CAS
3. 转区状态更新：锁+事务+CAS

## 6.2 缓存

当前关键 TTL：

- 支付通道：300 秒
- 玩家信息：600 秒
- 活跃服务器列表：3600 秒
