# 项目架构说明（与当前代码对齐）

> 更新时间：2026-02-23  
> 范围：多应用架构、核心中间件、关键业务链路与数据模型映射。

## 1. 项目概览

项目基于 ThinkPHP 8，多应用形态运行，核心应用包含：

- `admin`：管理后台
- `agent`：代理后台
- `api`：客户端/API入口
- `login`：授权相关入口
- `player`：玩家中心
- `index`：前台页
- `sdk`：SDK相关入口（控制器位于 `api` 应用内）

---

## 2. 目录与分层

## 2.1 核心目录

- `app/`：应用代码
- `config/`：配置
- `route/`：路由文件（当前可见 `app.php`、`player.php`）
- `database/mhxy.sql`：数据库基线
- `docs/`：文档

## 2.2 典型分层

1. Controller：请求入口与参数协调
2. Model：状态规则与数据读写
3. Service：跨模型事务与业务编排
4. Middleware：认证/安全/频率控制

---

## 3. 中间件架构

## 3.1 全局中间件

文件：`app/middleware.php`

当前全局启用：

1. `\think\middleware\SessionInit`
2. `\app\middleware\Check`

补充：

- `Security` 在 [`config/middleware.php`](../../config/middleware.php) 中存在别名与优先级声明；
- 实际全局执行链以 [`app/middleware.php`](../../app/middleware.php) 为准；
- 文档中关于 `Security` 的描述按“能力已实现、装配以部署实际为准”口径处理。

## 3.2 Player 中间件

核心类：

- `app/player/middleware/PlayerSecurity.php`
- `app/player/middleware/PlayerAuth.php`
- `app/player/middleware/CsrfToken.php`

作用分别为：

1. 频率限制与恶意IP防护
2. 玩家会话与 Token 鉴权
3. CSRF 令牌生成/校验

说明：当前仓库能确认这些中间件实现存在；但是否在所有 player 路由统一挂载，需以实际路由装配与部署配置为准。

---

## 4. 认证架构

## 4.1 Admin/Agent 认证

由 `Check` 中间件统一处理：

- Session + HMAC Token
- token 秘钥来自 `config/security.php -> admin_auth.secret_key`
- 兼容旧密码 Session 自动迁移

## 4.2 Player 认证

由 `PlayerAuth` 处理：

- 校验 `id/username/token`
- 调用 `verifyPlayerToken()`
- 失败即清会话并阻断
- 玩家信息缓存 600 秒

---

## 5. 关键业务链路

## 5.1 支付链路

入口与组件：

1. 下单：`app/api/controller/Pay.php::getpay()`
2. 异步回调：`app/api/controller/Call.php::epay()`
3. 同步回跳：`app/api/controller/Notify.php::epay()`
4. 支付签名：`app/api/pay/EpayCore.php`

安全特征：

- 下单锁 `pay_order_lock:*`
- 回调幂等锁 `pay_callback_lock:*`
- nonce 防重放 `pay_callback_nonce:*`
- 回调事务一致性

## 5.2 转区链路

入口与组件：

1. 玩家提单：`app/player/controller/Transfer.php`
2. 管理审核：`app/admin/controller/Transfer.php`
3. 状态机：`app/model/Transfer.php`
4. 执行服务：`app/service/TransferExecutionService.php`

并发与一致性：

- 状态锁：`transfer_status_lock:*`
- 执行锁：`transfer_execution_lock:*`
- 状态迁移白名单 + CAS 更新

## 8. 当前实现中的约束说明

1. GM 转区相关方法在 `app/gm/Gm.php` 中为显式未实现返回 `error`，执行服务会出现失败分支。
2. `app/login/controller/Auth.php::opSecret()` 仍保留历史回退逻辑（`CHANGE_ME_OP_SALT`）。
3. 响应格式并非全局统一协议，JSON/字符串/HTML 并存。
