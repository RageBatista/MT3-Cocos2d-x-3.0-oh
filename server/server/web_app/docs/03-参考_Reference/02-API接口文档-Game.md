# API接口文档 - Game（游戏接入）

> **版本**: v1.0
> **更新日期**: 2026-02-28
> **基础路径**: `/api/game/`
> **源码位置**: [`app/api/controller/Game.php`](../../app/api/controller/Game.php)

## 概述

Game模块提供游戏客户端与服务端之间的核心交互接口，包括SDK登录鉴权、角色绑定、客服信息、转区服务和玩家反馈等功能。该模块是游戏SDK与服务端通信的关键桥梁。

## 接口列表

### 1. 游戏登录鉴权

**接口地址**: `GET/POST /api/game/sdk`

**功能描述**: 游戏客户端登录时调用，验证账号密码并返回登录结果。

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| account | string | 是 | 用户账号（支持逗号分隔的多账号格式，取第一个） |
| password | string | 是 | 用户密码（支持竖线分隔的格式，取后半部分） |
| serverId | string | 是 | 服务器ID |

**响应格式**: JSON字符串（历史兼容格式）

**成功响应**:
```json
{
    "Code": "1",
    "Channel": "1",
    "PlatformId": "1",
    "Account": "username",
    "Message": "登陆成功!",
    "Session": "encrypted_password"
}
```

**失败响应**:
```json
{
    "Code": "2"
}
```

**错误码说明**:

| Code值 | 说明 |
|--------|------|
| 1 | 登录成功 |
| 2 | 登录失败（账号不存在/密码错误/账号禁用/服务器限制等） |

**业务逻辑**:

1. 解析账号（支持逗号分隔格式）
2. 解析密码（支持竖线分隔格式）
3. 验证服务器ID必填
4. 查询用户信息
5. 检查用户是否已绑定该服务器
6. 特殊服务器权限检查（如直播区）
7. 验证密码正确性
8. 检查账号状态（status=1为正常）
9. 记录登录日志
10. 返回登录结果

### 2. 角色绑定

**接口地址**: `POST /api/game/bind`

**功能描述**: 游戏客户端创建角色后调用，将角色信息与用户账号绑定。

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| account | string | 是 | 用户账号 |
| qu | string | 是 | 服务器ID（区号） |
| roleid | string | 是 | 游戏角色ID |
| name | string | 是 | 角色名称 |

**响应格式**: JSON数字

**成功响应**:
```json
1
```

**失败响应**:
```json
0
```

**响应值说明**:

| 返回值 | 说明 |
|--------|------|
| 1 | 绑定成功 |
| 0 | 绑定失败（账号不存在/角色已绑定） |

**业务逻辑**:

1. 解析账号（支持逗号分隔格式）
2. 验证用户存在性
3. 检查角色是否已被绑定
4. 创建绑定记录（userid, serverid, playerid, playername）
5. 记录操作日志

返回包含以下信息的HTML页面：

### 5. 转区提交

**接口地址**: `POST /api/game/zhuanquSub`

**功能描述**: 执行转区操作，将老区角色的充值金额按比例转换为新区角色的游戏货币和VIP经验。

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| oldrole | int | 是 | 被转区角色ID（老区角色） |
| newrole | int | 是 | 接收转区福利角色ID（新区角色） |

**响应格式**: JSON

**成功响应**:
```json
{
    "code": 1,
    "msg": "转区成功"
}
```

**失败响应**:
```json
{
    "code": 0,
    "msg": "参数异常"
}
```

**错误码说明**:

| 错误信息 | 说明 |
|----------|------|
| 参数异常 | 缺少必要参数 |
| 新区角色不存在 | 新区角色ID无效 |
| 被转区角色不存在 | 老区角色ID无效 |
| 角色不属于同一账号，无法转区 | 安全限制 |
| 新区角色与被转区角色相同 | 不能选择同一角色 |
| 新区角色已接受过转区福利，无法使用 | 每个角色只能接收一次 |
| 被转区角色已被转区，无法使用 | 老区角色已转出 |
| 被专区角色累计金额不足1000元，无法转区 | 最低充值要求 |
| 新区角色累计充值低于要求，无法使用 | 新区充值需达老区50% |
| 转区失败：GM命令执行失败 | 游戏服务器执行失败 |
| 转区失败：GM服务器无响应 | 游戏服务器通信失败 |

**转区规则**:

| 条件 | 要求 |
|------|------|
| 老区角色累计充值 | ≥ 1000元 |
| 新区角色累计充值 | ≥ 老区角色的50% |
| 角色归属 | 两个角色必须属于同一账号 |
| 转区福利 | 每个新区角色只能接收一次 |

**转区奖励计算**:

```
闲鱼（游戏货币）= 老区累计充值 × 600
VIP经验 = 老区累计充值 × 3
```

**业务逻辑**:

1. 验证参数完整性
2. 查询两个角色信息
3. 安全验证：确认角色属于同一用户
4. 检查转区条件（充值金额、转区状态）
5. 开启数据库事务
6. 踢掉老区角色下线
7. 向新区角色发放奖励（闲鱼+VIP经验）
8. 更新转区状态
9. 提交事务

### 8. 反馈提交

**接口地址**: `POST /api/game/fankuiSub`

**功能描述**: 提交玩家反馈内容。

**请求参数**:

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| role | int | 是 | 接收答复的角色ID |
| info | string | 是 | 反馈内容 |

**响应格式**: JSON

**成功响应**:
```json
{
    "code": 1,
    "msg": "您的意见已收录，请耐心等待回复"
}
```

**失败响应**:
```json
{
    "code": 0,
    "msg": "请选择接收答复的角色"
}
```

```json
{
    "code": 0,
    "msg": "请输入您的反馈内容"
}
```

```json
{
    "code": 0,
    "msg": "你反馈的内容将在24小时内回复,如超时未回复，请在24小时后再次反馈！"
}
```

**业务逻辑**:

1. 验证参数完整性
2. 检查该角色是否有待处理的反馈
3. 如果有待处理反馈且未超过24小时，提示等待
4. 创建新的反馈记录
5. 返回成功提示

**反馈频率限制**:

同一角色在提交反馈后，需等待24小时才能再次提交（如果上次反馈尚未处理）。

## 安全机制

### 1. 角色归属验证

转区操作前验证两个角色是否属于同一用户：

```php
if($newroleData['userid'] != $oldroleData['userid']){
    return notify(0,'角色不属于同一账号，无法转区');
}
```

### 2. 事务保护

转区操作使用数据库事务确保数据一致性：

```php
\think\facade\Db::startTrans();
try {
    // 执行转区操作
    \think\facade\Db::commit();
    return notify(1,'转区成功');
} catch (\Exception $e) {
    \think\facade\Db::rollback();
    return notify(0,'转区失败：' . $e->getMessage());
}
```

### 3. 来源验证

转区页面检查请求来源：

```php
$referer = $this->request->header('referer', '');
if (empty($referer) || strpos($referer, $this->request->host()) === false) {
    // 记录日志但允许访问
}
```

## 注意事项

1. **账号格式兼容**: 接口支持逗号分隔的多账号格式和竖线分隔的密码格式，用于兼容历史数据
2. **直播区权限**: 特殊服务器（如ID为1000000999的直播区）需要用户具有`zhiboqu=1`权限
3. **转区不可逆**: 转区操作执行后，老区角色将被标记为已转区，无法再次使用
4. **反馈频率**: 玩家反馈有24小时冷却期，避免频繁提交
5. **客服配置**: 客服信息从代理商配置中读取，需确保代理商已配置客服信息
