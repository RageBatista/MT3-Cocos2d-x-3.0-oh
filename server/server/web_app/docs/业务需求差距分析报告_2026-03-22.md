## 二、核心业务逻辑分析

### 2.1 角色绑定业务逻辑 ✅

**评分：95/100 - 优秀**

#### 亮点分析：

1. **统一绑定入口** (`RoleBindService.php:248-459`)
   - 整合了 3 个绑定入口
   - 避免了多入口实现漂移问题

2. **多层账号回查机制**
   - 第一层：`role.userid` 直接映射
   - 第二层：基于 `lastlogintime` 窗口回查
   - 第三层：基于 `player_login_log` 最近登录记录
   - 第四层：`user_log` 登录日志模式匹配

3. **并发幂等性保证** (`Bind.php:63-91`)
   - 使用唯一键冲突处理
   - 冲突时自动降级为 UPDATE

4. **自动补齐缺失绑定** (`Bind.php:408-590`)
   - 每 5 分钟自动回填
   - 保护期机制防止误操作

#### 发现的问题：

⚠️ **中等风险 - 错绑风险**
```php
// RoleBindService.php:127-169
// 在 180 秒窗口内仅一个登录账号时，会自动绑定
// 高并发场景下可能产生错绑
```

**建议**：
- 增加并发检测阈值
- 窗口缩小至 60 秒

### 2.2 玩家管理业务逻辑 ✅

### 2.3 代理管理业务逻辑 ✅

**评分：82/100 - 良好**

#### 佣金计算逻辑：

```php
// Agent.php:164-200
// 计算公式：
// 总充值 = 直属充值 + 下级充值
// 直属充值 = SUM(user_order.realmoney WHERE agent LIKE 'id|%')
// 下级充值 = SUM(user_order.realmoney WHERE agent LIKE '%@id@%')
```

#### 发现的问题：

❌ **高风险 - 佣金计算未考虑退款**
- **问题**：`user_order.status = 1` 仅验证订单完成，未过滤退款订单
- **风险**：代理佣金计算虚高，导致财务损失

**建议**：
```sql
-- 增加退款状态过滤
WHERE status = 1 AND refund_status = 0
```

| 数据清理冲突 | ✅ 锁机制 | 85/100 | - |

### 4.2 关键缺陷识别

#### ❌ 高风险 - MySQL 连接无降级方案

**问题代码：**
```php
// RoleBindService.php:76-87
$userRow = Db::name('user_account')->where('id', $userId)->find();
if (!$userRow) {
    return ['ok' => false, 'msg' => '账号不存在或未同步'];
}
```

**影响：**
- MySQL 服务异常时，所有绑定操作失败
- 游戏客户端无法登录

**建议改进：**
```php
// 增加 Redis 缓存降级
$cacheKey = "user:{$userId}";
$userRow = Cache::get($cacheKey);
if (!$userRow) {
    try {
        $userRow = Db::name('user_account')->where('id', $userId)->find();
        if ($userRow) {
            Cache::set($cacheKey, $userRow, 3600);
        }
    } catch (\Throwable $e) {
        $userRow = Cache::get($cacheKey . ':backup');
    }
}
```

### 5.3 权限缺陷识别

#### ⚠️ 中等风险 - GM 命令权限不够细化

**问题代码：**
```php
// Gm.php:21-29
private function checkGMPermission()
{
    $currentUser = $this->myAdmin;
    if ((int)$currentUser['type'] !== 1) {
        return false;
    }
    return true;
}
```

**问题：**
- 仅区分"超级管理员"和"非超级管理员"
- 所有 type=1 的管理员拥有相同权限
- 无法实现细粒度控制

#### ❌ 高风险 - 充值操作无审批流程

**问题代码：**
```php
// Player.php:89-141
public function modify()
{
    // ❌ 仅验证 CSRF Token，无审批流程
    $bind = new B();
    $upUser = $bind->upBindCharge($id, $money, $daycharge);
}
```

**风险：**
- 任何有权限的管理员可直接充值
- 无金额限制（单笔理论上限 999999）
- 无操作日志告警
