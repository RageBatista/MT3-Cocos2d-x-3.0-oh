## 1. 文档更新流程

### 1.1 代码变更时的文档同步步骤

当进行代码变更时，请按以下步骤同步更新文档：

```
┌─────────────────────────────────────────────────────────────┐
│                    代码变更 → 文档同步流程                    │
├─────────────────────────────────────────────────────────────┤
│  1. 代码变更前                                               │
│     ├─ 评估变更影响的文档范围                                 │
│     └─ 在 commit message 中标注文档更新需求                   │
│                                                             │
│  2. 代码变更后                                               │
│     ├─ 更新 API 文档（如有接口变更）                          │
│     ├─ 更新配置文档（如有配置项变更）                          │
│     ├─ 更新数据库文档（如有表结构变更）                        │
│     └─ 更新教程文档（如有操作流程变更）                        │
│                                                             │
│  3. 提交文档更新                                             │
│     ├─ 在 CHANGELOG.md 中记录变更                            │
│     └─ 与代码变更一起提交或单独提交                           │
└─────────────────────────────────────────────────────────────┘
```

**文档同步检查表：**

| 变更类型 | 需更新的文档 |
|---------|-------------|
| 新增 API 接口 | `03-参考_Reference/02-API接口文档-*.md` |
| 修改 API 参数/响应 | `03-参考_Reference/02-API接口文档-*.md` |
| 新增配置项 | `03-参考_Reference/03-配置文件说明.md` |
| 修改数据库表结构 | `03-参考_Reference/07-数据库模式文档.md` |
| 新增功能模块 | `03-参考_Reference/06-功能模块说明.md` |
| 修复安全漏洞 | `04-解释_Explanation/01-安全修复记录总览.md` |
| 修改部署流程 | `02-操作指南_How-To-Guides/01-部署指南.md` |

### 1.2 文档审核流程

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   编写文档    │ ──▶ │   自我审查    │ ──▶ │   提交 PR     │
└──────────────┘     └──────────────┘     └──────────────┘
                                                 │
                                                 ▼
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   发布文档    │ ◀── │   审核通过    │ ◀── │   代码审查    │
└──────────────┘     └──────────────┘     └──────────────┘
```

**审核要点：**
1. 内容准确性：文档描述与代码实现一致
2. 格式规范性：符合本文档规定的格式规范
3. 链接有效性：所有链接可正常访问
4. 完整性：覆盖所有必要信息

### 1.3 发布流程

1. **文档版本号更新**：在 [`CHANGELOG.md`](CHANGELOG.md) 中记录变更
2. **索引更新**：更新 [`00-README_文档索引_Documentation_Index.md`](../00-README_文档索引_Documentation_Index.md)
3. **归档处理**：若项目后续启用归档目录，再统一定义归档规则；当前仓库未启用 `meta/archive/`

## 2. 文档编写规范

### 2.1 Markdown 格式规范

#### 基本原则

- 使用 **UTF-8** 编码
- 使用 **Unix 换行符**（LF，`\n`）
- 文件末尾保留一个空行
- 每行不超过 **120 字符**（表格除外）

#### 文档结构模板

```markdown
# 文档标题

简短描述文档的目的和内容。

---

## 目录

1. [章节一](#1-章节一)
2. [章节二](#2-章节二)

---

## 1. 章节一

内容...

### 1.1 子章节

内容...

---

## 2. 章节二

内容...
```

### 2.2 标题层级规范

| 层级 | 用途 | 示例 |
|-----|------|------|
| `#` | 文档标题（仅一个） | `# API 接口文档` |
| `##` | 主要章节 | `## 1. 用户接口` |
| `###` | 子章节 | `### 1.1 登录接口` |
| `####` | 详细说明 | `#### 请求参数` |
| `#####` | 补充说明 | `##### 注意事项` |

**规范要求：**
- 标题层级不超过 5 级
- 标题前后各空一行
- 标题不使用标点符号结尾
- 章节编号使用 `1.` `1.1` `1.1.1` 格式

### 2.3 代码块规范

#### 代码块语法

````markdown
```语言名称
代码内容
```
````

**常用语言标识：**

| 语言 | 标识 |
|-----|------|
| PHP | `php` |
| JavaScript | `javascript` 或 `js` |
| HTML | `html` |
| CSS | `css` |
| SQL | `sql` |
| JSON | `json` |
| Shell | `bash` 或 `shell` |
| HTTP 请求 | `http` |
| 无高亮 | `text` 或省略 |

#### 代码块示例

````markdown
```php
// PHP 代码示例
function hello(string $name): string {
    return "Hello, {$name}!";
}
```
````

#### 行内代码

使用反引号包裹：
- 文件名：`config/app.php`
- 函数名：`htmlEncode()`
- 变量名：`$username`
- 配置项：`APP_DEBUG`

### 2.4 链接规范

#### 内部链接

使用相对路径：

```markdown
<!-- 链接到同目录文件 -->
[配置说明](./03-配置文件说明.md)

<!-- 链接到上级目录 -->
[返回首页](../README.md)

<!-- 链接到子目录 -->
[部署指南](./03-运维指南/01-部署指南.md)

<!-- 链接到特定行 -->
[Check.php:47](../app/middleware/Check.php:47)
```

#### 外部链接

```markdown
[ThinkPHP 文档](https://www.kancloud.cn/manual/thinkphp6_0/content)
```

#### 引用式链接

适用于多次引用同一链接：

```markdown
详见 [API 文档][api-docs] 和 [配置说明][config-docs]。

[api-docs]: ./02-API接口文档-SDK.md
[config-docs]: ./03-配置文件说明.md
```

### 2.5 表格规范

#### 基本格式

```markdown
| 列1 | 列2 | 列3 |
|-----|-----|-----|
| 内容1 | 内容2 | 内容3 |
| 内容4 | 内容5 | 内容6 |
```

#### 对齐方式

```markdown
| 左对齐 | 居中 | 右对齐 |
|:-------|:----:|-------:|
| 内容 | 内容 | 内容 |
```

#### 参数表格模板

```markdown
| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| username | string | 是 | 用户名，6-18位 |
| password | string | 是 | 密码，6-18位 |
| remember | boolean | 否 | 是否记住登录 |
```

## 3. 文件命名规范

### 3.1 目录命名规则

| 规则 | 示例 |
|-----|------|
| 使用两位数字前缀排序 | `01-教程_Tutorials/` `02-操作指南_How-To-Guides/` |
| 使用中文名称（可选英文后缀） | `03-参考_Reference/` `04-解释_Explanation/` |
| 使用连字符分隔 | `01-快速入门/` |
| 全部小写字母（英文部分） | `archive/` `meta/` |

### 3.2 文件命名规则

| 规则 | 正确示例 | 错误示例 |
|-----|---------|---------|
| 使用数字前缀 | `01-部署指南.md` | `部署指南.md` |
| 中文命名 | `02-API接口文档-公共.md` | `02-API_Document.md` |
| 连字符分隔 | `02-API接口文档-SDK.md` | `02-API接口文档_SDK.md` |
| 统一扩展名 | `README.md` | `README.txt` |

**特殊文件命名：**

| 文件类型 | 命名规则 | 示例 |
|---------|---------|------|
| 索引文件 | `README.md` | `docs/02-技术文档/README.md` |
| 变更日志 | `CHANGELOG.md` | `docs/meta/CHANGELOG.md` |
| 贡献指南 | `CONTRIBUTING.md` | `docs/meta/CONTRIBUTING.md` |
| 归档文件 | 原名_归档.md（如项目启用归档策略） | `02-API接口文档_归档.md` |
| 报告文件 | 类型_日期.md | `文档审计报告_2026-02-21.md` |

### 3.3 版本号规则

采用 **语义化版本**（Semantic Versioning）：`MAJOR.MINOR.PATCH`

| 版本类型 | 说明 | 示例 |
|---------|------|------|
| MAJOR | 重大变更、不兼容更新 | 1.0.0 → 2.0.0 |
| MINOR | 新增功能、向后兼容 | 1.0.0 → 1.1.0 |
| PATCH | Bug 修复、小改进 | 1.0.0 → 1.0.1 |

## 4. 版本记录规范

### 4.1 CHANGELOG 格式

[`CHANGELOG.md`](CHANGELOG.md) 遵循 [Keep a Changelog](https://keepachangelog.com/) 格式：

```markdown
## [版本号] - YYYY-MM-DD

### 新增（Added）
- 新功能描述

### 变更（Changed）
- 变更描述

### 修复（Fixed）
- 修复描述

### 移除（Removed）
- 移除描述

### 安全（Security）
- 安全修复描述

### 文档（Docs）
- 文档更新描述

### 修改文件
- 文件路径列表

---
```

### 4.2 版本号递增规则

| 变更类型 | 版本递增 | 示例 |
|---------|---------|------|
| 新增功能模块 | MINOR | 1.2.0 → 1.3.0 |
| 新增 API 接口 | MINOR | 1.2.0 → 1.3.0 |
| Bug 修复 | PATCH | 1.2.0 → 1.2.1 |
| 安全漏洞修复 | PATCH | 1.2.0 → 1.2.1 |
| 文档更新 | PATCH | 1.2.0 → 1.2.1 |
| 不兼容的 API 变更 | MAJOR | 1.2.0 → 2.0.0 |

## 5. 文档审查清单

### 5.1 内容完整性检查

- [ ] **标题清晰**：文档标题准确反映内容
- [ ] **目录完整**：包含所有主要章节的目录
- [ ] **引言说明**：开头有简要说明文档目的
- [ ] **覆盖完整**：覆盖主题的所有必要方面
- [ ] **示例充足**：包含足够的代码示例和使用说明
- [ ] **版本信息**：注明适用的版本范围

### 5.2 格式规范性检查

- [ ] **标题层级**：层级正确，不超过 5 级
- [ ] **代码块**：指定正确的语言标识
- [ ] **表格格式**：对齐正确，表头清晰
- [ ] **列表格式**：有序/无序列表使用正确
- [ ] **空行规范**：标题前后、段落之间有空行
- [ ] **文件编码**：UTF-8 编码
- [ ] **换行符**：使用 LF 换行符

### 5.3 链接有效性检查

- [ ] **内部链接**：相对路径正确，文件存在
- [ ] **外部链接**：URL 可访问
- [ ] **锚点链接**：锚点名称正确
- [ ] **代码链接**：行号引用正确
- [ ] **无死链**：所有链接均可访问

### 5.4 提交前检查清单

```markdown
## 文档提交检查清单

### 内容
- [ ] 内容准确，与代码实现一致
- [ ] 无错别字和语法错误
- [ ] 技术术语使用正确

### 格式
- [ ] 符合 Markdown 格式规范
- [ ] 代码块语法高亮正确
- [ ] 表格格式正确

### 链接
- [ ] 所有链接已验证有效
- [ ] 相对路径正确

### 版本
- [ ] 已更新 CHANGELOG.md
- [ ] 已更新文档索引（如需要）
```
