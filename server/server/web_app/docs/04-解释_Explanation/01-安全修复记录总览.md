## 3. 认证与会话链路（Admin/Agent）

### 3.1 `Check` 中间件当前行为

- 仅对 `admin`、`agent` 应用执行登录态校验；
- 优先验证 `player_admin_*` 新 Session；
- 新 Session 不通过时再兼容旧 `username_*` + `auth_token_*`；
- 旧 `password_*` 仅用于迁移，不再作为长期认证依据；
- token 通过 HMAC 生成并用 `hash_equals` 比较。

关键文件：

- [`../../app/middleware/Check.php`](../../app/middleware/Check.php)
- [`../../app/middleware.php`](../../app/middleware.php)

### 3.2 后台鉴权密钥外置

- `generateToken()` 依赖 `security.admin_auth.secret_key`；
- 密钥为空时直接抛异常并记录错误日志；
- 密钥长度不足会触发强度告警（不阻断，但会留痕）。

关键文件：

- [`../../config/security.php`](../../config/security.php)
- [`../../app/middleware/Check.php`](../../app/middleware/Check.php)
- [`../../.env.example`](../../.env.example)

### 3.3 运行日志侧证据（2026-03-22）

在 `runtime/log/20260322.log` 可见稳定出现：

- `Check.php::verifyPlayerAdminAuth START`
- `Check.php::verifyPlayerAdminAuth SUCCESS`
- `JMX配置来源: config/security.php`
- `JMX配置状态: 已启用认证,Token=已配置`

说明后台认证链路与 JMX 配置读取链路处于正常工作状态。

## 4. 玩家侧安全链路（Player）

### 4.1 中间件挂载状态

玩家应用已在应用层统一挂载四类中间件：

- `TraceId`（P3 新增：UUID v4 全链路追踪）
- `PlayerSecurity`
- `PlayerAuth`
- `CsrfToken`

关键文件：[`../../app/player/middleware.php`](../../app/player/middleware.php)

### 4.2 Token 与会话

- Token 格式：`{sha256}.{timestamp}.{version}`（P3 新增版本号，支持主动吊销）；
- 时效：24 小时；
- 摘要基于 `id|username|timestamp` + `OP_SECRET_SALT`；
- 版本号存储于 Redis `player_token_version:{userId}`，改密/封号时递增版本号使旧 Token 立即失效；
- `OP_SECRET_SALT` 缺失时：
  - 生成 token 抛异常拒绝；
  - 校验 token 直接失败并记录错误日志。

关键文件：[`../../app/player/common.php`](../../app/player/common.php)

### 4.3 `PlayerAuth` 失效阻断

- Session 缺关键字段时拦截；
- 验签失败会清理玩家 Session；
- 异步请求返回 401 JSON，普通请求重定向登录；
- 玩家信息缓存 TTL 当前为 600 秒。

关键文件：[`../../app/player/middleware/PlayerAuth.php`](../../app/player/middleware/PlayerAuth.php)

### 4.4 `PlayerSecurity` 当前策略

当前重点是“限流与告警”，不是“硬封禁”：

- 登录操作限速（5 分钟最多 5 次）；
- 请求窗口限速（1 分钟 60 次）；
- 超阈值后记录可疑计数；
- Redis 异常时降级到文件缓存；
- 玩家端 IP 封禁拦截已按需求关闭（仅留计数和日志）。

关键文件：[`../../app/player/middleware/PlayerSecurity.php`](../../app/player/middleware/PlayerSecurity.php)

### 4.5 CSRF 双键兼容

- 支持 `csrf_token` 与历史 `__csrf_token__`；
- 校验成功后普通表单单次消费并刷新 token；
- 异步请求保留 token 以兼容前端不刷 token 的场景。

关键文件：[`../../app/player/middleware/CsrfToken.php`](../../app/player/middleware/CsrfToken.php)

## 5. 请求防护与扫描流量处理

### 5.1 `Security` 中间件能力与现状

`Security` 代码能力包含：

- SQL 注入关键字/长度检查；
- XSS 标签/属性检查；
- IP 黑白名单检查；
- 命中后 403 阻断。

关键文件：[`../../app/middleware/Security.php`](../../app/middleware/Security.php)

当前挂载状态说明：

- `config/middleware.php` 已声明 `security` 别名和优先级；
- `app/middleware.php` 全局链包含 4 个中间件：`CheckRequestCache`、`SessionInit`、`Check`、`PermissionGuard`；
- `Security` 未在全局链中挂载，是否生效取决于路由/分组是否显式绑定。

关键文件：

- [`../../config/middleware.php`](../../config/middleware.php)
- [`../../app/middleware.php`](../../app/middleware.php)

### 5.2 扫描请求治理

关键文件：

### 6.3 下单并发防护（`Pay::getpay`）

## 7. 已知限制与历史兼容项

1. `Security` 中间件未默认全局启用。  
当前仅配置了别名/优先级，若路由未显式绑定则不会执行其 SQL/XSS 检查。

2. 支付防重放对 `nonce` 存在“上游可选”依赖。  
当上游未传 `nonce` 时会降级为日志告警 + 其他校验，不是完全强约束防重放。

3. 玩家端 IP 黑名单为“弱执行”模式。  
当前策略是记录可疑计数与告警，不在 `PlayerSecurity` 里直接封禁请求。

4. 转区 GM 全量迁移能力未完全落地。  
`Gm` 中相关迁移方法为显式 `error` 返回，当前生产可用路径是绑定级转区流程。

5. `.env.example` 中仍保留历史占位项。  
如 `MASTER_VERIFY_PASSWORD`、`OP_SECRET_SALT` 等，需要部署时按安全要求显式替换。
