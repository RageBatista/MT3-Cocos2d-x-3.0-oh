# jmxc 泄露与盗刷风控方案（Leak & Abuse Mitigation Plan）

## 1. 背景与目标
- jmxc 工具可直接访问 MT3 游戏服的关键 JMX MBean（关服、GM、充值等），一旦泄露将被用于盗刷或破坏线上服务。
- 目标：通过网络隔离、身份校验、命令级风控与快速响应机制，构建“纵深防御 + 快速处置”体系，确保工具泄露时攻击者仍无法造成大规模损失。

## 2. 威胁模型
| 场景 | 威胁主体 | 说明 |
| --- | --- | --- |
| Jar/源码泄露 | 内部人员、被攻陷的 CI/CD、外包等 | 攻击者反编译工具，分析调用入口。 |
| 凭据泄露 | 钓鱼、弱口令、脚本硬编码 | 拿到账号密码即可在暴露的 JMX 端口执行命令。 |
| 网络暴露 | 管理端口未做 ACL，或 VPN 账号被盗 | 攻击者可直接连通 RMI/JMX。 |
| 高危命令滥用 | 工具默认单人执行 | 关服、GM 指令无审批。 |

## 3. 分层防护设计
### 3.1 接入与网络隔离
1. JMX 端口仅开放在管理专网/VPN；默认禁止跨 IDC、跨公网访问。
2. 在硬件防火墙/SD-WAN 配置源 IP 白名单，按运维岗位动态维护。
3. 部署端口扫描/异常流量监控，一旦发现 JMX 连接尝试立即告警。

### 3.2 身份与凭据控制
1. 引入一次性 Token（OTP）或短期凭据，与静态账号组合使用，超时即失效。
2. jmxc 客户端接入 Windows Credential Manager / Linux Gnome Keyring，避免凭据明文落盘。
3. 对客户端绑定机器证书或序列号（Hardware Binding），服务器端在 `LogInfo` 中校验。
4. 所有高危操作必须通过堡垒机或零信任代理；真实凭据仅存放在堡垒机中。

### 3.3 命令级风控
1. 服务端对 `gm`、`bindMacToLahu` 等命令设置额度、频率与每日上限，超阈需二次审批。
2. 引入命令注册表（Command Registry），为每个命令配置风险级别，客户端根据级别触发多因子确认。
3. 输出结构化审计日志（时间、目标节点、参数摘要、流水号），实时推送到 SIEM。
4. 对关服、停服、发奖等命令实施“双人确认”：运维 A 发起，运维 B 审批后才执行。

### 3.4 行为与数据校验
1. GM/奖励类指令需附加服务器端签名或 challenge-response，防止命令被篡改。
2. 对同一账号短时间多次执行高危命令时自动锁定，并触发人工复核。
3. 引入“金库账户”，自带强约束（时间窗、科目限制），独立于普通运维账号。

### 3.5 客户端加固
1. 对 jmxc Jar 做代码混淆与完整性校验（SHA-256 + 签名）；启动时校验签名。
2. 将命令配置和凭据读取逻辑封装在本地安全模块，禁止直接通过反编译获取明文。
3. 提供安全参数（如 `--secure-mode`），强制启用 TLS/JMXMP 或 SSH 隧道。

## 4. 事件响应流程
1. **发现**：通过 SIEM 告警（异常 IP、频繁 gm、失败率异常）或外部线索。
2. **遏制**：立即停用相关账号 / 凭据，封禁可疑 IP，关闭受影响节点的 JMX 端口。
3. **根因分析**：
   - 调取 jmxc 审计日志 + 服务器审计；
   - 查找泄露源（CI/CD、Git、终端等）。
4. **恢复**：
   - 对受影响的游戏资产执行回滚或补偿；
   - 重建凭据与证书，更新白名单。
5. **复盘**：
   - 更新威胁模型与防护策略；
   - 推送强制升级指令，确保所有客户端使用最新加固版本。

## 5. 实施路线图
| 阶段 | 时间（相对） | 重点任务 | 产出 |
| --- | --- | --- | --- |
| P0：快速加固 (T+1 周) | 网络 ACL、堡垒机代理、凭据轮换 | 白名单、防火墙策略、堡垒机流程文档 |
| P1：命令风控 (T+3 周) | Command Registry、双人确认、审计日志 | 新版 jmxc + 服务器审计适配 |
| P2：客户端加固 (T+5 周) | 混淆、签名校验、安全存储 | 加固版 Jar、部署指南 |
| P3：智能监控 (T+7 周) | SIEM 规则、异常行为检测 | 告警看板、响应 Runbook |

## 6. 验收指标
- 95% 的高危操作在 1 分钟内可追溯到责任人和操作参数。
- 内部红队模拟泄露后，多层防护使其无法在 10 分钟内执行成功 GM/充值。
- 凭据轮换流程可在 15 分钟内完成全量吊销与重新分发。
- SIEM 告警到响应团队介入的平均时间 < 5 分钟。

以上方案可与现有“项目说明”文档配套，作为安全团队或运维团队的执行依据。
